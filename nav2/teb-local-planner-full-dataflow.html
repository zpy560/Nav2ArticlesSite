局部路径为什么会“变形”？拆解 TEB 如何把空间、时间和避障压进一张优化图 ​

本文基于当前项目中的 teb_local_planner ROS 2/Nav2 移植源码，梳理插件装载、生命周期、全局路径裁剪、障碍提取、时空轨迹优化、可行性复核、速度输出、恢复状态与可视化数据流。

一、先给结论：TEB 输出的不是“另一条全局路径” ​

TEB 的全称是 Timed Elastic Band，直译是“带时间信息的弹性带”。它接收全局路径作为参考，把机器人未来一小段运动表示成一串二维位姿和相邻位姿之间的时间间隔，再同时优化路径形状与运动时间。

在 Nav2 中，它是 nav2_core::Controller 插件，不是独立导航节点。直接输出是当前控制周期的 geometry_msgs::msg::TwistStamped；局部轨迹、候选拓扑和障碍物只是优化中间结果与可视化数据。

它要同时回答四件事：

  • 往哪里走：跟随全局路径和 via points。
  • 怎样绕开障碍：把局部 Costmap 的致命栅格转成障碍点。
  • 怎样符合底盘：约束速度、加速度、非完整运动学和最小转弯半径。
  • 这一周期发什么速度：从优化轨迹前若干个位姿和时间差计算 vx、vy、omega。

二、谁调用它：ControllerServer 才是 ROS 接口外壳 ​

插件 XML 导出 C++ 类型 teb_local_planner::TebLocalPlannerROS，基类为 nav2_core::Controller。ControllerServer 负责 FollowPath Action、控制频率、机器人位姿、速度、目标检查器和最终速度发布，TEB 只实现控制器插件约定。

五个直接入口构成完整调用面：

  • configure()：接收生命周期父节点、插件 ID、TF Buffer 和局部 Costmap。
  • setPlan()：缓存新的全局 Path，但不立即清空已有 TEB，以便下一周期热启动。
  • computeVelocityCommands()：每个控制周期完成全部局部规划和速度求解。
  • setSpeedLimit()：接收 Costmap 速度限制信息。
  • activate()、deactivate()、cleanup()：跟随 ControllerServer 生命周期管理可视化发布器。

上层传给 computeVelocityCommands() 的输入包括机器人位姿、当前速度和 GoalChecker；返回的 TwistStamped 由 ControllerServer 继续经过进度检查、速度阈值和发布链路。

三、生命周期与内部资源 ​

configure() 内部先调用只允许执行一次的 initialize()，完成核心资源初始化。

3.1 声明并加载参数 ​

声明并加载 TEB 参数。

3.2 准备障碍容器 ​

为障碍容器预留空间。

3.3 选择规划器 ​

根据 enable_homotopy_class_planning 选择单轨迹 TebOptimalPlanner，或多拓扑 HomotopyClassPlanner。

3.4 获取地图与机器人模型 ​

获得局部 Costmap 和机器人 footprint。

3.5 创建轨迹可行性检查器 ​

创建基于 DWB ObstacleFootprintCritic 的轨迹可行性检查器。

3.6 注册运行期接口 ​

注册动态参数回调和 via_points 订阅。

3.7 初始化恢复状态 ​

初始化振荡检测窗口和恢复计时器。

initialize() 返回后，configure() 再创建可视化对象，并配置五个生命周期发布器。

激活时五个发布器进入 Active；停用时全部 Deactivate；清理时调用可视化对象的 on_cleanup()。

当前实现的 cleanup() 没有把 initialized_ 复位，也没有显式释放规划器、订阅、动态参数句柄和可视化对象。因此“清理后再次配置”并不是一条完整重建路径，这是该移植版本需要补齐的生命周期边界。

四、全部输入输出：有直接接口，也有间接 ROS 数据 ​

4.1 直接输入 ​

  • setPlan() 输入 nav_msgs::msg::Path，保存为 global_plan_。
  • computeVelocityCommands() 输入 PoseStamped、Twist 和 GoalChecker*。
  • setSpeedLimit() 输入绝对速度限制或百分比限制。
  • 共享局部 Costmap 提供致命障碍栅格、地图范围、分辨率、footprint 和坐标系。
  • TF Buffer 负责全局路径坐标系与局部规划坐标系之间的变换。
  • 参数决定轨迹采样、机器人约束、障碍距离、优化权重、同伦类别和恢复行为。

4.2 直接输出 ​

  • TwistStamped：当前周期的底盘速度命令。
  • 异常：变换失败、空局部路径、优化失败、发散、不可行或速度无效时抛出运行时错误，由 ControllerServer 处理。

4.3 ROS 订阅与可视化输出 ​

插件自己还订阅相对名称 via_points，消息类型为 nav_msgs::msg::Path。可视化对象发布相对名称 global_plan、local_plan、teb_poses、teb_markers 和 teb_feedback；最终解析后的完整名称取决于 ControllerServer 所在命名空间。

4.4 当前障碍输入边界 ​

当前代码中的 costmap converter 和自定义障碍回调整段被注释，实际障碍输入只来自 Costmap 致命栅格；配置文件中即使保留 converter 参数，也不会形成动态多边形障碍数据流。

五、一个控制周期的完整数据流 ​

computeVelocityCommands() 是整个包的总入口。一周期按下面顺序执行。

5.1 初始化速度输出 ​

生成以 base frame 为坐标系、初值为零的 TwistStamped。

5.2 更新目标容差 ​

从 GoalChecker 读取容差，并更新 TEB 的平面目标容差。

5.3 保存机器人状态 ​

保存当前机器人位姿和速度。

5.4 裁剪全局路径 ​

从缓存全局路径中裁掉机器人身后的旧点。

5.5 变换局部路径 ​

用 TF 将局部窗口内的全局路径变换到局部 Costmap 全局坐标系。

5.6 准备 Via Points ​

从局部路径自动抽取 via points，或使用外部 via_points。

5.7 更新恢复模式 ​

根据连续不可行次数和振荡检测进入恢复模式。

5.8 更新局部目标姿态 ​

用局部终点估计目标方向，并把局部路径首点替换为机器人真实位姿。

5.9 构造障碍对象 ​

扫描局部 Costmap，将致命障碍栅格转成点障碍。

5.10 优化 TEB ​

锁住参数，初始化或热启动 TEB，构图并迭代优化。

5.11 检查轨迹可行性 ​

检查优化发散和 footprint 碰撞可行性。

5.12 提取并限制速度 ​

从轨迹前若干点提取速度，执行限幅；车式底盘可把角速度换成转角。

5.13 发布结果 ​

更新恢复状态，发布调试可视化，返回速度命令。

六、全局路径怎样变成局部参考路径 ​

setPlan() 会逐个复制全局 Path 的 pose，并统一使用 Path header。它刻意不清空已有局部规划器，因为全局规划器可能频繁刷新路径；TEB 希望下一控制周期复用旧轨迹做热启动。

进入控制周期后，pruneGlobalPlan() 先把机器人位姿变换到路径坐标系，并删除机器人身后一段路径。随后 transformGlobalPlan() 执行以下步骤。

6.1 获取坐标变换 ​

获取路径坐标系到局部规划坐标系的 TF。

6.2 查找局部最近点 ​

在路径上寻找机器人附近的局部最近点。

6.3 按 Costmap 范围裁剪 ​

只保留局部 Costmap 半径约 85％范围内的点。

6.4 限制累计前视距离 ​

同时受 max_global_plan_lookahead_dist 累计长度限制。

6.5 补入全局终点 ​

如果机器人已经非常接近全局终点、裁剪结果为空，则显式注入全局终点。

这里有一个确定的当前代码缺陷：函数在检查 global_plan.empty() 之前就访问 global_plan[0]。如果上层传入空路径，理论上的错误分支还没执行就已经发生越界访问。

七、弹性带里到底存了什么 ​

7.1 优化变量 ​

TimedElasticBand 的状态不是普通 Path，而是交替排列的两类优化变量：

  • PoseSE2：每个采样点的 x、y、theta。
  • TimeDiff：相邻两个位姿之间的时间间隔 Δt。

新任务第一次进入时，用裁剪后的全局路径初始化这些变量。如果新终点与旧终点距离和角度变化不大，就调用 updateAndPruneTEB()，删除已经走过的前段并更新起终点；变化过大才清空重建。

外循环先用 dt_ref、dt_hysteresis、最少和最多采样数自动调整轨迹离散密度，再构建 g2o 优化图。内循环使用 Levenberg-Marquardt 求解。每轮外循环还会用 weight_adapt_factor 逐步增强部分约束权重。

7.2 优化约束 ​

优化图包含的主要边包括：

  • 障碍物与膨胀距离约束。
  • 动态障碍约束，前提是实际障碍对象带速度；当前 Costmap 点障碍链路并不提供这一信息。
  • via point 贴合约束。
  • 最大速度、最大加速度约束。
  • 总时间最优与最短路径约束。
  • 差速或车式运动学约束。
  • 偏好转向方向约束。
  • 速度与障碍距离比约束。

因此，TEB 不是先算路径再独立做速度规划，而是在同一张图中共同调整空间位姿和时间间隔。

八、单条 TEB 与多同伦类别 TEB ​

关闭 enable_homotopy_class_planning 时，只维护一个 TebOptimalPlanner。打开后，HomotopyClassPlanner 会探索绕障碍物左右两侧等不同拓扑类别，为每类初始化一条 TEB，并可并行优化。

多类别流程如下。

8.1 更新已有候选 ​

更新并分析上周期保留下来的候选轨迹。

8.2 探索新等价类 ​

根据图搜索结果探索新的等价类。

8.3 加入全局参考候选 ​

将全局参考路径作为一个优先候选。

8.4 绑定 Via Points ​

为各候选绑定 via points。

8.5 优化全部候选 ​

串行或多线程优化所有候选。

8.6 选择最佳 TEB ​

根据总成本、障碍成本缩放、时间成本、上一最佳轨迹滞回和初始路径偏好选择最佳 TEB。

8.7 限制拓扑切换 ​

在 switching_blocking_period 内限制频繁切换拓扑类别。

可行性检查如果发现最佳候选碰撞，会移除该候选并尝试下一个；如果不可行候选恰好是上周期最佳轨迹，则直接失败，避免轨迹之间来回振荡。

九、从优化轨迹到速度命令 ​

getVelocityCommand() 至少要求两个轨迹位姿。它从第一个位姿向前累计若干 TimeDiff，在配置的前视位姿范围内选定目标采样点，然后按底盘类型计算速度。

9.1 非全向底盘速度 ​

沿机器人朝向投影得到 vx，vy=0。

9.2 全向底盘速度 ​

将位移旋转到机器人坐标系，得到 vx 和 vy。

9.3 角速度 ​

归一化后的方向差除以累计时间。

优化使用软约束，因此结果还要经过 saturateVelocity() 硬限幅。use_proportional_saturation=true 时，三个速度分量按同一最小比例缩放，尽量保持曲率；否则分别裁剪。

车式底盘打开 cmd_angle_instead_rotvel 后，使用轴距和转弯半径把角速度转换成转向角。如果结果不是有限数，整条轨迹会被清空，本周期失败。

十、恢复机制不是 Behavior Server 的恢复行为 ​

本包内部有两种局部恢复状态，它们发生在控制器内部，不是 Nav2 Behavior Server 的 spin、backup 或 wait。

10.1 缩短视野 ​

检测到不可行轨迹后，至少在 shrink_horizon_min_duration 内把局部目标向前收缩约 50％；连续失败超过 9 次时进一步缩短。

10.2 振荡恢复 ​

FailureDetector 根据一段时间内的线速度与角速度符号变化判断振荡，并把当前旋转方向设置为优化偏好，保持到恢复窗口过期。

成功得到可行速度后，连续不可行计数归零；规划失败、发散、碰撞或速度无效都会增加计数、记录时间、保存零速度并清空规划器。

十一、当前移植源码需要特别留意的边界 ​

除空路径越界和生命周期清理不完整外，还有几处直接影响实车行为：

  • 动态 footprint 更新分支把新 footprint 反向覆盖为旧值，实际没有更新 footprint_spec_，也没有把新结果正确保存。
  • setSpeedLimit() 只有前向 max_vel_x 被正确修改；后退、横向和角速度分支多处写入 base_max_* 自身，而不是活动上限 max_vel_*。百分比限制还会累计改写基准值。
  • customViaPointsCB() 有互斥锁，但控制周期读取 via_points_ 时没有使用同一把锁，存在并发访问边界。
  • Costmap 转障碍只采集 LETHAL_OBSTACLE，不会把膨胀层、未知区域或语义多边形直接变成障碍对象。
  • 配置里存在 costmap converter 参数，但对应实现被注释；不能据此判断动态障碍预测已经接通。
  • 轨迹优化时锁住参数配置，但动态参数回调、速度限制更新与其他容器的并发边界仍不完整。

这些内容不等于 TEB 算法本身有问题，而是当前 ROS 2 移植版本的工程完成度边界。上线前应针对空路径、动态 footprint、速度限制、生命周期重配和并发 via points 建立回归测试。

十二、调参应该按什么顺序 ​

12.1 保证几何模型正确 ​

先检查 footprint、min_obstacle_dist、局部 Costmap 分辨率和膨胀距离。

12.2 保证底盘约束正确 ​

再检查 max_vel_*、acc_lim_*、是否全向、最小转弯半径和轴距。

12.3 调整时间离散 ​

调整 dt_ref、dt_hysteresis、min_samples、max_samples 和控制前视位姿数。

12.4 调整优化权重 ​

随后调整速度、加速度、障碍、via point、最优时间和运动学权重。

12.5 启用多同伦类别和多线程 ​

最后再打开多同伦类别和多线程。它能提升复杂绕障场景的选择能力，但也会显著增加计算量和调参维度。

调参时至少同时记录控制周期耗时、最小障碍距离、轨迹总时间、速度连续性、不可行次数和拓扑切换次数，只看 RViz 轨迹“顺不顺眼”远远不够。

十三、结语 ​

TEB 的价值，是把“路径长什么样”和“多快走过去”放到一个统一优化问题里。全局路径提供方向，局部 Costmap 提供障碍，机器人模型提供可执行边界，时间变量把几何路径变成速度命令。

真正读懂它，不是记住几十个权重，而是抓住一条主线：全局 Path 先被裁剪和变换，随后变成 Pose 与 TimeDiff 组成的弹性带，再通过约束图优化、footprint 可行性复核和速度限幅，最终在每个控制周期输出一条可执行命令。
