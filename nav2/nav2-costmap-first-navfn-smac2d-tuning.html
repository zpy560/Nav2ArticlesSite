路径贴墙，真是规划器的锅吗？先调好 Costmap，再对决 NavFn A* 与 Smac2D ​

同一台机器人换了规划器，路径仍然贴墙、穿窄门失败，通常不是两套算法同时失效，而是它们读到了同一张有问题的 Costmap。

公平比较只有一条原则：先校准机器人几何、地图、障碍和膨胀梯度，冻结公共输入，再只切换 planner_id。否则所谓优劣只是多个变量叠加后的错觉。

一、先分清比较对象 ​

1.1 GridBasedAstar 是插件 ID ​

当前配置中的 GridBasedAstar 与 GridBased 都指向 nav2_navfn_planner/NavfnPlanner，不是另一套官方 A*。use_astar: true 才让 NavFn 使用 A* 传播势场。

Smac2D 指向 nav2_smac_planner/SmacPlanner2D，使用带 Costmap 代价的八连通二维 A*。因此本文实际比较的是 NavFn A* 与 Smac2D。

1.2 两者共享同一张试卷 ​

Planner Server 把起点、终点和 Global Costmap 交给选中的插件。StaticLayer、ObstacleLayer、footprint 与 InflationLayer 先决定哪些栅格禁止通行、哪些区域代价较高，规划器再决定如何搜索。

二、Costmap 基线必须先合格 ​

2.1 机器人几何决定能否通过 ​

优先核对 footprint 或 robot radius、footprint_padding、地图分辨率与真实车宽。模型偏小会让路径看似可行却导致实车擦碰；模型偏大则会封死本来能过的窄通道。

2.2 地图与障碍层必须可信 ​

  • StaticLayer 的地图原点、分辨率、占用阈值与实际环境一致。
  • ObstacleLayer 能标记障碍，也能通过 raytracing 清除旧障碍。
  • 激光 frame、时间戳和 TF 正常，不在地图上制造重影。
  • Master Costmap 中未知区、致命障碍与自由空间符合预期。

只有这四类输入稳定后，规划器对比才有意义。

三、Inflation 两个参数最容易调反 ​

3.1 inflation_radius 决定覆盖范围 ​

它决定障碍物周围多远仍保留膨胀代价。半径过小，宽通道中央几乎没有代价差，规划器缺少远离墙面的动力；半径过大，窄通道可能被高代价区压缩甚至封闭。

3.2 cost_scaling_factor 决定衰减速度 ​

代价大致按指数衰减。cost_scaling_factor 越大，离开障碍后下降越快；越小，高代价影响延伸越远。它不是“越大越安全”。

调试时先保证窄通道仍连通，再观察宽通道是否形成连续、对称的代价坡度，最后冻结这两个参数。

四、两套 A* 怎样使用代价 ​

4.1 NavFn A* 传播势场 ​

NavFn 先把 Costmap 值映射到内部代价，再从目标向外传播 potential。启发项改变节点展开优先级，最终通过梯度回溯形成连续 Path。它成熟、简单，但净空偏好主要受固定代价映射和 Inflation 地形影响。

4.2 Smac2D 显式计算代价感知移动成本 ​

Smac2D 使用 g+h 搜索。每次八邻域移动不仅计算直走或斜走距离，还将归一化 Costmap 代价乘入 cost_travel_multiplier。因此在仍可通行的栅格中，它能更直接地权衡路程与净空。

搜索结果还会进入内置 Smoother，所以最终 Path 的圆滑程度不能全部归因于 A* 搜索本身。

五、公平 A/B 只改变 planner_id ​

5.1 固定公共条件 ​

地图、起终点、footprint、Costmap 分辨率、障碍源、Inflation、TF、定位和最大规划时间必须一致。不要一边换规划器，一边调整膨胀或平滑参数。

5.2 使用统一场景与指标 ​

测试应覆盖宽通道、窄门、贴墙起终点、拐角和长距离绕障。每组重复运行，记录：

  • 成功率与规划耗时。
  • 最小障碍净空与路径长度。
  • 搜索扩展数或超时情况。
  • 路径曲率、抖动和执行成功率。

截图漂亮不是可靠指标；同场景多次结果才有统计意义。

六、Costmap 固定后再调插件参数 ​

6.1 NavFn 先作为稳定基线 ​

保持 allow_unknown、tolerance、use_astar 和 use_final_approach_orientation 明确，先确认它能稳定生成可执行路径。若它与 Smac2D 都失败，应回到公共输入排查。

6.2 Smac2D 再调代价权衡 ​

cost_travel_multiplier 越大，搜索越不愿进入高代价区，但可能产生更长绕行。downsample_costmap 会改变搜索分辨率和速度，也会牺牲窄结构细节。搜索与 Smoother 参数应分开调，避免把路径形状变化归错层。

七、按现象定位责任层 ​

7.1 两套规划器都贴墙 ​

优先查 footprint、Inflation 梯度和静态地图边界，而不是继续放大某个插件权重。

7.2 两套规划器都过不了窄门 ​

检查 footprint、padding、分辨率和 inflation radius 是否共同封闭通道。

7.3 只有 Smac2D 绕行明显 ​

检查 cost_travel_multiplier 是否过大，以及内置平滑是否改变了路径外形。

7.4 全局路径正常但实车擦碰 ​

问题已经进入 Local Costmap、Controller、速度、定位延迟或底盘跟踪层，不应继续调全局规划器。

八、选型没有绝对冠军 ​

8.1 NavFn A* 适合成熟简洁的基线 ​

它依赖少、行为稳定、调参面较小，适合快速建立可靠基线与资源受限平台。

8.2 Smac2D 适合更明确的净空权衡 ​

它让 Costmap 代价直接进入移动成本，并提供降采样与内置平滑，更适合需要通道居中、愿意用计算量换路径质量的场景。

九、最终结论 ​

9.1 正确顺序比“选谁”更重要 ​

Costmap 决定哪里能走、哪里更贵；规划器决定怎样在这片代价地形中搜索。先把地图、几何、障碍和 Inflation 调可信，再做单变量 A/B，NavFn A* 与 Smac2D 的差异才可复现、可解释。
