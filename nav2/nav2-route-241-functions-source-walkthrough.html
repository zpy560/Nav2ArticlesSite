一张拓扑图如何变成可执行路线？逐函数拆解 Nav2 Route Server 的 241 个入口 ​

自由空间规划回答的是“在这一张代价地图上怎么绕开障碍”，Route Server 回答的却是“在园区道路、仓库通道、楼层走廊和交通规则组成的拓扑网中，应该依次走哪些节点和边”。它不只计算一条 Route，还会把稀疏图边变成可跟踪的 Path，在机器人行进时识别已通过的节点，执行限速、碰撞检查、服务触发、耗时记录，并在边失效时重新规划。

本文以本地 navigation2 的 nav2_route 为唯一源码基线。生产范围包括 34 个头文件、28 个 .cpp、plugins.xml 和构建清单。按显式构造、析构、普通方法、模板方法、纯虚接口和内联函数统计，头文件有 240 个入口，再加 main()，合计 241 个。测试函数和脚本工具不计入正文函数总数。

一、先看清 Route Server 的系统位置 ​

1.1 它规划的是图，不是任意栅格 ​

输入端有两类导航请求。调用者可以直接给 start_id 和 goal_id，也可以给起终点 Pose，让系统自行寻找附近可达的图节点。图本身来自 GeoJSON 文件，节点保存坐标、元数据和节点操作，边保存方向、代价、元数据和边操作。

输出也分两层。nav2_msgs::msg::Route 保留拓扑语义，告诉上层经过哪些节点和边；nav_msgs::msg::Path 把图边稠密化为连续 Pose，便于后续自由空间规划器、控制器或可视化组件使用。

1.2 包外调用采用消息接口隔离 ​

当前仓库没有其他生产包直接包含 nav2_route 的 C++ 头文件。nav2_behavior_tree 提供 ComputeRoute 和 ComputeAndTrackRoute 两个 BT Action 节点，分别连接 compute_route 与 compute_and_track_route。nav2_bt_navigator 只是注册对应 BT 插件库。

这意味着包外调用不需要理解 Graph、NodePtr 或 ReroutingState。它只需要遵守 Action、Service 和 Topic 契约。包内则通过普通 C++ 对象和 Pluginlib 串起图加载、意图提取、搜索、Path 转换与跟踪。

1.3 两个 Action 的语义不同 ​

  • compute_route 接收 ID 或 Pose，返回 Route、Path 和 planning_time，规划完成即结束。
  • compute_and_track_route 先规划，再持续发布当前边、前后节点、Route、Path、已触发操作和是否重规划，直到终点、取消、抢占或异常。
  • route_server/set_route_graph 在运行时接收新图文件路径。
  • route_server/<DynamicEdgesScorer 名称>/adjust_edges 动态关闭、开放或修改边代价。
  • route_server/<ReroutingService 名称>/reroute 请求重新规划。
  • /route_graph 发布拓扑 Marker，/plan 发布稠密 Path。

二、RouteServer 如何接住生命周期与 ROS 回调 ​

2.1 main() 与 RouteServer 构造、析构 ​

  • main(int argc, char ** argv) 输入进程参数，初始化 ROS 2，创建 RouteServer，交给执行器 spin，退出时 shutdown；输出是进程生命周期，不产生业务消息。
  • RouteServer::RouteServer(const rclcpp::NodeOptions & options) 输入组件化选项，以节点名 route_server 构造 nav2_util::LifecycleNode；输出是尚未配置的生命周期节点。
  • RouteServer::~RouteServer() 是默认析构，输入为空，输出是对象资源按成员规则释放；真正的 ROS 接口收口由 Lifecycle on_cleanup() 主动完成。

2.2 五个 Lifecycle 回调 ​

  • RouteServer::on_configure(state) 是配置回调。输入是 Lifecycle 状态，内部创建 TF Buffer／Listener、route_graph Publisher、两个 SimpleActionServer、换图 Service、CostmapSubscriber，再构造 GraphLoader、GoalIntentExtractor、RoutePlanner、RouteTracker 和 PathConverter。输出为 SUCCESS 或 FAILURE，此时 Action 尚未接单。
  • RouteServer::on_activate(state) 是激活回调。输入状态只用于接口契约；它激活两个 Action Server 和图 Publisher，立即发布当前 Graph Marker并创建 Bond，输出 SUCCESS。
  • RouteServer::on_deactivate(state) 停用 Action 和 Publisher，销毁 Bond，输出 SUCCESS，保留已配置图与内部对象。
  • RouteServer::on_cleanup(state) 释放 Action、Service、加载器、规划器、跟踪器、Path 转换器、意图提取器、Publisher、TF，并清空 Graph，输出 SUCCESS。
  • RouteServer::on_shutdown(state) 只记录关闭日志并返回 SUCCESS，没有额外业务输出。

2.3 Action 执行入口 ​

  • RouteServer::computeRoute() 是 compute_route 的执行回调，不直接解析 Goal；它把 compute_route_server_ 交给模板 processRouteRequest<ComputeRoute>()，最终输出 Route、Path 和规划耗时。
  • RouteServer::computeAndTrackRoute() 是 compute_and_track_route 的执行回调，进入同一模板主链；不同点是得到 Route 和 Path 后阻塞在 RouteTracker，持续输出 Feedback。
  • RouteServer::processRouteRequest<ActionT>() 输入对应 SimpleActionServer。它取当前 Goal，初始化 ReroutingState，循环检查取消与抢占，调用 findRoute()、PathConverter::densify()，再按 Action 类型选择立即成功或跟踪。跟踪器返回 INTERRUPTED 时循环重规划，返回 COMPLETED 时成功，返回 EXITED 时结束。异常被映射为 Action 终止。
  • RouteServer::isRequestValid<ActionT>() 输入 Action Server 引用，检查 Server 活性、取消请求和 Graph 是否为空；输出 bool。取消时终止全部 Goal，空图时终止当前 Goal。

2.4 路由查找与结果回填 ​

  • RouteServer::findRoute<GoalT>() 输入 Goal 与可选重规划状态。它先让 GoalIntentExtractor 得到图数组中的起终点索引；有重规划起点时覆盖起点；起终点相同则生成零边 Route，否则构造 RouteRequest 调 RoutePlanner；最后执行首尾裁剪，输出 Route。
  • RouteServer::findPlanningDuration(start_time) 输入规划开始时间，输出当前时刻差值；若超过 max_planning_time，额外打印期望频率和实际频率警告。
  • RouteServer::populateActionResult(ComputeRoute::Result, route, path, duration) 输入 Route、Path 和耗时，把内部 Route 转为消息并填入规划结果，无独立返回值。
  • RouteServer::populateActionResult(ComputeAndTrackRoute::Result, route, path, duration) 是跟踪 Action 的重载。Route 和 Path 在该结果类型中不用，只写 execution_duration。

2.5 Service 与异常收口 ​

  • RouteServer::setRouteGraph(header, request, response) 是换图 Service 回调。输入 graph_filepath，清空现有 Graph 和 ID Map，调用 GraphLoader，成功后重建 KD-Tree、发布新 Marker并令 response.success=true；失败返回 false。
  • RouteServer::exceptionWarning<GoalT>(goal, ex) 输入失败 Goal 与异常，输出一条包含起点 Pose／ID、终点 Pose／ID 和异常文本的日志；调用者随后终止当前 Action。

三、图数据类型与通用函数 ​

3.1 Metadata 的三个入口 ​

  • Metadata::Metadata() 无输入，构造空的 unordered_map<string, any>，供节点、边和 Operation 保存任意业务字段。
  • Metadata::getValue<T>(key, default_val) 输入键和默认值；键不存在时返回默认值，存在时执行 std::any_cast<T> 并返回。类型不匹配会抛异常，调用者必须让 GeoJSON 类型和插件模板类型一致。
  • Metadata::setValue<T>(key, value) 输入键和值，以 std::any 写回 Map，无返回值；TimeMarker 会用它把实测边耗时写回 Graph。

3.2 搜索和重规划状态入口 ​

  • NodeComparator::operator()(a, b) 输入两个 cost＋NodePtr，输出 a.cost > b.cost，使标准优先队列表现为最小代价队列。
  • DirectionalEdge::getEdgeLength() 无外部输入，从 start 和 end 坐标计算欧氏长度并返回 float。
  • SearchState::reset() 无输入，把累计代价和本边代价恢复为最大浮点数，把 parent_edge 清空。
  • Node::addEdge(cost, node, edgeid, metadata, operations) 输入目标节点、边 ID、代价、元数据和操作，向当前节点的有向邻边数组追加 DirectionalEdge，无返回值。
  • ReroutingState::reset() 无输入，清空阻塞 ID、当前边、最近点和重规划起点，恢复“首次规划”标志；抢占新 Goal 时调用。

3.3 utils 的六个入口 ​

  • utils::toMsg(x, y) 输入二维坐标，输出只填写位置的 PoseStamped。
  • utils::toMsg(graph, frame, now) 输入完整 Graph、坐标系和时间，输出 MarkerArray；节点是红色球和节点编号，边是绿色线和边编号，已标记删除的节点会被跳过。
  • utils::toMsg(route, frame, now) 输入内部 Route，输出 nav2_msgs::msg::Route，依次填入起始节点、每条边和边终点。
  • utils::normalizedDot(v1x, v1y, v2x, v2y) 输入两个二维向量，输出归一化点积；任一向量接近零时返回零，避免除零。
  • utils::findClosestPoint(pose, start, end) 输入 Pose 和线段端点，输出线段上距离 Pose 最近的点；投影超出线段时钳到端点。
  • utils::distance(coords, pose) 输入坐标和 Pose，输出二维欧氏距离。

四、GeoJSON 怎样进入和离开 Graph ​

4.1 GraphFileLoader 插件接口 ​

  • GraphFileLoader::GraphFileLoader() 与 GraphFileLoader::~GraphFileLoader() 无业务输入输出，只建立可被 Pluginlib 管理的多态对象生命周期。
  • GraphFileLoader::configure(node) 是纯虚配置入口，输入 Lifecycle Node，要求实现类保存日志或读取参数，无统一返回值。
  • GraphFileLoader::loadGraphFromFile(graph, id_map, filepath) 是纯虚加载入口，输入目标 Graph、ID Map 和文件路径，输出成功标志并通过引用填充数据。

4.2 GraphLoader 的五个入口 ​

  • GraphLoader::GraphLoader(node, tf, frame) 输入节点、TF Buffer 和 Route Frame，读取 graph_filepath 与 graph_file_loader，通过 Pluginlib 创建并配置解析器；构造失败会抛 Pluginlib 异常。
  • GraphLoader::~GraphLoader() 默认析构，释放插件 SharedPtr 和 ClassLoader 成员。
  • GraphLoader::loadGraphFromFile(graph, id_map, filepath) 输入显式路径，调用插件加载，再调用 transformGraph() 把节点统一到 Route Frame，输出 bool。
  • GraphLoader::loadGraphFromParameter(graph, id_map) 输入目标容器，路径来自参数；空路径被视为“暂不加载”并返回成功，便于稍后通过 Service 设置图。
  • GraphLoader::transformGraph(graph) 输入可变 Graph，以源 Frame 为键缓存 TF，逐节点变换 XY 并把 frame_id 改成 Route Frame，输出是否全部成功。

4.3 GeoJsonGraphFileLoader 的十三个入口 ​

  • GeoJsonGraphFileLoader::GeoJsonGraphFileLoader() 与 GeoJsonGraphFileLoader::~GeoJsonGraphFileLoader() 是默认生命周期入口，没有 ROS 数据输出。
  • GeoJsonGraphFileLoader::configure(node) 输入 Lifecycle Node，只保存 Logger。
  • GeoJsonGraphFileLoader::loadGraphFromFile(graph, id_map, filepath) 检查文件、解析 JSON、拆分节点与边、创建 Graph、填充 ID Map 和有向边，输出 bool；JSON 语法错误返回失败，边引用不存在节点时抛 NoValidGraph。
  • GeoJsonGraphFileLoader::doesFileExist(filepath) 输入路径，输出文件存在性。
  • GeoJsonGraphFileLoader::getGraphElements(features, nodes, edges) 输入 Feature 数组，把 Point 分到节点，把 LineString／MultiLineString 分到边，输出经两个引用返回。
  • GeoJsonGraphFileLoader::addNodesToGraph(graph, id_map, nodes) 输入节点 JSON，写入节点 ID、数组索引、坐标、Operations 和 Metadata。
  • GeoJsonGraphFileLoader::addEdgesToGraph(graph, id_map, edges) 输入边 JSON，校验 startid／endid，解析代价、Operations 和 Metadata，再调用 Node::addEdge()。
  • GeoJsonGraphFileLoader::convertCoordinatesFromJson(node) 输入 Point Feature，输出 Coordinates；缺省 Frame 保留 map。
  • GeoJsonGraphFileLoader::convertMetaDataFromJson(properties, key) 输入 JSON 属性和键，递归输出 Metadata；支持字符串、整数、无符号整数、浮点、布尔、嵌套对象和基本类型数组。
  • GeoJsonGraphFileLoader::convertOperationFromJson(json_operation) 输入单个 Operation JSON，输出类型、触发时机和元数据组成的 Operation。
  • GeoJsonGraphFileLoader::convertOperationsFromJson(properties) 输入节点或边属性，输出 Operations 数组；没有该字段时返回空数组。
  • GeoJsonGraphFileLoader::convertEdgeCostFromJson(properties) 输入边属性，输出静态 cost 与 overridable；缺省分别为零和可覆盖。

4.4 GraphFileSaver 与 GraphSaver ​

  • GraphFileSaver::GraphFileSaver()、GraphFileSaver::~GraphFileSaver() 管理保存插件基类生命周期。
  • GraphFileSaver::configure(node) 是纯虚配置入口，输入 Lifecycle Node。
  • GraphFileSaver::saveGraphToFile(graph, filepath) 是纯虚保存入口，输入 Graph 和路径，输出成功标志。
  • GraphSaver::GraphSaver(node, tf, frame) 输入节点、TF 和 Route Frame，读取保存路径与插件类型，通过 Pluginlib 创建 GeoJSON 或自定义保存器。
  • GraphSaver::~GraphSaver() 默认释放插件资源。
  • GraphSaver::saveGraphToFile(graph, filepath) 输入 Graph 和可选路径；空参数会尝试使用 graph_filepath，然后调用插件写文件并调用 transformGraph()，输出 bool。
  • GraphSaver::transformGraph(graph) 与加载侧类似，按节点源 Frame 缓存 TF并原地转换到 Route Frame，输出是否成功。

4.5 GeoJsonGraphFileSaver 的八个入口 ​

  • GeoJsonGraphFileSaver::GeoJsonGraphFileSaver() 与 GeoJsonGraphFileSaver::~GeoJsonGraphFileSaver() 是默认生命周期入口。
  • GeoJsonGraphFileSaver::configure(node) 输入 Lifecycle Node，保存 Logger。
  • GeoJsonGraphFileSaver::saveGraphToFile(graph, filepath) 输入 Graph 和路径，构造 FeatureCollection、CRS、节点和边，再以四空格缩进写出，输出成功标志。
  • GeoJsonGraphFileSaver::loadNodesFromGraph(graph, features) 输入 Graph，把有效节点转换成 Point Feature并追加到输出数组。
  • GeoJsonGraphFileSaver::loadEdgesFromGraph(graph, features) 输入 Graph，把每条有向边转换成带 ID、起终点、代价、元数据和 Operations 的 Feature。
  • GeoJsonGraphFileSaver::convertMetaDataToJson(metadata, json) 输入 std::any Metadata，按已支持类型递归转换，未知类型写入运行时类型名。
  • GeoJsonGraphFileSaver::convertOperationsToJson(operations, json) 输入 Operations，把类型、触发时机和元数据写成 JSON。

五、Pose 如何落到可达图节点 ​

5.1 GraphAdaptor 与 NodeSpatialTree ​

  • GraphAdaptor::GraphAdaptor(graph) 输入 Graph 常量引用，不复制节点，只建立 Nanoflann 适配视图。
  • GraphAdaptor::kdtree_get_point_count() 无输入，输出图节点数量。
  • GraphAdaptor::kdtree_get_pt(idx, dim) 输入节点索引和维度，输出 X 或 Y。
  • GraphAdaptor::kdtree_get_bbox(bbox) 输入 Nanoflann 的包围盒对象，固定返回 false，表示让库自行计算边界。
  • NodeSpatialTree::NodeSpatialTree() 默认构造 KD-Tree 管理器。
  • NodeSpatialTree::~NodeSpatialTree() 删除 KD-Tree 和 Adaptor 裸指针并置空。
  • NodeSpatialTree::computeTree(graph) 输入 Graph，销毁旧索引，创建新 Adaptor 和二维 KD-Tree，构建索引并保存 Graph 地址。
  • NodeSpatialTree::findNearestGraphNodesToPose(pose, node_ids) 输入 Pose 和输出数组，执行 K 近邻查询，输出成功标志并把图数组索引追加到 node_ids。
  • NodeSpatialTree::setNumOfNearestNodes(count) 输入候选数，更新后续 KNN 查询数量。

5.2 BreadthFirstSearch 与 LoSCollisionChecker ​

  • BreadthFirstSearch::BreadthFirstSearch(costmap) 输入 Costmap SharedPtr，建立可达性搜索器。
  • BreadthFirstSearch::search(reference, candidates, max_iterations) 把参考点和候选点转成栅格索引，从参考点做八邻域 BFS，输出是否找到候选；结果索引由 getClosestNodeIdx() 读取。
  • BreadthFirstSearch::getNeighbors(current_id) 输入 Costmap 线性索引，过滤越界、跨行回绕和致命代价，输出八邻域可扩展索引。
  • BreadthFirstSearch::inCollision(id) 输入栅格索引，输出代价是否大于等于致命阈值且不是 Unknown。
  • BreadthFirstSearch::getClosestNodeIdx() 无输入，输出上次命中的候选数组位置。
  • BreadthFirstSearch::~BreadthFirstSearch() 默认释放 SharedPtr。
  • LoSCollisionChecker::LoSCollisionChecker(costmap) 输入 Costmap，建立线段碰撞检查器。
  • LoSCollisionChecker::~LoSCollisionChecker() 默认析构。
  • LoSCollisionChecker::worldToMap(start, end) 输入世界坐标线段，输出两个端点能否映射到 Costmap，并保存栅格端点。
  • LoSCollisionChecker::isInCollision() 沿保存的栅格线逐格检查，输出是否遇到致命且非 Unknown 代价。

5.3 GoalIntentExtractor 的九个入口 ​

  • GoalIntentExtractor::GoalIntentExtractor() 与 GoalIntentExtractor::~GoalIntentExtractor() 是默认生命周期入口。
  • GoalIntentExtractor::configure(node, graph, id_map, tf, costmap, route_frame, global_frame, base_frame) 输入全部上下文，构建 KD-Tree并读取裁剪、KNN 和 BFS 参数，无返回值。
  • GoalIntentExtractor::setGraph(graph, id_map) 输入新 Graph 与映射，更新内部指针并重建 KD-Tree；由换图 Service 成功分支调用。
  • GoalIntentExtractor::transformPose(pose, target_frame) 输入 Pose 和目标 Frame；相同 Frame 直接返回，否则调用包外 nav2_util::transformPoseInTargetFrame()，失败抛 RouteTFError。
  • GoalIntentExtractor::findStartandGoal<GoalT>(goal) 输入两种 Action Goal。ID 模式直接查 Map；Pose 模式可从 TF 取当前机器人位姿，转换 Frame，做 KNN，必要时借 Costmap LoS 和 BFS选择可达候选，输出两个图数组索引。
  • GoalIntentExtractor::pruneStartandGoal<GoalT>(route, goal, rerouting_state) 输入原 Route、Goal 与重规划状态。它用归一化投影、线段最近点和距离阈值裁掉已在机器人身后的首边，按配置裁掉越过目标 Pose 的末边，并维护部分边信息，输出新 Route。
  • GoalIntentExtractor::overrideStart(start_pose) 输入重规划时的当前 Pose，覆盖内部起点。
  • GoalIntentExtractor::getStart() 无输入，输出当前用于评分和裁剪的起点 Pose。

六、Dijkstra 如何调度边代价插件 ​

6.1 EdgeCostFunction 六个接口 ​

  • EdgeCostFunction::EdgeCostFunction() 与 EdgeCostFunction::~EdgeCostFunction() 建立和释放多态评分插件。
  • EdgeCostFunction::configure(node, tf, costmap, name) 是纯虚配置入口，输入节点、TF、CostmapSubscriber 和参数域名称。
  • EdgeCostFunction::score(edge, request, edge_type, cost) 是纯虚评分回调，输入边、请求、边类型和输出代价引用；返回 false 表示边不可通行。
  • EdgeCostFunction::getName() 是纯虚名称接口，输出插件参数域。
  • EdgeCostFunction::prepare() 默认无操作；EdgeScorer 在每次边评分前调用，CostmapScorer 用它抓取同一轮 Costmap 快照。

6.2 EdgeScorer 四个入口 ​

  • EdgeScorer::EdgeScorer(node, tf, costmap) 输入运行上下文，读取 edge_cost_functions，默认加载 DistanceScorer 与 DynamicEdgesScorer，逐个配置并保存插件。
  • EdgeScorer::~EdgeScorer() 默认释放插件和 ClassLoader。
  • EdgeScorer::score(edge, request, edge_type, total_score) 先对全部插件调用 prepare()，再逐个调用 score() 并累加代价；任一插件返回 false 就拒绝该边，输出成功标志和总分。
  • EdgeScorer::numPlugins() 无输入，输出已加载插件数量。

6.3 RoutePlanner 十四个入口 ​

  • RoutePlanner::RoutePlanner() 与 RoutePlanner::~RoutePlanner() 建立和释放搜索器。
  • RoutePlanner::configure(node, tf, costmap) 输入节点、TF 与 Costmap，读取 max_iterations；非正值转为整数上限，并构造 EdgeScorer。
  • RoutePlanner::findRoute(graph, start_index, goal_index, blocked_ids, request) 输入 Graph、数组索引、阻塞 ID 和请求上下文，执行最短路搜索，再从目标的 parent_edge 反向回溯并反转，输出 Route；无父边时抛无有效路线异常。
  • RoutePlanner::resetSearchStates(graph) 输入 Graph，调用每个节点的 SearchState::reset()。
  • RoutePlanner::findShortestGraphTraversal(graph, start, goal, blocked_ids, request) 输入搜索边界和限制，执行 Dijkstra；命中目标时清空队列返回，达到迭代上限时抛超时异常。
  • RoutePlanner::getTraversalCost(edge, score, blocked_ids, request) 输入候选边。边或终点被阻塞时返回 false；不可覆盖或没有插件时使用正的静态边代价；否则交给 EdgeScorer。
  • RoutePlanner::getNextNode() 从优先队列取出并返回最低代价节点。
  • RoutePlanner::addNode(cost, node) 输入累计代价与节点，把它压入队列。
  • RoutePlanner::getEdges(node) 输入节点，输出其有向邻边引用。
  • RoutePlanner::clearQueue() 无输入，通过交换空队列彻底清空。
  • RoutePlanner::isGoal(node) 输入节点，输出其 ID 是否等于当前目标 ID。
  • RoutePlanner::isStart(node) 输入节点，输出其 ID 是否等于当前起点 ID。
  • RoutePlanner::classifyEdge(edge) 输入边，输出 START、END 或 NONE，供航向评分器只处理边界边。

七、八类边代价插件逐个拆开 ​

7.1 DistanceScorer 五个入口 ​

  • DistanceScorer::DistanceScorer() 与 DistanceScorer::~DistanceScorer() 是默认插件生命周期。
  • DistanceScorer::configure(node, tf, costmap, name) 使用节点和名称读取 speed_tag、weight，另外两个上下文参数不使用。
  • DistanceScorer::score(edge, request, type, cost) 输入边，以欧氏长度除以元数据中的相对速度值，再乘权重，输出代价并返回可通行。
  • DistanceScorer::getName() 输出参数域名称。

7.2 TimeScorer 五个入口 ​

  • TimeScorer::TimeScorer() 与 TimeScorer::~TimeScorer() 是默认生命周期。
  • TimeScorer::configure(node, tf, costmap, name) 读取实测耗时键、绝对速度键、权重和缺省最大速度。
  • TimeScorer::score(edge, request, type, cost) 优先读取 TimeMarker 回写的实测耗时；没有正耗时时按边长度除以绝对速度或最大速度估算，输出加权时间代价。
  • TimeScorer::getName() 输出插件名称。

7.3 DynamicEdgesScorer 六个入口 ​

  • DynamicEdgesScorer::DynamicEdgesScorer() 与 DynamicEdgesScorer::~DynamicEdgesScorer() 管理动态边插件生命周期。
  • DynamicEdgesScorer::configure(node, tf, costmap, name) 创建 adjust_edges Service并清空关闭边集合和动态惩罚 Map。
  • DynamicEdgesScorer::closedEdgesCb(header, request, response) 是 Service 回调，输入关闭边、开放边和代价调整，更新内部状态并返回 success=true。
  • DynamicEdgesScorer::score(edge, request, type, cost) 输入候选边；关闭边返回 false，有动态代价则写入 cost，否则贡献零并返回 true。
  • DynamicEdgesScorer::getName() 输出参数域名称。

7.4 PenaltyScorer 五个入口 ​

  • PenaltyScorer::PenaltyScorer() 与 PenaltyScorer::~PenaltyScorer() 是默认生命周期。
  • PenaltyScorer::configure(node, tf, costmap, name) 读取惩罚元数据键和权重。
  • PenaltyScorer::score(edge, request, type, cost) 输入边，读取静态惩罚，输出加权代价。
  • PenaltyScorer::getName() 输出插件名称。

7.5 CostmapScorer 六个入口 ​

  • CostmapScorer::CostmapScorer() 与 CostmapScorer::~CostmapScorer() 是默认生命周期。
  • CostmapScorer::configure(node, tf, costmap, name) 读取最大或平均模式、碰撞／越界策略、代价阈值、采样分辨率、Costmap Topic 和权重；Topic 不同时创建独立 Subscriber。
  • CostmapScorer::prepare() 从 Subscriber 获取最新 Costmap，失败则清空快照。
  • CostmapScorer::score(edge, request, type, cost) 把边端点映射到栅格，沿线采样；按配置拒绝越界或高代价边，输出最大代价或平均代价的归一化加权值。
  • CostmapScorer::getName() 输出插件名称。

7.6 SemanticScorer 七个入口 ​

  • SemanticScorer::SemanticScorer() 与 SemanticScorer::~SemanticScorer() 是默认生命周期。
  • SemanticScorer::configure(node, tf, costmap, name) 输入节点和名称，读取语义类别与每类代价、语义键和权重。
  • SemanticScorer::metadataKeyScorer(metadata, score) 输入 Metadata 与累计分，按键名匹配语义类别并累加。
  • SemanticScorer::metadataValueScorer(metadata, score) 输入 Metadata 与累计分，从指定键取类别字符串并累加。
  • SemanticScorer::score(edge, request, type, cost) 同时检查边终点 Metadata 和边 Metadata，按键模式或值模式求和，输出加权语义代价。
  • SemanticScorer::getName() 输出插件名称。

7.7 StartPoseOrientationScorer 五个入口 ​

  • StartPoseOrientationScorer::StartPoseOrientationScorer() 与 StartPoseOrientationScorer::~StartPoseOrientationScorer() 是默认生命周期。
  • StartPoseOrientationScorer::configure(node, tf, costmap, name) 读取航向容差、权重和是否启用硬阈值，并保存 TF Buffer。
  • StartPoseOrientationScorer::score(edge, request, edge_type, cost) 要求 Pose 请求；只在起始边比较边方向与起点朝向，超阈值可拒绝边，否则输出角差加权代价。
  • StartPoseOrientationScorer::getName() 输出插件名称。

7.8 GoalOrientationScorer 五个入口 ​

  • GoalOrientationScorer::GoalOrientationScorer() 与 GoalOrientationScorer::~GoalOrientationScorer() 是默认生命周期。
  • GoalOrientationScorer::configure(node, tf, costmap, name) 读取终点航向容差、权重和硬阈值开关。
  • GoalOrientationScorer::score(edge, request, edge_type, cost) 要求 Pose 请求；只在末边比较边方向与目标朝向，输出角差代价或拒绝超阈值边。
  • GoalOrientationScorer::getName() 输出插件名称。

八、稀疏 Route 怎样变成稠密 Path ​

8.1 CornerArc 七个入口 ​

  • CornerArc::CornerArc(start, corner, end, radius) 输入连续三点和最小半径，计算两边长度、夹角、切点、角平分线和圆心；能在两条边内放下圆弧时把内部状态标为有效。
  • CornerArc::~CornerArc() 默认析构。
  • CornerArc::interpolateArc(max_angle_resolution, poses) 输入角分辨率和输出 Pose 数组，按有符号圆心角插值并追加弧上点。
  • CornerArc::isCornerValid() 无输入，输出构造阶段是否得到有效圆弧。
  • CornerArc::getCornerStart() 输出入边切点。
  • CornerArc::getCornerEnd() 输出出边切点。
  • CornerArc::getAngleBetweenEdges(start, corner, end) 输入三点，输出两条边的夹角。

8.2 PathConverter 五个入口 ​

  • PathConverter::PathConverter() 与 PathConverter::~PathConverter() 是默认生命周期。
  • PathConverter::configure(node) 输入 Lifecycle Node，读取 Path 密度、圆弧半径和转角平滑开关，创建并激活 /plan Lifecycle Publisher。
  • PathConverter::densify(route, rerouting_state, frame, now) 输入 Route、部分边状态、Frame 和时间。它先补部分边，再逐边线性插值，可选插入 CornerArc，补齐每个 Pose 的切线朝向，发布并返回 Path。
  • PathConverter::interpolateEdge(x0, y0, x1, y1, poses) 输入线段和输出数组，按 path_density 计算点数并沿单位向量追加 Pose。

九、RouteTracker 如何知道机器人走到哪里 ​

9.1 RouteTracker 八个入口 ​

  • RouteTracker::RouteTracker() 与 RouteTracker::~RouteTracker() 是默认生命周期。
  • RouteTracker::configure(node, tf, costmap, action_server, route_frame, base_frame) 输入运行上下文，读取普通节点和边界节点到达半径、更新频率、阻塞 ID 聚合策略，并构造 OperationsManager。
  • RouteTracker::getRobotPose() 无业务输入，通过包外 nav2_util::getCurrentPose() 查询 route_frame→base_frame，输出当前 Pose；失败抛 RouteTFError。
  • RouteTracker::nodeAchieved(pose, state, route) 输入当前 Pose、跟踪状态和 Route。边界节点按半径判断；中间节点还用前后边角平分线判断机器人是否越过节点空间分界，输出 bool 并更新 within_radius。
  • RouteTracker::isStartOrEndNode(state, route) 输入状态与 Route，输出当前目标是否是起始边界或末节点。
  • RouteTracker::publishFeedback(rerouted, next_id, last_id, edge_id, operations) 输入进度字段，连同缓存的 Route 和 Path构造 Action Feedback并发布。
  • RouteTracker::trackRoute(route, path, rerouting_state) 输入 Route、Path 和共享重规划状态，以 tracker_update_rate 循环取 TF、判断节点、执行 Operations、发布 Feedback。终点输出 COMPLETED，取消／抢占／重规划输出 INTERRUPTED，ROS 退出输出 EXITED。

十、运行操作怎样被统一调度 ​

10.1 RouteOperation 六个接口 ​

  • RouteOperation::RouteOperation() 与 RouteOperation::~RouteOperation() 管理多态 Operation 生命周期。
  • RouteOperation::configure(node, costmap, name) 是纯虚配置入口，输入节点、CostmapSubscriber 和插件实例名。
  • RouteOperation::getName() 是纯虚名称接口。
  • RouteOperation::processType() 默认输出 ON_GRAPH；实现类可改成状态变化触发或周期查询触发。
  • RouteOperation::perform(node, entered, exited, route, pose, metadata) 是纯虚运行回调，输入节点／边上下文、完整 Route、当前 Pose 和可选元数据，输出 OperationResult，可请求重规划并附带阻塞 ID。

10.2 OperationsManager 七个入口 ​

  • OperationsManager::OperationsManager(node, costmap) 输入节点和 Costmap，读取 Operation 列表，通过 Pluginlib 创建实例，再按 processType() 分入 Graph、状态变化和周期查询三组。
  • OperationsManager::~OperationsManager() 默认释放插件。
  • OperationsManager::findGraphOperations(node, entered, exited) 输入当前节点、进入边和退出边，输出符合 NODE、ON_ENTER、ON_EXIT 触发条件的 Operation 指针。
  • OperationsManager::findGraphOperationsToProcess<T>(object, trigger, operations) 输入节点或边指针、触发枚举和输出数组，把匹配 Operation 追加进去。
  • OperationsManager::updateResult(name, op_result, result) 输入单插件结果，合并 reroute、阻塞 ID 和已触发插件名称。
  • OperationsManager::processOperationsPluginVector(plugins, result, node, entered, exited, route, pose) 输入同类插件数组，逐个调用 perform() 并聚合结果。
  • OperationsManager::process(status_change, state, route, pose, rerouting_state) 输入当前跟踪状态。状态变化时执行图内指定 Operation 和全部状态变化插件；每个周期都执行查询插件，输出合并后的 OperationsResult。

十一、五类运行操作逐个拆开 ​

11.1 AdjustSpeedLimit 六个入口 ​

  • AdjustSpeedLimit::AdjustSpeedLimit() 与 AdjustSpeedLimit::~AdjustSpeedLimit() 是默认生命周期。
  • AdjustSpeedLimit::configure(node, costmap, name) 输入节点和插件名，读取速度元数据键与发布 Topic并创建 SpeedLimit Publisher。
  • AdjustSpeedLimit::getName() 输出插件名称。
  • AdjustSpeedLimit::processType() 输出 ON_STATUS_CHANGE，因此节点／边状态变化时执行。
  • AdjustSpeedLimit::perform(node, entered, exited, route, pose, metadata) 输入跟踪上下文；有新进入边时读取百分比限速并发布 nav2_msgs::msg::SpeedLimit，输出不请求重规划的空结果。

11.2 CollisionMonitor 十一个入口 ​

  • CollisionMonitor::CollisionMonitor() 与 CollisionMonitor::~CollisionMonitor() 是默认生命周期。
  • CollisionMonitor::configure(node, costmap, name) 输入上下文，读取检查频率、Costmap Topic、碰撞阈值、采样分辨率、前视距离和是否重规划。
  • CollisionMonitor::getName() 输出插件名称。
  • CollisionMonitor::processType() 输出 ON_QUERY，因此每个跟踪周期都有调用机会，函数内部再按频率限流。
  • CollisionMonitor::perform(node, current_edge, exited, route, pose, metadata) 从机器人在线段上的投影点开始，沿当前和后续边检查指定距离；遇到碰撞时请求重规划并阻塞对应边，或在禁用重规划时抛 OperationFailed。
  • CollisionMonitor::backoutValidEndPoint(start, end, dist) 输入线段和目标检查距离，输出缩短后的世界坐标终点。
  • CollisionMonitor::backoutValidEndPoint(start, line) 输入世界起点和部分越界栅格线，输出能否把终点回退到 Costmap 内，并原地修改 line。
  • CollisionMonitor::lineToMap(start, end, line) 输入世界线段，输出是否完整落在 Costmap并写入栅格线。
  • CollisionMonitor::isInCollision(line) 输入栅格线，按分辨率采样并输出是否存在高于阈值且非 Unknown 的代价。
  • CollisionMonitor::getCostmap() 从 Subscriber 取得最新 Costmap，无返回值；失败抛 OperationFailed。

11.3 ReroutingService 七个入口 ​

  • ReroutingService::ReroutingService() 与 ReroutingService::~ReroutingService() 是默认生命周期。
  • ReroutingService::configure(node, costmap, name) 创建 <name>/reroute Trigger Service并清空原子标志。
  • ReroutingService::getName() 输出插件名称。
  • ReroutingService::processType() 输出 ON_QUERY。
  • ReroutingService::serviceCb(header, request, response) 是 Service 回调，设置原子重规划标志并返回成功。
  • ReroutingService::perform(node, entered, exited, route, pose, metadata) 每周期读取并消费该标志，输出一次 reroute=true，不附加阻塞边。

11.4 TimeMarker 六个入口 ​

  • TimeMarker::TimeMarker() 与 TimeMarker::~TimeMarker() 是默认生命周期。
  • TimeMarker::configure(node, costmap, name) 读取耗时元数据键，保存 Clock并清空计时状态。
  • TimeMarker::getName() 输出插件名称。
  • TimeMarker::processType() 输出 ON_STATUS_CHANGE。
  • TimeMarker::perform(node, entered, exited, route, pose, metadata) 输入状态变化上下文，记录进入边时间；确认退出同一边后计算持续时间并写入该边 Metadata，输出空 OperationResult。

11.5 RouteOperationClient<SrvT> 十个入口 ​

  • RouteOperationClient::RouteOperationClient() 与 RouteOperationClient::~RouteOperationClient() 管理模板 Service Operation 生命周期。
  • RouteOperationClient::configureEvent(node, name) 是可覆盖扩展点，输入节点和名称，默认无操作。
  • RouteOperationClient::populateRequest(request, metadata) 是可覆盖扩展点，输入 Service 请求与图元数据，默认无操作。
  • RouteOperationClient::processResponse(response) 是可覆盖扩展点，输入 Service 响应，默认返回空 OperationResult。
  • RouteOperationClient::configure(node, costmap, name) 是最终配置实现，创建互斥 Callback Group 和专用单线程 Executor，读取固定 Service 名并调用 configureEvent()。
  • RouteOperationClient::perform(node, entered, exited, route, pose, metadata) 输入图触发上下文，从 Metadata 或参数选择 Service，填请求、同步等待响应、处理响应并输出 OperationResult；失败统一转换为 OperationFailed。
  • RouteOperationClient::callService(client, request, timeout) 输入 Client、请求和超时，等待 Service，异步发送并用专用 Executor 等待 Future，输出响应。
  • RouteOperationClient::getName() 输出插件实例名。
  • RouteOperationClient::processType() 固定输出 ON_GRAPH。

11.6 TriggerEvent 两个入口 ​

  • TriggerEvent::TriggerEvent() 与 TriggerEvent::~TriggerEvent() 是默认生命周期。该类不新增业务函数，只把 RouteOperationClient<std_srvs::srv::Trigger> 具体化并导出为 Pluginlib 插件，因此请求为空，响应默认转换为空 OperationResult。

十二、完整输入输出与回调闭环 ​

12.1 只计算 Route 的数据流 ​

BT 或其他 Action Client 发送 ComputeRoute Goal。RouteServer 校验图与取消状态，GoalIntentExtractor 将 ID 或 Pose 变成图索引，RoutePlanner 用 Dijkstra 和边评分插件生成 Route，PathConverter 生成 Path，结果回到 Action Client。这个链路不进入 RouteTracker，也不会执行运行 Operation。

12.2 计算并跟踪 Route 的数据流 ​

ComputeAndTrackRoute 复用同一规划链，随后 RouteTracker 持续从 TF 读取机器人 Pose。节点状态改变会触发图 Operation 和状态变化 Operation；周期 Operation会检查碰撞或外部重规划标志。Feedback把 Route、Path、当前边、前后节点和触发记录送回 BT。

12.3 重规划数据流 ​

CollisionMonitor 或 ReroutingService 输出 reroute=true。RouteTracker把阻塞边、当前边、当前位置和重规划起点写入 ReroutingState，返回 INTERRUPTED。RouteServer 的 Action 循环不结束，而是重新提取起点、避开阻塞 ID、裁掉已走过的部分边，再生成新 Path并继续跟踪。

12.4 外部函数只描述契约 ​

本包调用的 TF、Costmap、Action Server、Pluginlib、Lifecycle Publisher 和参数工具都不在 nav2_route 内。它们在本文中的职责边界分别是：提供坐标变换、提供栅格代价快照、管理 Goal 状态、动态创建插件、约束激活状态、读取参数。包内不实现这些基础设施，只消费它们的结果并把失败转换为 Route 异常或 Operation 异常。

十三、当前源码中值得警惕的边界 ​

13.1 KD-Tree 裸指针和返回数量 ​

NodeSpatialTree 的 kdtree_ 与 adaptor_ 没有类内空值初始化，默认构造后首次判空依赖未定义初值。KNN 查询还按请求数量分配数组，却按数组长度而不是 Nanoflann 实际返回数量追加结果；图节点少于 K 值时可能带入未写满索引。

13.2 零长度边会放大 Path 风险 ​

PathConverter::interpolateEdge() 没有先处理 mag==0。此时点数为零，后续距离和单位向量计算发生除零，无符号循环上界还会下溢。图文件应避免重合节点形成零长度边，生产代码更适合在函数入口显式返回单点。

13.3 换图失败会丢失旧图 ​

setRouteGraph() 在验证新图之前清空当前 Graph 和 ID Map，异常还被空 catch 吞掉。新文件无效时 Service 只返回失败，旧图不会自动恢复。更稳妥的实现应先加载到临时 Graph，完成解析、TF 和 KD-Tree校验后再原子替换。

13.4 两个参数链存在直接偏差 ​

AdjustSpeedLimit::configure() 声明 speed_limit_topic，实际却读取 speed_tag 作为 Publisher Topic，所以修改前者不会改变 Topic。DistanceScorer 的速度元数据和 TimeScorer 的最大速度也没有在评分前校验正值，零值会进入除法。

13.5 图保存顺序和 Operation 序列化 ​

GraphSaver::saveGraphToFile() 先调用插件写文件，再执行 transformGraph()。若 Graph 仍含其他 Frame，本次文件保存的不是变换后坐标。GeoJSON 保存器又用 Operation 类型作为 JSON 对象键，同一节点或边上相同类型的多个 Operation会互相覆盖。

13.6 并发和空指针依赖调用约束 ​

DynamicEdgesScorer 的 Service 回调与搜索评分共享关闭边集合和动态代价 Map，没有显式 Mutex。RouteOperationClient 的 perform() 直接解引用 Metadata；正常 ON_GRAPH 调度会传入有效指针，但脱离 OperationsManager 直接调用就不安全。这些行为都依赖当前执行器和调度路径，而不是由函数自身防御。

十四、把 241 个入口收束成一条主线 ​

nav2_route 的核心不是“又一个栅格规划器”，而是一台拓扑路线执行机：GeoJSON 负责表达道路结构和业务语义，GoalIntentExtractor 把导航意图落到图上，RoutePlanner 用可插拔代价寻找最优边序列，PathConverter 把稀疏 Route 变成可消费 Path，RouteTracker 再把真实运动进度、业务 Operation 和动态改道闭成循环。

理解这个包时，最有价值的分界不是文件目录，而是三类数据：静态 Graph描述“哪里能走”，RouteRequest 和边评分描述“这次更想怎么走”，ReroutingState 与 OperationResult描述“走的过程中发生了什么”。抓住这三类数据，241 个入口就不再是一堆函数，而是同一条路线从文件、搜索、执行到重规划的不同关口。
