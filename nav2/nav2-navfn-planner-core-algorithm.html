从机器人脚下掀起一场“势能洪水”：Nav2 NavFn 如何把 Costmap 变成路径？ ​

给 NavFn 一张 Costmap、一个机器人位置和一个目标点，它不会直接在栅格里保存一串父节点，也不会先得到折线路径再调用独立平滑器。

它真正做的是：把整张地图改写成一张导航势场，让势值从机器人所在栅格向外传播；目标附近一旦拥有有限势值，再从目标沿负势梯度走回机器人，最后把这段内部路径逆序，得到机器人到目标的 nav_msgs/Path。

这套实现里最容易看反的是 start 与 goal。ROS 请求的起点被写入 NavFn 的内部 goal，ROS 请求的目标反而被写入内部 start。只有先把这层变量语义理顺，Dijkstra、A*、目标容差和路径回溯才能连成同一条数据流。

本文基于当前本地 navigation2、nav2_navfn_planner 1.1.20 源码，只拆 Costmap 转换、势场传播、平面波更新、A*／Dijkstra、梯度取路和目标整形等核心算法。

一、NavFn 求解的不是一串父节点 ​

1.1 输入最终落成三块核心数据 ​

NavfnPlanner::makePlan() 接收 ROS 世界坐标下的机器人起点 start、请求目标 goal 和目标容差 tolerance。真正进入算法内核的数据是：

  • 一维栅格通行代价数组 costarr。
  • 一维导航势数组 potarr。
  • 两个整数栅格坐标 start[2] 与 goal[2]。

二维栅格 (x, y) 在数组中的索引为：

text
index = y * nx + x

costarr[index] 表示该格能否通过以及穿越有多贵，potarr[index] 表示从零势源走到该格需要积累多少导航势。

1.2 势值是到零势源的累计通行代价 ​

每轮规划开始时，全部 potarr 被重置为 POT_HIGH=1.0e10。这个大数不是普通高代价，而是“势场尚未抵达”或“从当前传播域不可达”的哨兵值。

内部 goal 所在格被设为零势：

text
potarr[goal] = 0

随后波前不断更新四邻域。空旷区域每跨一格至少增加 COST_NEUTRAL=50，膨胀区与未知区增加得更多，障碍格完全不参与传播。因此，势场同时编码了距离和 Costmap 风险。

1.3 输出路径来自势场坡度 ​

当候选终点已经拥有有限势值，calcPath() 从该点出发，持续朝势值下降的方向移动。正常情况下它不只在栅格中心间跳转，而是对四个角点的梯度做双线性插值，每次前进 0.5 个栅格。

所以 NavFn 的路径比“只保存八邻域父节点并原样回溯”更连续，但这仍是势场插值结果，不等于带曲率约束的车辆轨迹，也不等于优化型路径平滑。

1.4 算法主链可以压缩成一行 ​

text
Costmap
→ 内部通行代价
→ 零势源初始化
→ Dijkstra / A* 调度波前
→ 平面波更新 potarr
→ 选择有限势终点
→ 负势梯度取路
→ 逆序与坐标转换
→ nav_msgs/Path

二、Costmap 不是原样进入势场 ​

2.1 普通栅格先被抬高到中性代价 ​

setCostmap() 按下面的线性关系转换 ROS Costmap 的 0～252：

text
navfn_cost = min(50 + 0.8 * costmap_cost, 253)

这意味着 Costmap 自由空间 0 进入 NavFn 后不是零，而是 50。势值因而会随路径长度稳定增长，哪怕整段路径都处于完全自由空间。

例如：

text
Costmap 0    → NavFn 50
Costmap 100  → NavFn 130
Costmap 200  → NavFn 210
Costmap 252  → NavFn 251

膨胀代价越高，势场的坡就越陡。路径沿负势梯度提取时，自然更偏向较低代价走廊。

2.2 致命障碍与内切障碍统一封死 ​

ROS Costmap 值 253 和 254 都被转换为内部 COST_OBS=254。所有入队宏和势值更新都要求：

text
costarr[n] < COST_OBS

因此内部代价 254 是不可传播边界。波前只能绕开它，不能靠“支付更高代价”穿过去。

2.3 未知空间的语义由 allow_unknown 决定 ​

Costmap 的未知值为 255。当 allow_unknown=true 时，它被转换为内部 253；当 allow_unknown=false 时，它被转换为 254。

这个差异只有一个数值，却改变了拓扑：

  • 内部 253 < 254，波前可以穿过未知格，但每格代价极高。
  • 内部 254，未知格与障碍一样，波前不能进入。

所以“允许未知空间”不等于把未知区域当成自由空间，而是把它当成可穿越的高代价区域。

2.4 地图最外圈会被二次封边 ​

setupNavFn() 不信任输入地图的边缘状态。每次传播前，它都会把首行、末行、首列和末列强制写成 COST_OBS。

这既避免了无边界检查的四邻域访问越界，也意味着贴着 Costmap 最外圈的通道会被 NavFn 主动封闭。调试“地图边缘明明是自由空间却无法规划”时，不能只看原始 Costmap。

三、包装层交换了内部 start 与 goal ​

3.1 ROS 起点被写入内部 goal ​

机器人世界坐标先经 worldToMap() 变成 map_start。目标点变成 map_goal。随后源码执行：

cpp
planner_->setStart(map_goal);
planner_->setGoal(map_start);

对应关系是：

text
NavFn start = ROS 请求目标
NavFn goal  = ROS 机器人起点

这不是注释笔误，而是后续势场、容差和路径方向的基础。

3.2 势场从机器人位置向请求目标传播 ​

setupNavFn() 总是把内部 goal 的势设为零，并把它的四个邻格送入当前优先级缓冲区。因为内部 goal 就是 ROS 起点，真实波前方向为：

text
机器人位置 → 请求目标

Dijkstra 的 atStart=true 和 A* 的终止判断都检查内部 start 是否获得有限势。换回 ROS 语义，就是检查请求目标是否已经被机器人起点发出的势场抵达。

3.3 交换让目标容差检查变得直接 ​

请求目标可能恰好落在障碍、膨胀致命区或不可达孤岛中。包装层需要在目标附近寻找一个可达候选点。

由于势场以机器人位置为零势源，任意栅格的 potarr 都直接回答：

text
机器人能否从当前起点到达这个栅格？

因此候选终点只需检查 potential < POT_HIGH，不必为每个候选重新运行一次搜索。

3.4 内部路径方向必须再次翻转 ​

calcPath() 默认从内部 start 开始，也就是从请求目标或容差候选点开始，沿负势梯度走向内部 goal，也就是机器人位置。

得到的 pathx／pathy 顺序为：

text
候选终点 → 机器人起点

getPlanFromPotential() 从 len-1 递减到 0 读取数组，才恢复成 ROS 消费方需要的：

text
机器人起点 → 候选终点

四、波前不是普通队列，而是三组势值桶 ​

4.1 三块固定数组承担优先级调度 ​

NavFn 没有使用 std::priority_queue。它预先分配三块长度均为 PRIORITYBUFSIZE=10000 的整数数组：

  • curP 保存当前阈值下正在处理的栅格。
  • nextP 保存本批更新产生的低势候选。
  • overP 保存超过当前阈值的候选。

pending[] 记录栅格是否已经等待处理，避免同一格在一次调度阶段被重复插入。

4.2 势阈值按固定增量上升 ​

初始阈值为：

text
curT = COST_OBS = 254

阈值增量为：

text
priInc = 2 * COST_NEUTRAL = 100

新势值低于 curT 时，受影响邻格进入 nextP；否则进入 overP。当前与下一缓冲都耗尽后，curT 增加 100，原来的溢出缓冲成为新的当前缓冲。

这是一种粗粒度桶式优先队列：势更低的区域优先推进，势更高的区域被延后，但不用维护逐元素堆结构。

4.3 四邻域传播带着近似对角门槛 ​

中心格势值降低后，源码检查左、右、上、下四个邻格是否值得重新入队。比较中加入：

text
0.707106781 * neighbor_cost

这个 1/√2 系数不是让搜索直接扩展对角邻居，而是作为邻格受当前新势影响的调度门槛。真正的传播和势值读取仍建立在四邻域上。

4.4 固定容量是必须知道的工程边界 ​

三个入队宏都带有：

text
buffer_count < 10000

缓冲区满时，新的候选不会插入，源码也不会扩容或抛出错误。普通尺寸地图和常见波前通常不会触发，但在超大地图、复杂等势前沿或异常高并发候选场景中，这个静默容量上限值得纳入失败排查。

五、一个栅格的势值如何计算 ​

5.1 横纵方向各取一个最低势邻居 ​

对待更新栅格 n，先读取四邻域势值：

text
l = potarr[n - 1]
r = potarr[n + 1]
u = potarr[n - nx]
d = potarr[n + nx]

再分别取横向和纵向的较小值：

text
tc = min(l, r)
ta = min(u, d)

源码通过交换保证 ta <= tc，并定义：

text
hf = costarr[n]
dc = tc - ta

hf 是穿越当前格的代价，dc 是两个有效方向的势差。

5.2 势差大时退化为单邻居更新 ​

当：

text
dc >= hf

较高势邻居提供的信息太弱，新势值只依赖最低势邻居：

text
pot = ta + hf

这与常见最短路更新直觉一致：从已知最便宜的相邻格跨入当前格，并支付当前格代价。

5.3 势差小时使用二邻居平面波近似 ​

当：

text
dc < hf

横纵两个方向都对波面形状有贡献。NavFn 使用一个二次多项式近似：

text
d = dc / hf
v = -0.2301 * d² + 0.5307 * d + 0.7040
pot = ta + hf * v

当两个方向势值接近时，波面可以从二维方向共同抵达当前格，新增势值会小于简单的 ta + hf。这也是 NavFn 能形成更连续势场，而不是纯曼哈顿距离层纹的关键。

5.4 只有更低的新势才会触发传播 ​

新势计算完后仍需满足：

text
pot < potarr[n]

只有势值得到改善，才写回 potarr[n] 并检查周围邻格。势场因此不断做松弛，直到请求目标被抵达、队列耗尽或达到最大循环数。

六、Dijkstra 与 A* 共享同一张势场公式 ​

6.1 Dijkstra 直接按累计势调度 ​

updateCell() 计算出原始 pot 后，直接用它与当前阈值 curT 比较：

text
priority = pot

没有目标方向启发项时，低势波前会从机器人位置较均匀地向外扩散。只要 atStart=true，请求目标一获得有限势，传播就停止。

6.2 A* 只给调度优先级添加启发项 ​

updateCellAstar() 使用完全相同的平面波公式计算原始势值，然后求当前格到内部 start 的欧氏距离：

text
h = hypot(x - start_x, y - start_y) * COST_NEUTRAL
priority = pot + h

内部 start 是 ROS 请求目标，所以这个启发项把波前优先引向请求目标。

6.3 启发项不会污染 potarr ​

A* 源码的写入顺序非常重要：

cpp
potarr[n] = pot;
pot += dist;

potarr 保存的仍是未加启发项的导航势，dist 只临时用于决定邻格进入 nextP 还是 overP。

因此 Dijkstra 和 A* 产生的是同一类“通行累计势”，后续目标容差判断和负势梯度取路不需要知道启发项。二者主要区别是哪些栅格先被计算、通常访问多少栅格，而不是使用两套路径代价公式。

6.4 A* 的初始阈值也向目标倾斜 ​

A* 传播开始前，还会把机器人位置与请求目标的欧氏距离乘以 50，加到初始 curT：

text
curT = 254 + distance(start, goal) * 50

后续每个栅格再以 pot+h 参与桶式调度。它不是标准二叉堆版本的逐节点 A*，而是“平面波势场＋启发式桶调度”的 NavFn 实现。

6.5 当前工程默认选择 A* 配置组 ​

当前 nav2_regulated_modules 与 myagv_test_bringup 都保留两套 NavFn 插件配置：

yaml
GridBased:
  tolerance: 0.5
  use_astar: false
  allow_unknown: true

GridBasedAstar:
  tolerance: 0.5
  use_astar: true
  allow_unknown: true

当前 selected_planner 为 GridBasedAstar。也就是说，实际默认路径使用 A* 调度，但仍走 NavFn 的代价转换、平面波势场和梯度取路。

七、目标不可达时不会立刻失败 ​

7.1 请求目标先接受精确势值检查 ​

势场传播结束后，包装层先读取请求目标对应的：

text
potential = potarr[goal_cell]

只要它小于 POT_HIGH，就直接把请求目标作为路径提取起点。

这里不要求目标势“足够低”。有限势只表示从机器人起点出发的传播已经抵达该格。

7.2 tolerance 遍历的是正方形区域 ​

请求目标势为 POT_HIGH 时，源码以 Costmap 分辨率为步长，遍历：

text
x ∈ [goal.x - tolerance, goal.x + tolerance]
y ∈ [goal.y - tolerance, goal.y + tolerance]

这是轴对齐正方形，不是严格的圆形半径。正方形角点也会被检查。

7.3 候选排序按几何距离而不是势值 ​

每个候选先通过 potential < POT_HIGH 判断可达，再计算它与原请求目标的欧氏距离平方：

text
sdist = (x - goal.x)² + (y - goal.y)²

最终选取距离原目标最近的可达点，而不是选择势值最低、路径总代价最小或离机器人最近的点。

因此 tolerance=0.5 的真实含义是“目标失效时允许在周围网格中找最近可达替代终点”，不是给所有规划结果增加半米误差。

7.4 容差无法修复传播拓扑断裂 ​

容差候选必须已经拥有有限势。如果机器人和整个目标容差区域被障碍完全分隔，所有候选仍是 POT_HIGH，规划结果就是空 Path。

容差擅长处理目标落在障碍边缘、栅格离散误差或末端局部不可达，不会让算法穿墙，也不会跨越未允许的未知区域。

八、负势梯度把候选终点拉回机器人 ​

8.1 calcPath 从候选终点开始 ​

包装层先把内部 start 更新为选中的 best_pose，再调用：

text
calcPath(max(nx, ny) * 4)

路径缓存起点是候选终点。内部终点仍是零势的机器人位置。

每轮循环先保存当前亚栅格坐标，再尝试沿势值降低方向前进。只要当前位置附近的势小于 COST_NEUTRAL=50，算法就直接追加内部 goal，完成内部方向的候选终点到机器人路径。

8.2 gradCell 计算归一化负势梯度 ​

普通可达栅格的梯度近似来自左右、上下势差：

text
dx += pot(left) - pot(center)
dx += pot(center) - pot(right)

dy += pot(up) - pot(center)
dy += pot(center) - pot(down)

随后用 hypot(dx, dy) 归一化。正方向对应数组中的右和下，向量整体指向势值更低的方向。

梯度被缓存在 gradx／grady 中，已经计算过的栅格可以复用。

8.3 四角梯度经过双线性插值 ​

路径点不总在栅格中心。源码用当前整数格和右、下、右下四个角点的梯度，先沿 x 插值，再沿 y 插值：

text
gx = bilinear(gradx, dx, dy)
gy = bilinear(grady, dx, dy)

然后把插值向量缩放到固定步长：

text
step_scale = 0.5 / hypot(gx, gy)
offset += gradient * step_scale

偏移超过一个栅格时，再修正整数索引和局部偏移。这样得到的内部路径可以穿过亚栅格位置，而不是只能连接栅格中心。

8.4 高势边界会切换为八邻域跟随 ​

如果当前格周围九个位置中存在 POT_HIGH，连续梯度可能不稳定。源码会暂停双线性插值，检查周围八邻格，直接移动到势值最低的格子，并把亚栅格偏移清零。

这个分支也用于修复路径在两个位置之间来回振荡的情况。源码通过比较当前路径点与前两个路径点，检测二周期振荡。

8.5 零梯度和超长路径都会失败 ​

以下情况会让 calcPath() 返回 0：

  • 当前索引接近数组边界，继续插值可能越界。
  • 八邻域最低势仍为 POT_HIGH。
  • 插值后的 x、y 梯度同时为零。
  • 在允许循环数内没有抵达零势区域。

包装层即使找到了有限势候选，也会在路径提取失败时输出错误并返回空 Path。

九、离散路径还要经过两次末端整形 ​

9.1 包装层把内部路径逆序并换回世界坐标 ​

pathx／pathy 是候选终点到机器人位置的栅格坐标。包装层从数组尾部向头部遍历，并执行：

text
world_x = origin_x + map_x * resolution
world_y = origin_y + map_y * resolution

输出 Pose 的初始方向统一为单位四元数，对应零偏航。最终 Path 顺序成为机器人位置到候选终点。

9.2 smoothApproachToGoal 只处理最后一个点 ​

smoothApproachToGoal() 的名字容易让人误解。它不是遍历整条路径的平滑器，只比较：

  • Path 尾部前一 Pose 到当前最后 Pose 的距离。
  • Path 尾部前一 Pose 到真实候选终点的距离。

如果真实候选终点更近，就用它替换最后点；否则把真实候选终点追加到 Path 尾部。它修复的是离散取路末端的小折返或缺口，不会重塑整条路径。

9.3 最终方向默认保留候选目标姿态 ​

当前 NavFn 配置没有显式设置 use_final_approach_orientation，使用默认值 false。在这种模式下，末端 Pose 由 best_pose 带入的目标姿态决定。

若启用 use_final_approach_orientation=true，包装层会用末点与前一个有效点的连线方向设置末端朝向，让机器人保持最后接近方向，而不是强制旋转到请求目标姿态。

9.4 起终点重合走独立短路 ​

当起点和目标的 x、y 完全相等，算法不会建立势场。如果该格不是致命障碍，直接输出只含一个 Pose 的 Path。

默认方向使用请求目标方向；启用最终接近方向模式时保留起点方向，避免局部控制器只为方向差驱动机器人原地旋转。

十、四个参数改变的是不同算法边界 ​

10.1 tolerance 只在精确目标不可达时生效 ​

请求目标势有限时，tolerance 不参与路径选择。只有目标势为 POT_HIGH，才扫描目标附近候选。

增大它会扩大可接受终点区域，也可能让机器人停在离请求目标更远的位置。它不是解决整图不可达的搜索半径。

10.2 use_astar 只切换波前调度 ​

use_astar=false 调用 calcNavFnDijkstra(true)，use_astar=true 调用 calcNavFnAstar()。

它不会更换代价映射、平面波公式或路径提取器。比较两种模式时，应重点观察访问栅格量、规划耗时和桶式调度效果，而不是假设 A* 会启用一套全新轨迹平滑算法。

10.3 allow_unknown 改变未知区是否属于可行域 ​

allow_unknown=true 把未知格转换成可传播的 253；关闭后转换成不可传播的 254。

在探索型地图里开启它可以让规划穿过未观测区，但路径仍会受到极高单格代价影响。在已知静态地图或安全边界严格的场景中，关闭它能阻止规划进入未知区域。

10.4 use_final_approach_orientation 只改最后 Pose ​

这个参数不参与势场、候选终点或路径坐标计算，只决定最终 Path 尾部 Pose 的朝向。

若后续 Controller 或 GoalChecker 强依赖目标姿态，使用目标原姿态更直接；若不希望机器人在路径末端额外旋转，最终接近方向更合适。

十一、源码里还有几条容易漏掉的边界 ​

11.1 起点清障会写回原 Costmap ​

包装层认为机器人当前所在格不应是障碍，因此调用：

cpp
costmap_->setCost(mx, my, FREE_SPACE);

这不是只修改 NavFn 的内部副本，而是直接修改原 Costmap。并且该调用发生在获取 Costmap mutex 之前。它有利于处理机器人 footprint 把自身起点标成障碍的情况，但并非纯只读规划。

11.2 坐标转换使用 round 而不是 floor ​

worldToMap() 使用：

text
round((world - origin) / resolution)

mapToWorld() 则直接使用：

text
origin + map * resolution

它没有补 0.5 * resolution 的栅格中心偏移。分析末端半栅格误差或与其他 Costmap 坐标工具差异时，要以这组本地实现为准。

11.3 Dijkstra 的调试 path cost 不可靠 ​

last_path_cost_ 只在 propNavFnAstar() 结束时被赋值。Dijkstra 传播没有更新它，但路径提取后仍统一调用 getLastPathCost() 输出 debug 日志。

因此 Dijkstra 模式下日志中的该 cost 不应被当成可靠路径代价指标。Path 是否成功仍由势场、calcPath() 返回值和输出 Pose 数量决定。

11.4 最大传播与取路次数都有限 ​

势场传播循环上限为：

text
max(nx * ny / 20, nx + ny)

路径提取循环上限为：

text
max(nx, ny) * 4

NavFn 不是无界运行。极端曲折通道、超大地图或异常势场既可能耗尽传播轮数，也可能让路径长度超过取路上限。

11.5 运行路径集中在两份源文件和一份头文件 ​

核心算法可沿以下边界阅读：

  • src/navfn_planner.cpp：ROS 坐标、Costmap、起终点交换、目标容差、逆序输出和末端方向。
  • src/navfn.cpp：内部代价、三缓冲传播、平面波势值、A* 启发项、梯度与路径提取。
  • include/nav2_navfn_planner/navfn.hpp：常量、数组和内部状态定义。

源码中的 create_nav_plan_astar() 位于整段注释中，不属于当前插件运行链。

十二、看懂 NavFn 的关键是把三种方向分开 ​

12.1 势场方向是机器人到目标 ​

包装层把 ROS 起点写成内部 goal，零势由机器人位置向外传播。当前默认 A* 再用到请求目标的欧氏距离，引导波前更快抵达目标。

12.2 内部取路方向是目标到机器人 ​

目标或容差候选点从高势处出发，沿负势梯度下降，最终抵达机器人所在的零势位置。双线性梯度插值让这条内部路径具备亚栅格连续性。

12.3 对外 Path 方向重新变成机器人到目标 ​

包装层把内部路径逆序，转换到世界坐标，修整最后离散点和末端方向，才生成 Controller Server、Smoother Server 与控制器能够消费的 nav_msgs/Path。

NavFn 的精髓不是“用了 Dijkstra 还是 A*”这一行开关，而是同一套连续链路：

text
Costmap 风险
→ 平面波导航势
→ 启发式波前调度
→ 负势梯度
→ 亚栅格路径

一张离散代价地图，正是在这条链路中长成了一条可以交给机器人执行的全局路径。
