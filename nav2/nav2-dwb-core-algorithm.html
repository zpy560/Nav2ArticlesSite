每 50 毫秒淘汰数百种走法：DWB 如何从速度窗口里选出机器人下一步？ ​

DWB 不直接把路径变成一个固定转角。它在每个控制周期里生成一批可达速度，向前推演对应轨迹，再用多组 Critic 衡量碰撞、贴近路径、趋近目标和动作合理性。违法轨迹被淘汰，合法轨迹中总分最低者成为本周期速度。

一、DWB 的核心是离散局部优化 ​

1.1 输入不是只有路径 ​

一次计算需要当前位姿、当前速度、局部化后的 Path、Local Costmap、机器人运动学限制和目标姿态。DWB 求解的是一个有限集合上的最小化问题：

text
v* = argmin J(trajectory(v))

候选速度 v=(vx, vy, vθ) 先生成未来轨迹，再计算代价 J。算法只执行最优轨迹携带的速度，不执行整条模拟轨迹。

1.2 单周期闭环 ​

当前项目的 Controller 频率为 20 Hz，约每 50 ms 重算一次。上个周期的最优解并不会锁死未来；新的 Odom、Costmap 和 Path 会立即改变下一轮候选及评分。

二、动态窗口决定“哪些速度有资格参赛” ​

2.1 可达范围来自两类边界 ​

每个速度轴都先受全局上下限约束，再受当前速度和加减速度约束。单轴可达范围可概括为：

text
v_low  = max(v_min, v0 + decel × Δt)
v_high = min(v_max, v0 + accel × Δt)

decel 在配置中通常为负值。StandardTrajectoryGenerator 用 sim_time 构造范围；LimitedAccelGenerator 用一个控制周期 sim_period 构造更窄的经典 Dynamic Window。

2.2 离散采样形成候选集合 ​

vx、vy、vtheta 分别均匀采样后做笛卡尔积。跨越零点时迭代器会保留零速度，再过滤超出合速度限制和全零的组合。

当前差速配置为 vx_samples=20、vtheta_samples=20、vy=0，候选规模接近数百条，但实际数量会受零点补样和有效速度过滤影响，不能简单认定永远等于某个固定值。

三、一组速度如何长成未来轨迹 ​

3.1 速度先受加速度限制 ​

采样值是目标速度，不代表机器人能瞬间达到。computeNewVelocity() 在每个离散步内让当前速度向目标逼近，且不越过加速度或减速度允许的变化量。

3.2 位姿按机器人坐标系积分 ​

更新后的 vx、vy 会结合当前航向转换到地图坐标，vtheta 更新朝向。离散步数由时间粒度决定，或由预测线位移、角位移与对应粒度共同决定。最终得到包含候选速度、Pose 序列和时间偏移的 Trajectory2D。

sim_time 越长，算法看得越远，但弯道切角和计算量也可能增加；粒度越细，碰撞与几何评分更密，计算成本也更高。

四、MapGrid 把路径关系变成查表 ​

4.1 路径与目标分别成为零代价源 ​

PathDist 将局部路径覆盖的有效栅格设为零，GoalDist 将局部 Costmap 内最后一个路径点设为零。队列从这些源点向外传播曼哈顿距离，形成可复用的栅格距离场。

4.2 轨迹评分变成栅格查询 ​

候选轨迹的 Pose 映射到栅格后，可以按 last、sum 或 product 聚合距离。PathAlign 和 GoalAlign 还会查询机器人前方点，使朝向对齐不只依赖轨迹终点。

这种做法把大量“点到路径”的几何计算转换成预处理加查表，适合在一个周期内批量评估数百条轨迹。

五、Critic 如何表达驾驶偏好 ​

5.1 安全项拥有否决权 ​

BaseObstacle 或 ObstacleFootprint 发现碰撞、越界或不可达区域时，可以抛出违法轨迹异常。RotateToGoal 也会拒绝终点窗口内不减速或仍带平移速度的轨迹。这些不是“扣几分”，而是直接取消候选资格。

5.2 引导项塑造剩余轨迹 ​

  • PathDist、PathAlign：靠近并对齐局部路径。
  • GoalDist、GoalAlign：向局部目标推进并调整朝向。
  • Oscillation：抑制反复换向。
  • PreferForward、Twirling：表达前进和少旋转偏好。

项目当前启用其中七项：RotateToGoal、Oscillation、BaseObstacle、GoalAlign、PathAlign、PathDist、GoalDist。

六、最低总分如何胜出 ​

6.1 加权和不是简单投票 ​

合法轨迹的总分为：

text
J = Σ(raw_score_i × scale_i)

Critic 按配置顺序运行。启用 short_circuit_trajectory_evaluation 后，累计分一旦超过当前最优总分，后续项可以停止计算，因为分数继续累加只会更差。

6.2 Scale 大不等于一定主导 ​

不同 Critic 的原始分数量纲不同，不能只看 scale 大小判断谁最重要。调参时应同时观察原始分、加权分和淘汰原因；否则把 PathDist.scale 翻倍，实际效果可能远小于一次障碍碰撞否决。

全部候选违法时，DWB 不会勉强输出“最不坏”的轨迹，而是报告无合法轨迹。这通常指向 Footprint、局部 Costmap、速度窗口或终点动作约束问题。

七、核心参数应该按哪条链调整 ​

7.1 候选不足 ​

检查速度上下限、vx_samples、vtheta_samples、加减速度和生成器类型。采样过少会漏掉窄通道可行解，过多则提高每周期计算量。

7.2 轨迹预测不合适 ​

检查 sim_time、linear_granularity 和 angular_granularity。预测太短容易目光短浅，太长可能让局部轨迹过度受远处几何影响。

7.3 行为偏好不合理 ​

先区分违法淘汰与合法高分，再调整 Critic。贴障碍先核对 Footprint 和障碍项，偏离路径再看 Path／Goal 距离场，终点抖动再看 RotateToGoal 与 Oscillation。

八、把 DWB 记成一句话 ​

DWB 是“可达速度离散采样＋有限时域轨迹推演＋多 Critic 代价选择”。它不是求连续最优控制，也不是机械追踪最近路径点；它用当前局部地图和运动学条件，在每个控制周期重新挑选一条可执行、代价最低的短期未来。
