不选冠军，让 1000 种未来一起投票：Nav2 MPPI 如何炼出一条速度？ ​

传统局部控制器经常给人一种直觉：生成许多候选轨迹，逐条打分，然后执行得分最低的那一条。

Nav2 MPPI 的关键恰恰不在“选中一条轨迹”。它让整批随机控制序列向未来推演，再把每条轨迹的总代价转成概率权重，最后对所有候选控制做加权平均。低代价样本拥有更大话语权，高代价样本也不会立刻消失。

这套机制把路径跟踪、避障、目标收敛和运动约束压进同一个滚动优化闭环。本文只聚焦当前本地 nav2_mppi_controller 1.1.20 的核心算法，不展开 Lifecycle、可视化和参数框架的逐函数说明。

一、MPPI 的核心不是挑出一条最低代价轨迹 ​

1.1 控制周期接收四类有效输入 ​

MPPIController::computeVelocityCommands() 从 Controller Server 获得：

  • 机器人当前位姿 robot_pose。
  • 机器人当前速度 robot_speed。
  • 已通过 setPlan() 保存的全局路径。
  • 当前 GoalChecker。

路径先被变换和裁剪，随后与当前位姿、当前速度一起送入 Optimizer::evalControl()。代价地图在整个优化期间被加锁，保证批量轨迹评分看到的是同一份环境状态。

1.2 输出只是滚动控制序列中的一个时间片 ​

优化器内部维护一条长度为 time_steps 的均值控制序列：

text
U = [u0, u1, ... , uT-1]
ut = [vx, wz]                  DiffDrive / Ackermann
ut = [vx, vy, wz]              Omni

MPPI 每周期更新整条 U，但 Controller Server 只收到其中一个时间片组成的 TwistStamped。当前工程中 controller_frequency=20 Hz、model_dt=0.05 s，两者周期相等，因此控制序列平移开启，实际输出索引为 1。

1.3 候选轨迹是控制序列的批量未来 ​

当前参数为 batch_size=1000、time_steps=56。优化器不是创建 1000 个独立对象，而是使用 xtensor 保存批量二维张量：

text
cvx、cwz        shape = [1000, 56]
x、y、yaw       shape = [1000, 56]
costs           shape = [1000]

一次迭代会同时处理 56000 个预测时间步。向量化张量运算是 MPPI 能在 CPU 上高频运行的基础。

二、全局 Path 先被收缩成局部参考 ​

2.1 最近点搜索受到累计路径长度限制 ​

PathHandler 先把机器人位姿变换到全局路径坐标系，再在 max_robot_pose_search_dist 限定的累计路径范围内寻找最近点。这个上界防止环形或自交路径把机器人错误匹配到远处的另一段。

2.2 局部路径同时受前向裁剪距离和 Costmap 边界限制 ​

从最近点向前，PathHandler 最多保留 prune_distance 范围内的路径。每个 Pose 被变换到 Local Costmap 的全局坐标系；一旦某个点落到 Costmap 外，局部路径立即停止扩展。

已经驶过的全局路径段会从内部缓存中删除。后续控制周期因此从更靠前的位置继续，而不是每次从整条全局 Path 起点重新搜索。

2.3 当前速度成为所有 rollout 的共同初值 ​

Optimizer::prepare() 把 robot_speed 写入 State::speed。生成候选状态时，所有轨迹的时间索引 0 都使用同一份实测速度：

text
vx[i, 0] = robot_speed.linear.x
wz[i, 0] = robot_speed.angular.z

候选控制从后续时间步推动状态演化。这使预测起点与机器人当前运动连续，而不是假设机器人每周期都从静止出发。

2.4 Path 被转换为三个一维张量 ​

局部 nav_msgs/Path 最终被拆成 x、y、yaw 三个张量。Critic 不再反复访问 ROS 消息对象，而是直接在连续数值数组上计算距离、角度和有效性。

三、高斯噪声把一条均值控制扩展成一批候选 ​

3.1 采样中心来自上一周期的优化结果 ​

控制序列 U 并不会在每个周期清零。正常运行时，上一周期得到的最优均值序列就是新一轮采样中心。

这是一种滚动时域思想：机器人只执行当前片段，未执行的后续控制继续作为下一周期的先验。

3.2 每个控制维度使用独立高斯扰动 ​

NoiseGenerator 根据 vx_std、vy_std、wz_std 生成零均值高斯噪声：

text
εvx ~ N(0, σvx²)
εvy ~ N(0, σvy²)
εwz ~ N(0, σwz²)

Vi = U + εi

当前差速配置使用 vx_std=0.2、wz_std=0.4、vy_std=0.0。因此探索集中在线速度和角速度两个维度，横向速度始终不参与运动。

3.3 当前配置复用同一组噪声形状 ​

regenerate_noises=false 时，噪声张量在初始化或 reset 时生成，普通优化周期不会重新随机采样。候选仍会变化，因为均值控制序列 U 在滚动更新，但相对均值的 1000 组扰动形状保持不变。

这样做减少了随机数生成带来的运行时抖动，也意味着“每周期重新抽取一批全新随机轨迹”并不符合当前源码和配置。

3.4 候选控制不会在 rollout 前统一硬裁剪 ​

state.cvx、state.cwz 由均值控制与噪声直接相加，随后进入运动模型。速度越界样本仍可生成轨迹，交给 ConstraintCritic 增加代价。

硬裁剪发生在 softmax 更新出新的均值控制序列之后。MPPI 因而可以观察边界外样本带来的代价梯度，而最终输出仍回到速度约束内。

四、运动模型把控制张量积分成未来 Pose ​

4.1 控制量按一个时间步传播到状态速度 ​

所有模型都会保留当前实测速度作为状态起点，再把候选控制序列向后错一格写入未来速度：

text
state.vx[:, 1:] = candidate.vx[:, :-1]
state.wz[:, 1:] = candidate.wz[:, :-1]

这对应“当前状态已知，控制影响后续状态”的离散系统语义。

4.2 DiffDrive 使用批量运动学积分 ​

差速模型没有横向速度。预测航向先对角速度积分：

text
θt = θ0 + Σ(ωt · dt)

随后使用每个时间片开始处的航向计算位移：

text
xt = x0 + Σ(vt · cosθ · dt)
yt = y0 + Σ(vt · sinθ · dt)

当前 56×0.05 s 形成约 2.8 s 的预测时域。按照 vx_max=0.26 m/s 估算，纯直线最大投影距离约为 0.728 m，实际还会受到转弯、障碍和 Critic 的共同影响。

4.3 Omni 在同一积分中加入横向速度 ​

全向模型额外使用 vy：

text
dx = vx · cosθ - vy · sinθ
dy = vx · sinθ + vy · cosθ

只有 isHolonomic() 返回 true 时，噪声、状态、softmax 更新和最终 Twist 才会使用 vy。

4.4 Ackermann 通过最小转弯半径限制角速度 ​

Ackermann 与 DiffDrive 一样不使用横向速度，但最终控制序列还要满足：

text
|vx| / |wz| ≥ min_turning_r

若转弯半径过小，模型约束会降低 wz。候选 rollout 本身仍可能违反该条件，ConstraintCritic 会对这些样本增加额外代价。

五、Critic 把路径、目标和障碍压成一个总代价 ​

5.1 所有 Critic 共享同一个 costs 向量 ​

CriticManager 按 YAML 中的插件顺序调用 score()。每个 Critic 都在长度为 batch_size 的 costs 上原地累加：

text
Ji = Jconstraint + Jcostmap + Jgoal + Jgoal_angle
   + Jpath_align + Jpath_follow + Jpath_angle + Jforward

Critic 不是投票器，也不会各自挑出轨迹。它们只是从不同目标出发，向同一个候选轨迹总代价写入惩罚。

5.2 ConstraintCritic 处理速度和车型可行性 ​

它对超出 vx_min、vx_max 和 vy_max 合成速度边界的部分按时间累计。Ackermann 模型还会累计小于最小转弯半径的违反量。

当前 vx_min=0.0，负向候选会被计入越界代价；最终均值控制也会被裁剪到非负线速度。

5.3 CostCritic 同时承担障碍偏好和碰撞否决 ​

当前 consider_footprint=false，每个轨迹点按机器人中心查询 Costmap：

  • 自由空间不增加代价。
  • 膨胀区累计中心点代价。
  • 内切膨胀障碍和致命障碍被视为碰撞。
  • 碰撞轨迹直接赋予 collision_cost=1000000。

当 1000 条候选全部碰撞时，fail_flag 被置为 true，后续 Critic 停止评分并触发优化器 fallback。

5.4 PathAlignCritic 约束轨迹整体贴合路径 ​

该 Critic 沿候选轨迹累计距离寻找对应的路径进度，再计算抽样轨迹点与参考路径点的平均距离。它不是简单把每个轨迹点匹配到欧氏最近路径点，因此能减少弯道和回折处的错误对应。

当局部路径被障碍占据的比例超过阈值时，路径对齐项主动退出，让障碍代价和路径推进代价主导绕行，避免为了“贴线”把机器人拉向障碍。

5.5 PathFollowCritic 奖励向路径前方推进 ​

它先找出整批候选能够到达的最远路径索引，再向前偏移若干路径点作为临时跟随目标，比较每条候选轨迹末端与该目标的距离。

若目标路径点无效，它会继续向前寻找可用路径点。这个设计鼓励机器人越过局部受阻区域，而不是把障碍位置本身当作跟随目标。

5.6 PathAngleCritic 处理机器人尚未对准路径的情况 ​

当机器人朝向与前方参考点夹角超过阈值时，该 Critic 计算整条候选轨迹朝向与“指向参考点方向”的平均角误差。

当前 vx_min=0.0 使倒车不可用，forward_preference 会被强制为 true，因此它只鼓励车头方向对准路径前方。

5.7 GoalCritic 与 GoalAngleCritic 在目标附近接管 ​

GoalCritic 只在机器人进入 threshold_to_consider=1.4 m 后启用，对候选轨迹各时间点到目标位置的平均距离计费。

GoalAngleCritic 在 0.5 m 内启用，对候选轨迹各时间点与目标航向的平均角误差计费。路径跟随项和目标项通过距离阈值完成职责切换。

5.8 PreferForwardCritic 抑制负向运动 ​

该 Critic 对每条候选轨迹中的负 vx 按时间积分。即使最终配置禁止倒车，高斯噪声仍可能产生负向候选；这个代价会进一步降低它们在 softmax 中的权重。

六、softmax 让整批未来共同更新控制序列 ​

6.1 Critic 总成本还要叠加控制扰动正则项 ​

优化器在 Critic 成本之后加入控制代价。以 vx 为例：

text
Jcontrol,i += γ / σvx² · Σt [uvx,t · (cvx,i,t - uvx,t)]

wz 和全向模型的 vy 使用相同结构。这里的 gamma 调节控制先验与采样探索之间的权衡。

6.2 最小成本只用于数值归一化 ​

源码先减去整批最小代价：

text
J'i = Ji - min(J)

这不会改变轨迹之间的相对差异，但能避免指数运算直接处理过大的绝对成本。

6.3 temperature 决定权重集中程度 ​

每条候选轨迹的权重为：

text
wi = exp(-J'i / temperature) / Σj exp(-J'j / temperature)

temperature 越小，权重越集中在低代价样本；数值越大，更多普通样本会参与平均。当前值为 0.3。

6.4 新控制序列是候选控制的加权平均 ​

源码直接计算：

text
Unew(t) = Σi wi · Vi(t)

因此 MPPI 不会把最低代价轨迹的控制序列原样搬出来。它把整个成本分布压成一条新的均值控制序列，让多个较好未来共同决定方向。

6.5 iteration_count 决定同周期内重复优化次数 ​

一次迭代包含噪声叠加、运动学 rollout、Critic 评分和 softmax 更新。当前 iteration_count=1，每个控制周期只执行一轮，计算预算主要投向更大的 batch_size。

七、softmax 之后还有约束、滤波和滚动平移 ​

7.1 新均值序列先执行硬约束 ​

softmax 更新完成后，vx、vy、wz 被裁剪到当前速度限制。Ackermann 模型再修正不满足最小转弯半径的角速度。

SpeedLimit 会改变这组约束：百分比限速按相同比例缩放各方向速度；绝对限速以 vx_max 比例同步缩放 vx_min、vy 和 wz。

7.2 Savitzky-Golay 滤波降低控制序列抖动 ​

evalControl() 在优化结束后使用 9 点二次 Savitzky-Golay 系数平滑整条 vx、vy、wz 序列。序列头部还会使用最近四次输出历史补齐滤波窗口。

该滤波直接作用于未来控制序列，而不仅是当前待发布速度，因此下一周期继承的采样中心也被同步平滑。

7.3 当前频率启用控制序列平移 ​

当前控制周期与 model_dt 都是 0.05 s。初始化时 setOffset() 因两者相等而启用 shift_control_sequence：

text
发布 U[1]
U 向左滚动一个时间片
末尾复制原末端值

上一周期预测中的近期控制因此与真实时间推进对齐。若控制周期大于 model_dt，初始化会直接抛异常；若控制周期更短，只记录告警并关闭平移。

7.4 输出保留运动模型的自由度 ​

DiffDrive 和 Ackermann 输出 linear.x 与 angular.z，linear.y 保持为零。Omni 才会把 vy 写入 TwistStamped。

八、全部候选碰撞时，算法重置后再试 ​

8.1 fail_flag 来自障碍 Critic 的整批判定 ​

单条轨迹碰撞只会获得巨大成本；只有全部候选都碰撞时，CostCritic 才设置 fail_flag。CriticManager 随即停止剩余评分，但本轮仍会执行一次 softmax 更新，随后 fallback reset 整个优化器。

8.2 reset 会清空控制先验并重新准备噪声 ​

reset 会：

  • 把状态张量和均值控制序列清零。
  • 清空四帧控制历史。
  • 恢复基础速度约束。
  • 清零候选轨迹和成本。
  • 重新准备高斯噪声。

这相当于放弃已经陷入局部失败的滚动先验，从零控制中心重新探索。

8.3 重试耗尽后把失败交给 Controller Server ​

retry_attempt_limit 默认是 1。持续全碰撞时，优化器进行一次软重置重试；再次失败就抛出运行时异常，外层 Controller Server 再决定停止、切换控制器或触发恢复行为。

8.4 长时间未调用也会主动 reset ​

当前 reset_period=1.0 s。若控制器两次调用间隔超过该值，旧控制序列会被清空，避免机器人暂停后继续沿用过期控制先验。

九、当前工程参数塑造出的算法行为 ​

9.1 计算预算集中在批量宽度 ​

当前每周期使用 1000 条候选、56 个时间步和一次优化迭代。设计选择是“更宽地观察随机未来”，而不是在同一周期反复进行多轮小批量收敛。

9.2 预测时域覆盖低速机器人近期局部空间 ​

2.8 s 时域配合 0.26 m/s 最大前进速度，理论直线投影约 0.728 m。Local Costmap、prune_distance=1.5 m 和 Path Critic 的偏移仍需提供足够前向路径，否则再大的 batch 也无法评价看不到的区域。

9.3 当前配置只允许前进和原地转向 ​

motion_model=DiffDrive、vy_max=0.0、vx_min=0.0。最终控制不会横移或倒车，但噪声候选仍可能短暂越界，再由 ConstraintCritic、PreferForwardCritic 和最终裁剪共同压回合法范围。

9.4 目标附近会从路径跟踪转向目标收敛 ​

远离目标时，PathAlign、PathFollow、PathAngle 和 CostCritic 共同决定路径推进与避障。进入 1.4 m 后 GoalCritic 开始参与；进入 0.5 m 后 GoalAngleCritic 强化末端航向，PathAlign、PathAngle 和 PreferForward 逐渐退出。

9.5 当前 CostCritic 使用中心点碰撞语义 ​

consider_footprint=false 减少了每个预测 Pose 的 Footprint 计算量，但控制器依据中心 Costmap 代价判断内切与致命障碍。对于非圆形大车，是否切换完整 Footprint 必须与 Costmap 的机器人几何和计算预算一起评估。

十、读源码时必须看见的实现边界 ​

10.1 多轮迭代会继续累加上一轮 costs ​

prepare() 只在控制周期开始时把 costs 清零。optimize() 内若 iteration_count>1，后续迭代会继续在已有成本上累加 Critic 和控制正则项。

当前配置固定为一轮，因此不会触发这种累计效应；调大迭代次数时不能只按教科书中的“每轮独立重算成本”理解。

10.2 Savitzky-Golay 滤波后没有再次硬裁剪 ​

硬速度约束发生在 updateControlSequence() 末尾，而 Savitzky-Golay 滤波发生在整个 optimize 之后。滤波系数包含负值，源码没有在滤波后重新执行 applyControlSequenceConstraints()。

这意味着“softmax 后均值序列已受限”是确定事实，“最终发布值必然再次经过相同硬裁剪”则不是当前实现。

10.3 Costmap 外的预测点按未知空间策略解释 ​

轨迹点无法映射到 Costmap 时，CostCritic 把它视为 NO_INFORMATION。若 Costmap 允许跟踪未知空间，该点不算碰撞；否则按碰撞处理。

预测时域、最大速度和 Local Costmap 尺寸必须一起调，否则控制行为会被地图边界而非真实障碍主导。

10.4 固定噪声不是固定候选轨迹 ​

regenerate_noises=false 只固定相对扰动矩阵。均值控制、机器人初始状态、局部路径和 Costmap 每周期都在变化，所以积分出来的候选轨迹仍然变化。

把它理解为“固定的一组探索方向围绕移动中的控制中心”，比“每次都跑同样的 1000 条轨迹”更准确。

10.5 fallback 计数器是函数内 static 状态 ​

Optimizer::fallback() 的失败计数器声明为函数内 static，不是 Optimizer 成员。单进程加载多个 MPPI 实例时，这个计数状态可能在实例之间共享。

普通单控制器配置通常不会暴露该边界，但多机器人 Composition 或多 MPPI 插件实例需要注意。

10.6 Costmap 锁覆盖整个优化过程 ​

Controller 在进入 Optimizer::evalControl() 前锁住 Costmap mutex，直到批量 rollout、全部 Critic、softmax、滤波和输出完成后才释放。

这保证一个控制周期内环境数据一致，也意味着高 batch、重 Footprint 评分或可视化会延长 Costmap 被占用的时间。

十一、哪些关键能力来自包外 ​

11.1 Controller Server 提供控制闭环 ​

本包只实现 nav2_core::Controller 插件。控制频率、路径 Action、当前速度来源、速度发布、异常处理与控制器切换由包外 Controller Server 负责。

11.2 TF2 和 nav2_util 提供局部路径变换 ​

路径 Pose 的坐标变换由 TF2 Buffer 完成；累计路径距离、最近点搜索等几何工具来自 nav2_util。MPPI 只消费变换后的局部参考。

11.3 Costmap2D 提供障碍环境 ​

CostCritic 读取包外 Local Costmap 的栅格代价、未知空间策略、Inflation Layer 和可选 Footprint。MPPI 本身不维护激光、点云或障碍生命周期。

11.4 GoalChecker 提供目标容差 ​

部分 Critic 通过 GoalChecker 读取位置容差，决定何时停止普通路径行为。GoalChecker 的最终到达判定和状态策略不在本包内。

11.5 pluginlib 和 xtensor 提供扩展与计算底座 ​

Critic 通过 pluginlib 动态加载；批量控制、状态、轨迹、代价和 softmax 由 xtensor 向量化运算完成。它们分别提供算法可组合性和 CPU 批处理能力。

十二、MPPI 真正优化的是什么 ​

12.1 它优化的是一条随时间变化的控制分布中心 ​

候选轨迹只是评价控制序列的未来结果。每周期真正被保留下来的是新的均值控制序列 U，而不是某条轨迹对象。

12.2 它用 Critic 把多目标转成同一种货币 ​

路径偏差、目标距离、航向误差、倒车倾向、速度越界和碰撞风险最终都写入同一个标量成本。Critic 权重决定不同工程目标之间的兑换比例。

12.3 它用概率权重替代赢家通吃 ​

softmax 让低代价样本主导更新，又保留一批次优样本的方向信息。机器人因此不是机械复制某条随机轨迹，而是在大量未来之间形成更稳定的折中控制。

12.4 它依赖下一周期继续修正 ​

机器人只执行滚动控制序列中的近期时间片。新的位姿、速度、路径和 Costmap 很快再次进入优化器，旧预测误差不会被一次性执行到底。

所以 MPPI 的能力不来自“算准 2.8 秒后的唯一未来”，而来自不断采样、不断重估、不断把整批未来压回当前这一条速度。
