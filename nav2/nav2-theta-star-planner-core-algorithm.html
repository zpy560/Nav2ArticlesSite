A* 为什么非要一格一格拐？Nav2 Theta* 用一条视线把路径拉直 ​

普通栅格 A* 即使找到了最短路，也常交出一条“横一下、斜一下”的折线。问题不在 A* 不会算最短路，而在搜索图只允许节点连接有限个相邻栅格：父指针被锁在四邻域或八邻域里，最终路径自然带着网格方向的痕迹。

Nav2 Theta* 保留 A* 的开放队列、g+h 和父指针，却在节点真正展开前多问一句：当前节点能否直接看见父节点的父节点？如果中间无遮挡，而且直连更便宜，就跳过原父节点。一个局部重连动作，便把栅格折线拉成了任意角路径。

本文基于当前本地 navigation2@03db095、nav2_theta_star_planner 1.1.20 源码、测试与现用参数，只拆 Lazy Theta* P 的核心搜索、视线检查、代价函数、容器状态、回溯与实现边界。

一、Theta* 改的不是 A*，而是父节点关系 ​

1.1 普通 A* 的路径为什么带栅格味 ​

四邻域 A* 每次只能上下左右移动，八邻域再增加四个对角方向。无论启发函数多聪明，新节点的父节点都只能是直接扩展它的相邻节点。

因此，开放空间中的一条真实直线，会被离散成水平、垂直和四十五度斜线的组合。地图分辨率越粗，折线感越明显。

1.2 Theta* 允许跨过相邻节点 ​

设当前节点为 s，它的父节点为 p，祖父节点为 q。普通 A* 保留：

text
q → p → s

Theta* 会检查 q 到 s 的直线。如果沿线安全，并且：

text
g(q) + line_cost(q,s) < g(s)

就把父链改成：

text
q ─────────→ s

p 没有从搜索图消失，只是不再是 s 的最优父节点。不断发生的局部“抄近路”，最终形成少折点的任意角父链。

1.3 当前实现是 Lazy Theta* P ​

经典 Theta* 常在生成邻居时执行视线检查。当前源码采用 Lazy Theta* P 风格：邻居先按普通相邻边入队，等它成为待扩展节点后，resetParent() 才尝试连接祖父节点。

这减少了对所有候选邻居立即做视线检查的次数。代价是父节点修正发生得更晚，必须准确理解“入队”和“出队展开”两个时刻。

二、一个搜索节点究竟保存什么 ​

2.1 tree_node 是算法的最小状态 ​

每个节点保存：

  • 栅格坐标 x、y。
  • 起点累计代价 g。
  • 到目标的启发代价 h。
  • 总优先级 f=g+h。
  • 父节点指针 parent_id。
  • 当前是否在优先队列中的 is_in_queue。

起点的父指针指向自己。回溯遇到“父节点就是自身”时，便知道已经到达根节点。

2.2 node_position_ 负责按栅格查节点 ​

算法没有为整张图构造完整节点对象。node_position_[width*y+x] 保存该栅格对应的 tree_node*；未发现的栅格为 nullptr。

这张索引表负责快速回答“这个栅格以前见过吗”。真正被搜索到的节点连续存入 nodes_data_。

2.3 nodes_data_ 提供稳定节点存储 ​

地图尺寸初次出现或扩大时，源码按地图单元数为 nodes_data_ 预留容量，避免搜索中扩容后指针失效。新栅格初次出现时才从这块连续存储中分配一个节点位置。

2.4 queue_ 决定下一次展开谁 ​

queue_ 是按 f 从小到大弹出的优先队列。启发项让搜索倾向目标，累计代价又阻止它只顾眼前方向、不顾已经付出的路径成本。

这里没有独立的 Closed Set。节点展开时把 is_in_queue 置为 false；以后若发现更低代价，它仍可能再次入队。这个布尔量表达的是“是否在队列”，不是永久访问标记。

三、主循环如何从起点推进到目标 ​

3.1 起点也要支付栅格通行代价 ​

初始化时：

text
g(start) = traversal_cost(start)
h(start) = heuristic(start, goal)
f(start) = g(start) + h(start)
parent(start) = start

随后起点进入优先队列和栅格索引表。

3.2 待扩展节点先尝试修正父节点 ​

主循环对当前节点执行 resetParent()。它读取：

text
parent = current.parent
maybe_parent = parent.parent

若 current 与 maybe_parent 存在视线，就按整段直线重新计算 g。只有新值更低时，才修改父指针、g 和 f。

3.3 再扩展四邻域或八邻域 ​

how_many_corners=4 时，算法只使用固定移动表前四项，也就是上下左右。设为 8 时，再加入四个对角邻居。

邻居必须同时满足地图边界与通行条件。候选累计代价更低时，算法更新邻居的 g、h、f 与父节点；若它当前不在队列，再压入优先队列。

3.4 目标必须成为当前节点 ​

算法不是“发现目标邻居”就结束，而是等待目标成为当前节点，再进入回溯。开放队列耗尽则清空结果并报告失败。

当前现用配置为八邻域。八邻域只决定搜索图如何发现候选节点；任意角能力来自后续视线重连，不是来自对角移动本身。

四、视线检查如何判断一条直线能不能走 ​

4.1 它是带代价累计的 Bresenham ​

losCheck(x0,y0,x1,y1,sl_cost) 使用整数增量沿线推进，不需要把直线上的每个点转换成浮点坐标。

当横向跨度更大时，以 x 为主轴；纵向跨度更大时，以 y 为主轴。误差累计越过阈值时，副轴移动一个栅格。

4.2 检查结果不只是“通”或“不通” ​

每经过一个相关栅格，重载版 isSafe() 同时完成两件事：

  • 原始 Costmap 值为 0～252 时允许通过。
  • 原始值为 255 时，只在 allow_unknown=true 时允许通过。
  • 原始值为 253 或 254 时拒绝通过。
  • 对允许通过的栅格，把穿越代价累加到 sl_cost。

因此，两个端点之间即使都有视线，贴着膨胀层走的直线也可能比稍长但更居中的路线昂贵。

4.3 水平与垂直边界允许从一侧通过 ​

直线恰好沿两排栅格的公共边界移动时，源码会检查边界两侧。只有两侧都不安全才拒绝这条线。

这是一种点机器人式的栅格可见性语义。算法本身不沿直线旋转并检查完整 Footprint，机器人外形依赖 Global Costmap 的 Inflation 预先编码。

4.4 未知区可走不等于便宜 ​

未知栅格允许通过时，LOS 累计代价把它按接近障碍的高值 253 处理。它能保证搜索在探索地图中仍有路可走，却不会把未知区当成普通自由空间。

五、路径为何会在“最短”和“离障碍远”之间折中 ​

5.1 相邻扩展的累计代价 ​

从当前节点 n 走到邻居 m：

text
g_new(m) =
  g(n)
  + w_euc × hypot(mx-nx, my-ny)
  + w_traversal × ((26 + 0.9×C(m)) / 252)²

其中 C(m) 是 Costmap 原始值。源码先把原始代价平移并缩放为 26+0.9×C，再归一化、平方。

自由栅格也不是零穿越成本，因为平移后至少为 26。靠近障碍时，平方项会快速放大差异。

5.2 祖父节点直连的累计代价 ​

视线重连时：

text
g_los(current) =
  g(grandparent)
  + w_euc × distance(grandparent,current)
  + LOS 沿线累计穿越代价

只有 g_los < g(current) 才采用祖父节点。能看见只是必要条件，直连还必须在完整代价模型下更划算。

5.3 启发项保持保守 ​

text
h(n) = w_h × distance(n,goal)
w_h = min(w_euc, 1.0)
f(n) = g(n) + h(n)

配置阶段把启发权重限制在 w_euc 与 1.0 的较小值，避免启发项比几何移动代价更激进。

当前三套主要配置均使用：

text
how_many_corners = 8
allow_unknown = true
w_euc_cost = 1.0
w_traversal_cost = 2.0
use_final_approach_orientation = false

5.4 两个权重分别控制什么 ​

提高 w_euc_cost，更强调路径长度，结果倾向绷紧，但也可能更靠近障碍。

提高 w_traversal_cost，更强调 Inflation 代价，结果倾向走廊中部，但可能变长并扩展更多节点。

调 Theta* 不能只看这两个权重。Global Costmap 的 inflation_radius 与 cost_scaling_factor 决定算法究竟能“看见”多宽、多平缓的障碍代价坡面。

六、搜索成功后如何变成一条 Nav2 Path ​

6.1 父指针从目标回到起点 ​

backtrace() 从目标节点开始，不断读取 parent_id，把每个栅格中心通过 mapToWorld() 转成世界坐标。得到的逆序序列再反转，形成起点到目标的任意角折线。

路径的转折点不是每个 A* 相邻栅格，而是父节点重连后保留下来的可见性关键点。

6.2 线性插值把长直线重新采密 ​

任意角父链可能一段跨越很多栅格。linearInterpolation() 以 Costmap 分辨率为间距，在每个父链线段上补充 Pose，避免下游控制器只拿到极稀疏的折点。

这一步只做直线采样，不再次执行碰撞检查，也不做曲率优化。

6.3 末点朝向有两种语义 ​

use_final_approach_orientation=false 时，输出末 Pose 使用请求目标的方向。

设为 true 时，末 Pose 朝向由最后两个输出点的连线计算，让机器人沿最终接近方向到达，而不是在路径末端强行匹配目标 yaw。

七、当前实现中必须看懂的边界 ​

7.1 它没有目标容差回退 ​

Theta* 没有 NavFn 那种 tolerance 邻域搜索。目标栅格不安全或不可达时，结果就是空路径，不会自动选择目标附近的可达点。

7.2 同栅格快速路径的安全语义不同 ​

起终点落在同一栅格时，包装层只拒绝原始值等于 LETHAL_OBSTACLE 的栅格。该分支没有复用算法层 isSafe()，因此对 253、未知区和 allow_unknown 的解释与普通搜索分支并不完全一致。

7.3 优先队列没有 decrease-key ​

节点已经在队列中时，如果找到更低代价，源码会直接修改该节点对象的 f，但不会重新压入队列，也不会重建堆。

标准 C++ priority_queue 不会因为指针指向对象的值改变而自动恢复堆序。这意味着队首顺序可能暂时不再严格对应最新 f。

7.4 主循环的队列与当前节点错开一拍 ​

源码先处理 curr_data，再从队列取出下一节点。起点最初既是 curr_data 又留在队列中，因此可能被重复展开。

如果取出某个节点后队列恰好为空，下一轮不会再进入目标判断，随后 queue_.empty() 分支会报告失败。这个终止结构与常见的“先 pop、再判断目标”写法不同，需要专门的极小地图测试覆盖。

7.5 动态参数不完全重建派生状态 ​

配置阶段会把非法 how_many_corners 恢复为 8，动态回调却直接接受整数。大于固定移动表长度 8 的值会越界访问。

动态修改 w_euc_cost 时，源码也不会重新计算 w_heuristic_cost=min(w_euc_cost,1.0)。实车上更适合停用规划器后修改这类核心参数，再重新配置。

7.6 插值输出没有显式追加原始终点 ​

当前插值循环只为每段写入段首和中间采样点，没有在循环结束后显式写入 raw_path.back()。输出末点可能停在目标栅格中心前一个分辨率以内，而末点方向仍会被赋成目标方向或接近方向。

7.7 Costmap 锁覆盖完整计算 ​

createPlan() 从坐标检查开始持有 Costmap mutex，直到搜索、回溯和插值结束。复杂地图上，Theta* 的搜索耗时也会成为 Costmap 更新的阻塞时间。

八、什么场景适合 Theta* ​

8.1 开放空间与斜向走廊 ​

当真实最优方向不与地图轴对齐时，Theta* 能用长视线段减少八邻域 A* 的锯齿。

8.2 小型差速或全向机器人 ​

算法搜索 (x,y)，不携带航向、最小转弯半径或倒车状态。它适合由下游控制器消化折点的小型差速和全向底盘。

8.3 不适合把车辆运动学交给规划器的场景 ​

汽车型机器人若需要在全局搜索阶段保证曲率、朝向和倒车可行性，Smac Hybrid 或 State Lattice 更直接。Theta* 的直线可见不等于车辆能以合法转弯半径连接两段路径。

九、结语 ​

Theta* 的核心可以压缩成一句话：先按 A* 发现节点，再用 Costmap 上的视线检查重写父指针。

真正决定结果的不是“有没有一条直线”，而是三层约束共同作用：栅格是否安全、沿线穿越代价是否值得、祖父节点直连是否降低累计 g。理解 resetParent()、losCheck() 与代价公式后，就能分清任意角路径、贴障程度、未知区策略和搜索速度分别该从哪里调。

同时也要尊重当前实现边界：它不搜索目标容差，不检查完整运动学，优先队列更新与终止循环还有需要回归测试守住的角落。Theta* 能把栅格路径拉直，但不会替机器人解决所有几何与工程问题。
