不采样、不打分，一条公式如何让机器人优雅转弯？拆解 Nav2 Graceful Controller 核心算法 ​

DWB 会采样速度并给轨迹打分，MPPI 会批量 rollout 并迭代优化。nav2_graceful_controller 走的是另一条路：它从全局路径上取一个运动目标，把目标改写成机器人视角下的极坐标，再用一条基于 Lyapunov 思想的平滑控制律直接算出曲率、线速度和角速度。

它没有候选轨迹矩阵，也没有 Critic 权重表。每个控制周期只生成一条速度指令，再沿这条控制律向前积分出一条预测轨迹，用 Costmap 判断能否安全执行。

本文基于当前工程的 nav2_graceful_controller 1.1.20，只拆核心算法。Lifecycle 配置、Publisher 激活、Pluginlib 注册和可视化消息只说明接口边界，不展开成工程流程。

一、核心边界：它究竟接收什么，又输出什么 ​

1.1 输入不是一张局部轨迹候选表 ​

computeVelocityCommands() 的主要输入是当前机器人位姿 pose、当前速度 velocity 和包外 GoalChecker。当前源码没有使用 velocity 参数，真正进入控制律的是当前位姿、已经保存的全局路径、动态参数以及目标检查器给出的距离容差。

全局路径由包外 Controller Server 通过 setPlan() 写入 PathHandler::global_plan_。后续每个控制周期都在这条路径上裁剪已走部分、截取局部片段并选择运动目标。

1.2 输出是一条 TwistStamped ​

控制器最终输出：

text
linear.x  = v
angular.z = ω

差速机器人据此执行前进、倒车或原地旋转。linear.y 等其他分量保持零值。

1.3 算法同时输出一条验证轨迹 ​

速度指令之外，控制器还用相同平滑控制律迭代调用 calculateNextPose()，生成 local_plan。这条 Path 主要承担碰撞预测和调试可视化，不参与候选轨迹比较。

因此它的核心不是“生成很多条再选一条”，而是“先算出唯一控制律，再验证这条控制律将把机器人带到哪里”。

二、路径进入控制律前，先被裁剪到机器人附近 ​

2.1 transformGlobalPlan() 先找到路径上的机器人附近点 ​

PathHandler::transformGlobalPlan() 先通过包外 nav_2d_utils::transformPose()，把当前机器人位姿变换到全局路径坐标系。

源码不会在整条路径上无限搜索最近点。它用 first_after_integrated_distance() 沿路径累计距离，得到 max_robot_pose_search_dist 上界，再在这个范围内用 min_by() 找欧氏距离最小的路径点。

这一步避免路径在局部 Costmap 中回环时，控制器错误跳到更靠后的相交路段。

2.2 局部窗口只保留 Costmap 能覆盖的路径 ​

从最近点开始，源码找到首个距机器人超过下式阈值的路径点：

text
dist_threshold = max(costmap_size_x, costmap_size_y) / 2

最近点到该点之前的路径被逐点变换到机器人基坐标系。包外 TF 变换失败、原始路径为空或变换后路径为空，都会抛出 nav2_core::PlannerException。

已走过的原始路径段随后从 global_plan_ 中删除。这个 path pruning 会改变包内保存的路径，使下个控制周期不再重复处理身后路段。

2.3 getMotionTarget() 用径向距离选前视点 ​

变换后的路径已经位于机器人坐标系。getMotionTarget() 从头扫描，选择第一个满足下式的 Pose：

text
hypot(x, y) >= motion_target_dist

这里比较的是路径点到机器人原点的直线距离，不是沿路径累计距离。若所有点都不够远，就使用最后一个 Pose，也就是当前局部路径能够提供的最远目标。

2.4 距终点的判断使用路径累计距离 ​

运动目标点用径向距离选择，但 dist_to_goal 使用 calculate_path_length() 对变换后路径逐段累计。

弯曲路径中，这两个距离并不相同：

  • 径向距离决定控制器现在追哪个点。
  • 路径累计距离决定是否已经进入目标附近和最终旋转阶段。

当 final_rotation=true 且剩余路径短于 motion_target_dist，源码会忽略目标 Pose 原本的朝向，改用路径最后一段的切线方向作为运动目标朝向。真正的目标朝向留给最后的原地旋转处理。

三、三个自车极坐标，把目标位姿变成控制误差 ​

3.1 r 描述还要走多远 ​

EgocentricPolarCoordinates 接收同一坐标系中的目标 Pose 和当前 Pose：

text
Δx = target.x - current.x
Δy = target.y - current.y
r  = sqrt(Δx² + Δy²)

在实时速度计算中，当前 Pose 使用默认原点，因此 r 就是运动目标到机器人基坐标系原点的距离。

3.2 line_of_sight 建立机器人到目标的视线 ​

正向运动时源码计算：

text
line_of_sight = atan2(-Δy, Δx)

这里的 -Δy 来自该控制律采用的角度符号约定。随后所有角度都经过包外 angles::normalize_angle() 归一化到标准周期范围。

3.3 phi 描述目标朝向相对视线的误差 ​

text
phi = normalize(target_yaw + line_of_sight)

phi 不是机器人当前航向误差，而是运动目标期望朝向相对目标视线的关系。它决定慢子系统希望机器人以怎样的姿态收敛到目标 Pose。

3.4 delta 描述机器人当前转向相对视线的误差 ​

text
delta = normalize(current_yaw + line_of_sight)

delta 把机器人当前朝向与目标视线联系起来。实时计算默认 current_yaw=0，因为运动目标已经被变换到机器人基坐标系。

3.5 倒车会翻转视线和目标朝向 ​

当 allow_backward=true 且运动目标位于机器人后方，也就是 motion_target.x < 0，主控制器进入 reversing 模式。

主控制器把运动目标 yaw 加上 π；极坐标构造又把视线翻转到倒车方向。控制律随后反转曲率符号和线速度符号，使机器人以负 linear.x 接近目标，同时保持所需转向关系。

当前参数逻辑不允许 initial_rotation 和 allow_backward 同时生效。构造阶段两者都为 true 时会关闭倒车；动态修改发生冲突时，包内参数会忽略冲突值。

四、平滑控制律如何从姿态误差得到曲率 ​

4.1 比例项约束快速转向误差 ​

calculateCurvature() 先计算：

text
prop_term = k_delta × [delta - atan(-k_phi × phi)]

atan(-k_phi × phi) 是慢子系统给快速转向子系统的虚拟控制目标。delta 与该目标的差值越大，比例项越强。

k_delta 决定快速子系统修正航向的力度。值越大，机器人越积极地把当前转向角拉向虚拟目标，但角速度也更容易触发上限。

4.2 反馈项把视线误差带回闭环 ​

源码的反馈项为：

text
feedback_term =
  [1 + k_phi / (1 + (k_phi × phi)²)] × sin(delta)

它同时依赖 phi 和 delta。当 phi 接近零时，分式中的增益更明显；当目标姿态误差增大时，分母抑制该附加增益，避免修正无限放大。

4.3 曲率把两个子系统合并 ​

最终曲率为：

text
kappa = -(prop_term + feedback_term) / r

曲率绝对值越大，轨迹转弯越急；正负号决定转向方向。k_phi=0 时，目标姿态对慢子系统的影响被大幅削弱，控制器更接近只追位置的 waypoint follower。

4.4 r 同时带来收敛能力和奇异风险 ​

曲率包含 1 / r。机器人接近运动目标时，微小角度误差可能产生很大的曲率。

源码没有在 calculateCurvature() 内给 r 设置下限，而是依靠运动目标前视距离、目标附近线速度下降、角速度限幅和最终旋转分支共同减轻奇异性。若直接用几乎重合的 Pose 调用控制律，仍需要调用者理解这条边界。

五、曲率不是速度，控制器还要经过四层约束 ​

5.1 曲率越大，基础线速度越低 ​

源码先按曲率生成线速度候选：

text
v_curve = v_linear_max /
          [1 + beta × abs(kappa)^lambda]

beta 控制弯道降速的强度。lambda 控制曲率影响的非线性形状；值越大，高曲率区的速度下降越集中。

5.2 距运动目标越近，目标减速越明显 ​

另一条速度候选为：

text
v_slow = v_linear_max × r / slowdown_radius
v      = min(v_curve, v_slow)

这条规则围绕每个运动目标生效，并不只围绕全局终点生效。由于运动目标通常在路径前方滚动，正常跟踪时 r 会维持在前视距离附近；路径尾端无法再提供足够远的目标后，r 才持续缩小。

5.3 最小线速度会重新抬高速度 ​

随后源码执行：

text
v = clamp(v, v_linear_min, v_linear_max)

这意味着 v_slow 即使接近零，也会被 v_linear_min 抬高。控制律自身不会连续减速到完全静止，最终停车依赖 GoalChecker、最终旋转状态和 Controller Server 的任务终态。

倒车模式在 clamp 之后把 v 变成负值。

5.4 角速度限幅后重新投影线速度 ​

控制律先计算：

text
omega_raw = kappa × v
omega     = clamp(omega_raw, -v_angular_max, v_angular_max)

若角速度触顶，源码不是只截断 omega，而是重新计算：

text
v = omega / kappa

这样仍保持 omega / v = kappa，机器人不会因为角速度限幅而改变原计划曲率。代价是最终线速度可能低于前面设置的 v_linear_min；所以 v_linear_min 是角速度限幅之前的下限，不是最终输出的绝对保证。

5.5 当前工程参数代表怎样的行为 ​

nav2_regulated_modules 当前配置使用：

text
motion_target_dist = 0.6 m
k_phi              = 3.0
k_delta            = 2.0
beta               = 0.2
lambda             = 2.0
v_linear_min       = 0.03 m/s
v_linear_max       = 0.22 m/s
v_angular_max      = 1.0 rad/s
slowdown_radius    = 1.5 m

它把线速度压在实车较保守的范围内，同时保留较大的角速度余量。弯道中一旦 omega 接近上限，线速度会进一步被重新投影降低。

六、同一个控制周期可能进入三种运动模式 ​

6.1 最终旋转优先级最高 ​

当 final_rotation=true，并且剩余路径累计距离小于 GoalChecker 的位置容差，或 goal_reached_ 已经置位，控制器进入最终旋转。

它读取变换后路径最后一个 Pose 的 yaw，调用 rotateToTarget() 输出零线速度和角速度。goal_reached_ 是锁存状态，只有收到新路径时才由 setPlan() 清零，因此进入最终旋转后不会重新退回路径跟踪。

6.2 初始旋转处理前方偏角过大 ​

未进入最终旋转时，如果 initial_rotation=true 且运动目标方位角满足：

text
abs(atan2(target.y, target.x)) > initial_rotation_min_angle

控制器先原地朝向运动目标，避免平滑控制律从大偏角状态生成宽大的扫掠弧线。

6.3 常规跟踪直接调用平滑控制律 ​

两个旋转条件都不成立时，calculateRegularVelocity() 使用运动目标 Pose 计算唯一一组 v 与 omega。

传入 computeVelocityCommands() 的当前速度没有参与计算，因此该控制器本身不限制加速度和 jerk。项目中的 Velocity Smoother 或底盘控制器仍需承担速度时序平滑。

6.4 倒车是常规跟踪的方向变体 ​

倒车不会创建第四套曲率公式。它仍使用同一个 calculateRegularVelocity()，只是改变目标朝向、极坐标视线、曲率符号和线速度符号。

6.5 rotateToTarget() 是比例旋转而非严格限幅 ​

源码计算：

text
linear.x  = 0
angular.z = rotation_scaling_factor
            × angle_to_target
            × v_angular_max

这个结果没有再 clamp。若 rotation_scaling_factor × abs(angle_to_target) > 1，输出角速度可能超过 v_angular_max。默认缩放系数为 0.5，最大角误差接近 π 时理论输出约为 1.57 × v_angular_max。

七、唯一速度指令还要通过前向碰撞预测 ​

7.1 当前真实位姿先检查一次 ​

simulateTrajectory() 先把 computeVelocityCommands() 收到的机器人位姿交给 inCollision()。当前 Footprint 已在致命障碍物中时，函数立即返回 false。

7.2 积分步长由 Costmap 分辨率和最大线速度决定 ​

源码使用：

text
dt = costmap_resolution / v_linear_max

在直线且速度接近最大值时，每次积分大约移动一个栅格。最大迭代数为：

text
max_iter = 2 × target_distance / costmap_resolution

系数 2 给弯曲轨迹留出比直线距离更多的积分步数，同时限制异常情况下的无限循环。

7.3 calculateNextPose() 使用一阶欧拉积分 ​

每轮都基于预测 Pose 重新计算控制律：

text
x_next   = x + v × dt × cos(yaw)
y_next   = y + v × dt × sin(yaw)
yaw_next = yaw + omega × dt

因此预测轨迹的曲率会随 r、phi 和 delta 变化，不是一段固定圆弧。

7.4 每个预测 Pose 都要回到 Costmap 全局坐标系 ​

预测从机器人基坐标系原点开始。每个 next_pose 经包外 tf2::doTransform() 转到 Costmap 全局坐标系，再由 inCollision() 查询 Footprint 或机器人半径对应的栅格代价。

遇到 LETHAL_OBSTACLE 时判碰撞。是否把 INSCRIBED_INFLATED_OBSTACLE 和 NO_INFORMATION 视为碰撞，取决于机器人使用 Footprint 还是半径，以及 Layered Costmap 是否跟踪未知空间。

7.5 预测结束条件不是全局 Goal ​

预测 Pose 距运动目标小于一个 Costmap 分辨率，或轨迹长度达到 max_iter，循环结束并返回 true。

这只证明当前控制律在有限预测段内没有检测到碰撞，不代表整条全局路径安全。Controller Server 会在下个周期用更新后的机器人位姿和 Costmap 再计算。

八、速度限制如何改变控制律 ​

8.1 百分比限制同时缩放线速度与角速度 ​

setSpeedLimit(speed_limit, true) 以初始最大速度为基准：

text
v_linear_max  = max(v_linear_max_initial × percent / 100,
                    v_linear_min)
v_angular_max = v_angular_max_initial × percent / 100

线速度不会低于 v_linear_min，角速度没有同类最小值。

8.2 绝对线速度限制按比例缩放角速度 ​

绝对限制模式把输入解释为 m/s：

text
v_linear_max  = max(speed_limit, v_linear_min)
v_angular_max = v_angular_max_initial
                × speed_limit / v_linear_max_initial

角速度按原始线速度比例缩放，使外部限速不会只压低平移而保留过高转向能力。

8.3 取消限速恢复初始最大值 ​

收到包外 NO_SPEED_LIMIT 标志时，两个最大速度恢复到参数处理器保存的 initial 值。动态修改最大速度参数也会更新 initial 值，所以恢复的是最近一次参数基线，不一定是进程启动时的默认值。

九、哪些关键调用不在本包内 ​

9.1 Controller Server 提供执行时机 ​

nav2_core::Controller 只定义插件接口。包外 Controller Server 负责接收 FollowPath Action、调用 setPlan()、周期调用 computeVelocityCommands()，并把返回速度发布到后续 Topic。

Graceful Controller 不拥有导航任务状态机，也不决定何时取消 Action。

9.2 TF 与 nav_2d_utils 提供坐标变换 ​

机器人位姿进入全局路径坐标系、局部路径进入机器人基坐标系，以及预测 Pose 进入 Costmap 全局坐标系，都依赖包外 tf2_ros::Buffer、nav_2d_utils::transformPose() 和 tf2::doTransform()。

本包只决定变换发生在哪个算法阶段，不实现 TF 缓存和插值。

9.3 nav2_util 提供路径数学 ​

最近点上界、最小距离点、路径累计长度、欧氏距离和 yaw 四元数生成来自包外 nav2_util::geometry_utils。

9.4 Costmap 提供环境碰撞语义 ​

Costmap2DROS 提供分辨率、尺寸、坐标系、Footprint、机器人半径和未知空间策略。FootprintCollisionChecker 负责计算指定 Pose 上的点代价或 Footprint 代价。

本包只把这些代价值归类为可继续或碰撞。

9.5 GoalChecker 和 Velocity Smoother 补齐终点与时序闭环 ​

包外 GoalChecker 提供位置容差，并最终判断导航目标是否完成。Graceful Controller 的平滑控制律只处理几何收敛。

输入的当前速度未参与控制律，所以加减速度、命令频率补齐和基于 Odometry 的速度反馈，需要由包外 Velocity Smoother、底盘控制器或其他下游模块完成。

十、读源码时不能忽略的六个边界 ​

10.1 当前速度输入没有进入算法 ​

computeVelocityCommands() 明确忽略 velocity。控制输出可能在相邻周期发生较大变化，不能把“轨迹几何平滑”误解为“速度和加速度时序平滑”。

10.2 原地旋转指令与预测轨迹不是同一条运动 ​

主函数即使选择了 rotateToTarget()，后面的 simulateTrajectory() 仍调用 SmoothControlLaw::calculateNextPose()，模拟的是向运动目标平移的平滑轨迹，不是实际的原地旋转。

因此旋转模式下的碰撞验证与真实输出指令并不严格一致。

10.3 TF 查询失败仍会返回已经算出的速度 ​

Costmap 全局坐标变换查询失败时，源码记录错误并直接返回 cmd_vel，不会抛异常，也不会把速度清零。这个分支跳过了前向碰撞预测。

10.4 预测轨迹超出 Costmap 会按无碰撞处理 ​

inCollision() 的 worldToMap() 失败意味着 Pose 不在 Costmap 内。源码只输出警告并返回 false，也就是按“没有碰撞”继续，而不是保守停车。

10.5 最终切线方向默认路径至少有两个 Pose ​

进入目标附近且 final_rotation=true 时，源码直接访问倒数第二个 Pose 来计算末段切线。PathHandler 只保证变换后路径非空，没有在这里保证至少两个 Pose。

仅含一个 Pose 的路径进入该分支时存在越界风险。

10.6 最小速度不是最终绝对下限 ​

曲率减速和目标减速之后确实执行了 v_linear_min clamp，但角速度触顶后又用 v=omega/kappa 重新投影。因此最终线速度仍可能低于 v_linear_min。

十一、Graceful 的“优雅”到底来自哪里 ​

11.1 它把位置收敛与姿态收敛放进同一曲率 ​

r 决定距离尺度，phi 表示目标姿态相对视线的误差，delta 表示机器人转向相对视线的误差。曲率控制律让慢位置子系统和快转向子系统协同收敛。

11.2 它让速度服从曲率，而不是与曲率争抢 ​

弯道先通过 beta 和 lambda 主动降速；角速度达到上限后，再反推线速度保持原曲率。这种顺序优先保护几何轨迹形状。

11.3 它用滚动目标把复杂路径变成连续局部 Pose 跟踪 ​

运动目标始终从局部路径前方重新选择。机器人接近旧目标时，新的目标继续沿路径向前滚动，控制律不需要一次理解完整全局路径。

11.4 它的适用边界同样清晰 ​

Graceful Controller 适合希望以连续姿态收敛生成平滑弧线的差速移动机器人。它不是动态窗口搜索器，不会比较多条避障绕行轨迹；当前唯一预测轨迹发生碰撞时，它会抛出异常，把失败处理交给包外导航编排。

真正可靠的工程使用，需要同时保证局部路径质量、TF 连续、Costmap 覆盖、GoalChecker 语义、下游速度平滑以及旋转模式的安全边界。
