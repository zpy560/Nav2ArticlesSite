前方放一根“胡萝卜”，机器人就会转弯？拆解 Nav2 RPP 全调用、状态与数据流 ​

Regulated Pure Pursuit 可译为“受约束纯追踪”。它不只是追逐前视点，而是在 Pure Pursuit 几何控制前后加入路径裁剪、速度调节、旋转接管和 footprint 碰撞预测，把一条全局 Path 变成可执行的局部速度。

一、RPP 是 Controller 插件 ​

1.1 ROS 接口由 Controller Server 管理 ​

RPP 不创建独立节点。Controller Server 接收 FollowPath Action，持有 Local Costmap、TF、Odometry、ProgressChecker、GoalChecker 和 cmd_vel Publisher，再通过 setPlan()、computeVelocityCommands() 与 setSpeedLimit() 调用 RPP。

插件输入是本周期 Pose、当前 Twist、GoalChecker，以及内部缓存的 Path、Costmap 和参数；输出是 TwistStamped。Action Feedback、Result、失败容忍和最终零速不属于 RPP。

1.2 最终速度受多层约束 ​

RPP 内部决定曲率、目标速度、近障碍降速和碰撞安全；speed limit 修改期望线速度；Controller Server 处理异常；下游 Velocity Smoother 再限制速度、加减速度、死区和超时。

二、Lifecycle 与持久状态 ​

2.1 configure 创建运行资源 ​

configure 读取参数并由 controller_frequency 派生控制周期，创建 Path、carrot 与碰撞弧三个 Lifecycle Publisher，建立 FootprintCollisionChecker，并保存基础期望速度 base_desired_linear_vel_。

activate() 激活 Publisher 和动态参数回调；deactivate() 关闭运行期入口；cleanup() 释放资源。

2.2 控制周期不是完全无状态 ​

  • global_plan_ 保存尚未走完的路径。
  • desired_linear_vel_ 保存当前 speed limit 后的速度。
  • goal_dist_tol_ 来自当前 GoalChecker。
  • 参数 mutex 与 Costmap mutex 保护共享数据。

三、全局 Path 怎样变成 carrot ​

3.1 路径先裁剪再变换 ​

RPP 把机器人 Pose 变换到 Path frame，在有限前缀中寻找最近点，再按 Local Costmap 最大半边截取前方 Path。截取结果逐点变换到 base frame，机器人身后的旧前缀从 global_plan_ 中永久删除。

3.2 前视距离可以随速度变化 ​

固定模式直接使用 lookahead_dist。速度缩放模式使用：

text
lookahead = clamp(|current_vx| × lookahead_time,
                  min_lookahead_dist,
                  max_lookahead_dist)

允许倒车时，路径向量方向反转的位置被识别为 cusp，前视距离不能跨过该点。启用插值后，carrot 会精确落在路径线段与前视圆的交点上。

四、Pure Pursuit 与三分支控制 ​

4.1 几何核心只有一个公式 ​

carrot 位于 base frame，坐标为 (x, y)，曲率为：

text
curvature = 2y / (x² + y²)
angular_velocity = linear_velocity × curvature

横向偏移越大、前视距离越短，转弯越急。

4.2 控制分支有明确优先级 ​

进入目标 XY 容差后，若启用末端朝向控制，RPP 先原地对齐目标 yaw；否则当 carrot 方位角过大时原地对齐路径；其余情况才执行正常 Pure Pursuit。

三条分支都要经过碰撞预测，安全后才返回统一 TwistStamped。

五、线速度如何被逐层调节 ​

5.1 曲率约束给急弯降速 ​

当曲率半径小于 regulated_linear_scaling_min_radius 时，线速度按半径比例降低，并受 regulated_linear_scaling_min_speed 保护。

5.2 Costmap 代价反解障碍距离 ​

RPP 读取机器人当前位置的 Inflation 代价，反向估计到障碍物的距离。进入 cost_scaling_dist 后继续降低速度。这里的 inflation_cost_scaling_factor 必须与 Costmap InflationLayer 一致，否则反解距离失真。

5.3 接近目标继续减速 ​

局部 Path 的剩余积分长度不足 approach_velocity_scaling_dist 时，RPP 根据终点欧氏距离缩放速度，并保证不低于 min_approach_linear_velocity。

曲率速度与 Costmap 速度取较小值，再应用目标接近缩放、speed limit 和期望速度上限。下游 Velocity Smoother 仍会二次约束，所以 desired_linear_vel 不是最终底盘速度。

六、原地旋转与倒车 ​

6.1 旋转角速度受两类边界 ​

目标角速度由航向误差符号决定。当前 Odometry wz 与 max_angular_accel × dt 形成单周期可达窗口；剩余角度又通过制动公式限制最大角速度，减少过冲。

6.2 倒车由路径几何决定 ​

启用 allow_reversing 后，carrot 的 x 符号决定前进或倒车，cusp 来自相邻路径向量点积而不是 Pose orientation。倒车仍经过曲率、代价、目标和碰撞约束，并与旋转接管互斥。

七、Footprint 怎样预测未来碰撞 ​

7.1 当前姿态先检查 ​

算法先查询当前 footprint。若已经碰撞，立即抛出 PlannerException。

7.2 沿候选 Twist 前推 ​

平移时按 Costmap 分辨率选择步长，纯旋转使用独立角度步长，再用单轮车模型推进未来姿态。预测范围受 max_allowed_time_to_collision_up_to_carrot 和 carrot 距离共同限制。

每个姿态检查完整 footprint，并发布 lookahead_collision_arc。本地实现把 Costmap 外预测点视为无碰撞；允许跟踪未知区时，NO_INFORMATION 也可视为安全，这两个边界必须在实车上额外验证。

八、异常与动态控制面 ​

8.1 异常由 Controller Server 汇总 ​

空 Path、TF 失败和预测碰撞都会向上抛。Controller Server 在 failure_tolerance 内暂时发布零速，持续失败才终止 FollowPath；GoalChecker 决定最终成功。

8.2 动态参数并非全部覆盖 ​

本地回调支持主要速度、前视、旋转和调节开关，但声明过的参数不一定都能动态更新。setSpeedLimit() 也没有取得 RPP 本地 mutex，运行期高频改参应谨慎。

九、调参与排障 ​

9.1 不要孤立调整前视距离 ​

前视过短会放大路径噪声，过长会切弯。应同时观察 transformed plan、carrot、曲率和控制频率。

9.2 Inflation 参数必须配套 ​

机器人贴障碍或异常降速时，同时核对 Local Costmap 代价、RPP cost scaling 参数与 footprint，不能只增大某个权重。

9.3 三条观测链足够定位 ​

  • 路径链：原始 Path、裁剪 Path、TF 与 cusp。
  • 速度链：carrot、曲率、Costmap 代价、speed limit 与 smoother。
  • 安全链：footprint、碰撞弧、未知区和 Costmap 边界。

十、总结与参考 ​

10.1 完整控制数据链 ​

text
FollowPath → 局部 Path → carrot → 曲率／旋转
→ 曲率＋Costmap＋终点速度调节
→ footprint 碰撞预测 → TwistStamped
→ Controller Server → Velocity Smoother → cmd_vel

“追胡萝卜”只是几何核心，真正的工程能力来自它周围的路径状态、速度约束和碰撞状态。
