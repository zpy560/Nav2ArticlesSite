一颗 A* 大脑，三种机器人怎么共用？拆解 nav2_smac_planner 全调用、状态与数据流 ​

nav2_smac_planner 不是单一 Planner，而是一套模板化规划框架：Planner Server 管理 ROS 接口，三个 GlobalPlanner 插件共享 AStarAlgorithm<NodeT>，不同 Node 类型决定状态空间、运动扩展、启发函数和碰撞语义。

一、包边界与插件入口 ​

1.1 ROS 接口全部在 Planner Server ​

本包不创建独立节点。ComputePathToPose 或 ComputePathThroughPoses Action 进入 Planner Server，服务器完成起终点 TF、插件选择、Costmap 管理与 Action Result；Smac 插件只实现进程内 configure()、activate()、createPlan() 等接口。

1.2 三个插件对应三种状态空间 ​

  • SmacPlanner2D：状态为 x、y，使用八连通栅格。
  • SmacPlannerHybrid：状态为 x、y、theta，在线生成 Dubin 或 Reeds-Shepp 邻居。
  • SmacPlannerLattice：状态同样包含离散朝向，但邻居来自 JSON 运动基元。

二、Lifecycle 决定资源是否可用 ​

2.1 configure 创建算法对象 ​

Planner Server 在 configure 阶段通过 pluginlib 创建插件，并传入父 Lifecycle Node、TF Buffer 和 Global Costmap。插件读取参数，创建 A*、碰撞检查器、可选 CostmapDownsampler、Smoother 与调试 Publisher。

2.2 active 状态才开放运行入口 ​

activate() 激活 Publisher 和动态参数回调；deactivate() 关闭运行期入口；cleanup() 释放搜索、平滑和地图资源。插件不是 Lifecycle Node，但资源状态跟随 Planner Server。

三、一次 createPlan 怎样运行 ​

3.1 输入被离散成搜索状态 ​

插件锁定自身状态和 Costmap。若启用降采样，先生成低分辨率 Costmap；随后把世界坐标中的起点、终点转换成栅格索引和可选离散朝向，并检查边界与碰撞。

起终点落在同一离散状态时可直接返回；否则进入共享 A*。

3.2 AStarAlgorithm 管理公共搜索循环 ​

Open Queue 保存待展开节点，Visited 状态防止重复搜索，getTraversalCost() 计算移动代价，启发函数估计到目标的剩余成本。松弛成功后更新 accumulated_cost 与 parent，直到精确到达、容差内找到最佳近似节点、取消或耗尽迭代。

NodeT 决定邻居怎样产生、状态怎样索引和 Costmap 代价如何进入边成本，因此三套 Planner 能共享循环而保持不同运动学。

四、三种 Planner 真正差在哪里 ​

4.1 SmacPlanner2D 面向二维通行性 ​

它在八邻域栅格中移动，启发函数使用二维距离，Costmap 代价通过 cost_travel_multiplier 进入移动成本。它不维护车辆朝向和最小转弯半径，适合圆形、全向或允许控制器后续修正姿态的机器人。

4.2 Hybrid-A* 把运动学写进搜索 ​

Hybrid 状态包含离散 heading，邻居来自运动模型，碰撞检查覆盖完整 SE2 footprint。障碍启发与运动学启发共同工作，解析扩展会尝试用连续曲线直连目标。使用 Reeds-Shepp 时可以倒车。

4.3 State Lattice 用运动基元定义动作 ​

Lattice 从 JSON metadata 读取分辨率、朝向数量和 motion primitives。每个基元包含完整局部轨迹，能表达特定底盘可执行的转向、前进或倒车动作，但基元必须与机器人模型和 Costmap 分辨率匹配。

五、搜索之外还有五个关键组件 ​

5.1 CostmapDownsampler ​

降低搜索网格分辨率以换取速度，但可能损失窄门和细障碍信息。

5.2 GridCollisionChecker ​

统一检查栅格状态或 SE2 footprint 是否越界、未知或碰撞。机器人几何配置错误会让三种搜索同时失真。

5.3 障碍启发缓存 ​

Hybrid 与 Lattice 可缓存从目标传播的障碍启发，减少重复规划开销；地图或目标变化时必须正确失效。

5.4 AnalyticExpansion ​

非完整约束搜索在接近目标时尝试连续曲线直达，成功可减少离散搜索尾部扩展。

5.5 Smoother ​

搜索完成后在剩余时间内优化路径。平滑失败不必然等于规划失败，原始可行 Path 仍可能返回。

六、路径如何返回 Action ​

6.1 parent 链回溯并还原坐标 ​

A* 从终态沿 parent 回到起点，插件把离散状态还原为世界坐标 Pose。2D 根据路径方向补充 yaw；Hybrid 与 Lattice 保留搜索状态中的朝向，Lattice 还会清理重复 Pose。

原始结果可发布到 unsmoothed_plan，降采样地图也可单独观察；平滑后的 Path 作为函数返回值交还 Planner Server。

6.2 结果不只有成功和失败 ​

  • 起终点同状态：直接成功。
  • 精确到达：回溯目标节点。
  • 容差成功：回溯搜索到的最佳近似节点。
  • 无解或超时：返回空 Path 或抛规划异常。
  • 输入越界、碰撞或 TF 错误：由 Planner Server 转为 Action 失败。

七、动态参数与跨周期状态 ​

7.1 参数变化可能重建对象 ​

搜索模型、角度量化、降采样和 Smoother 相关参数不是简单改一个数，部分变化会重建 A*、碰撞检查器或降采样资源。动态回调只在 active 状态存在，并与规划调用互斥。

7.2 可复用状态用于提速 ​

插件会复用启发缓存、搜索节点存储、Smoother 和 CostmapDownsampler。缓存能降低重复规划时间，也意味着地图尺寸、分辨率、目标或运动模型变化时必须正确刷新。

八、选择与排障 ​

8.1 选择依据是机器人可执行性 ​

只需要二维可通行路径时选择 Smac2D；需要朝向、最小转弯半径和可选倒车时选择 Hybrid；需要用预生成动作精确约束特殊底盘时选择 Lattice。路径看起来更圆滑不是唯一标准，还要验证控制器能否跟踪和真实 footprint 是否安全。

8.2 按边界定位问题 ​

  • 收不到请求：检查 Planner Server 与 Action。
  • 起终点 frame 错：检查服务器侧 TF。
  • 三插件都失败：检查 Global Costmap、footprint 与输入合法性。
  • 只有某插件失败：检查状态空间、运动模型、基元或专属参数。
  • Path 已生成但执行失败：进入 Controller Server 与 Local Costmap，不再归因于 Smac。

text
