机器人还没撞上，速度为何先被“截胡”？逐函数拆解 Nav2 Collision Monitor 的 74 个入口 ​

关键词：碰撞监视器、碰撞监控、Collision Monitor

导航控制器给出了一条看似合理的速度，底盘却没有照单全收。机器人靠近障碍物时，它可能保持原速、按比例减速，或者直接归零。完成这次“截胡”的不是全局规划器，也不是局部控制器，而是串在速度链路末端的 nav2_collision_monitor。

这个包不重新规划路径，也不维护 Costmap。它缓存 LaserScan、PointCloud2 或 Range 的最新数据，在每次输入速度到达时把障碍观测统一转换到机器人坐标系，再用 Polygon 或 Circle 安全区域判断是否需要 STOP、SLOWDOWN 或 APPROACH，最后发布更保守的速度。

本文以本地 navigation2、包版本 1.1.20 为事实基线。生产范围包括 9 个头文件、9 个 C++ 实现文件和 1 个 Launch 文件，共 74 个具名函数、方法或入口。组件注册宏不是函数，不纳入计数；测试代码只用于核对边界，也不计入生产入口。

一、先把结论说清楚 ​

1.1 它是速度安全过滤器，不是碰撞规划器 ​

输入通常是 cmd_vel_raw，输出通常是 cmd_vel。包内没有 Global Path 搜索、Local Trajectory 打分或恢复行为。它只在控制命令即将下发时，根据最新障碍点和安全区域对速度进行放行、缩放或清零。

因此它更像一道实时安全门。上游控制算法仍负责“应该怎么走”，Collision Monitor 负责“这条速度现在是否还能安全执行”。

1.2 传感器回调只缓存，速度回调才计算 ​

三类传感器的 dataCallback() 都只把最新消息指针写入成员。它们不会在消息到达时扫描 Polygon，也不会主动发布速度。完整计算由 cmdVelInCallback() 驱动：每来一条输入速度，节点读取各传感器缓存、执行坐标变换、统计区域内点数、仲裁动作并输出一次速度。

这意味着处理频率由输入速度频率决定，而不是由雷达频率决定。没有新的输入速度，就不会因为新障碍消息单独触发一次制动输出。

1.3 三种安全动作不是简单按配置顺序覆盖 ​

STOP 一旦成立就把速度归零，并终止后续区域遍历。SLOWDOWN 与 APPROACH 会各自产生候选速度，只有候选的 x²+y²+tw² 更小时才替换当前结果。配置顺序影响“谁先被检查”，但非 STOP 动作最终仍要经过更小速度启发式比较。

这个平方和把米每秒与弧度每秒直接相加，只是源码中的安全候选排序规则，不是物理能量，也不是严格定义的制动距离。

1.4 当前项目并没有把它接进主 Bringup ​

本包自带 Launch 和示例 YAML，但当前仓库的主 Bringup、三模式规控入口与测试 Bringup 都没有启动 collision_monitor。仓库外层的 navigation2 元包只声明了运行依赖。本文描述的是本包当前源码能力，不代表项目运行时已经拥有这道速度安全门。

二、包边界与完整速度链 ​

2.1 上游与下游边界 ​

上游可以是 Controller Server、遥控节点或其他速度生成器。它们向输入 Topic 发布 geometry_msgs/msg/Twist。Collision Monitor 订阅原始速度，将传感器观测转换成 base_frame_id 下的二维 Point，再用安全区域生成 Action，最终通过 Lifecycle Publisher 输出另一个 Twist。

下游通常是 Velocity Smoother 或底盘驱动。源码没有强制某个具体下游，也不会检查是否存在订阅者；Topic 名完全由参数决定。

2.2 ROS 与包外依赖边界 ​

  • ROS 2 提供 Lifecycle、Subscription、LifecyclePublisher、参数回调、Executor 和 Component 注册。
  • nav2_util 提供 LifecycleNode、参数声明、Twist 有限值校验以及两个 TF 查询重载。
  • TF2 完成跨坐标系、可选跨时间点的传感器点变换。
  • nav2_costmap_2d::FootprintSubscriber 为 APPROACH Polygon 提供动态机器人 Footprint。
  • nav2_common::RewrittenYaml 在 Launch 阶段生成带 namespace 和 use_sim_time 覆盖的临时参数。
  • nav2_lifecycle_manager 在示例 Launch 中自动配置并激活节点。

2.3 包内对象关系 ​

CollisionMonitor 是总调度节点。Polygon 与 Circle 表示安全区域，Source 是传感器抽象基类，Scan、PointCloud 和 Range 负责把不同消息统一成二维障碍点。Velocity、Point、Pose 和 Action 是包内轻量数据结构，transformPoints() 与 projectState() 服务 APPROACH 前向仿真。

2.4 Lifecycle 与处理时机 ​

配置阶段创建 TF、区域、数据源以及速度 Topic；激活阶段才打开 Lifecycle Publisher 和 process_active_。停用阶段先关闭处理开关，再停用发布器。清理阶段释放 Topic、对象数组和 TF。对象已经订阅传感器并不等于节点会处理速度，是否真正执行由 Lifecycle 状态控制。

三、基础类型与运动学的五个入口 ​

3.1 Velocity::operator<() ​

  • 作用：比较两个速度候选的平方和，判断当前对象是否更“小”。
  • 输入：另一个 Velocity，双方都包含 x、y 和角速度 tw。
  • 输出：当前速度的 x²+y²+tw² 更小时返回 true。
  • 数据流／回调：SLOWDOWN 与 APPROACH 生成候选后用它决定是否替换已经选中的动作；它不是 ROS 回调。
  • 包外调用：没有包外调用，只使用基础浮点运算。当前仓库也没有发现包外生产代码直接使用该运算符。

3.2 Velocity::operator*() ​

  • 作用：按同一个比例缩放二维线速度与角速度。
  • 输入：缩放因子 mul。
  • 输出：新的 Velocity{x*mul, y*mul, tw*mul}，原对象不变。
  • 数据流／回调：SLOWDOWN 传入 slowdown_ratio；APPROACH 传入“预测碰撞时间除以目标时间裕量”。
  • 包外调用：没有包外依赖，只在本包动作计算中使用。

3.3 Velocity::isZero() ​

  • 作用：判断三项速度是否都精确等于零。
  • 输入：隐式读取当前速度对象。
  • 输出：三项都为 0.0 时返回 true。
  • 数据流／回调：publishVelocity() 用它识别刚停车、持续停车和恢复运动。
  • 包外调用：没有。这里没有浮点容差，接近零但不等于零的速度仍被视为运动。

3.4 transformPoints() ​

  • 作用：把一组固定障碍点转换到模拟机器人 Pose 对应的局部坐标系。
  • 输入：模拟 Pose{x,y,theta}，以及可原地改写的 std::vector<Point>。
  • 输出：函数无返回值；每个点被写成 Rᵀ × (point-pose) 的坐标。
  • 数据流／回调：APPROACH 每推进一个仿真步，就重新复制原障碍点并调用本函数，让“机器人向前走”转换成“障碍物在新车体坐标中如何移动”。
  • 包外调用：只调用 C++ 数学库的 sin() 与 cos()，没有 TF 查询；这是纯包内二维几何。

3.5 projectState() ​

  • 作用：用一个小时间步推进模拟机器人 Pose，并把车体速度方向随角速度旋转。
  • 输入：时间步 dt、可改写的 Pose 和可改写的 Velocity。
  • 输出：函数无返回值；Pose 完成线性平移和角度累加，速度的 x/y 分量按 tw×dt 旋转。
  • 数据流／回调：Polygon::getCollisionTime() 在循环中反复调用它，形成恒定 Twist 下的离散前向仿真。
  • 包外调用：只使用标准数学函数。它不是 ROS 运动模型，也不读取里程计或加速度限制。

四、进程、Launch 与主节点的十九个入口 ​

4.1 main() ​

  • 作用：提供独立进程入口。
  • 输入：进程参数 argc 与 argv。
  • 输出：正常退出返回 0。
  • 数据流／回调：初始化 ROS 2，构造 CollisionMonitor，把节点基础接口交给单线程 rclcpp::spin()，退出时关闭 ROS。
  • 包外调用：调用 rclcpp::init()、rclcpp::spin() 和 rclcpp::shutdown()。共享库也可通过 Component 注册加载，因此独立可执行程序不是唯一入口。

4.2 generate_launch_description() ​

  • 作用：构造本包示例 LaunchDescription。
  • 输入：Launch 命令行中的 namespace、use_sim_time 与 params_file。
  • 输出：包含三个参数声明、Lifecycle Manager 和 Collision Monitor 节点的 LaunchDescription。
  • 数据流／回调：用 RewrittenYaml 把 namespace 作为根键并覆盖 use_sim_time，再由 ParameterFile 把临时配置交给节点。
  • 包外调用：依赖 ament_index_python、ROS 2 Launch、nav2_common 和 nav2_lifecycle_manager。默认 autostart=True，因此 Lifecycle Manager 会主动配置和激活节点。

4.3 CollisionMonitor::CollisionMonitor() ​

  • 作用：构造名为 collision_monitor 的 LifecycleNode，并设置安全初值。
  • 输入：可选 rclcpp::NodeOptions。
  • 输出：尚未配置的节点对象；process_active_ 为 false，前一动作速度初始化为 {-1,-1,-1}，停车时间为零，发布零速超时初值为一秒。
  • 数据流／回调：不会在构造阶段创建 TF、Topic、Polygon 或 Source。
  • 包外调用：基类是 nav2_util::LifecycleNode；对象可能由 main() 创建，也可能由 rclcpp_components 的 Class Loader 创建。

4.4 CollisionMonitor::~CollisionMonitor() ​

  • 作用：在节点销毁时清空 Polygon 和 Source 容器。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：共享指针引用计数归零后，各派生对象析构并释放订阅器、参数回调与可视化资源。
  • 包外调用：由 C++ 对象生命周期触发，不是 Lifecycle 回调；正常 Lifecycle 清理通常已先释放资源。

4.5 CollisionMonitor::on_configure() ​

  • 作用：完成节点从未配置到已配置所需的运行资源创建。
  • 输入：Lifecycle 状态参数，当前实现不读取其内容。
  • 输出：成功返回 SUCCESS；参数、区域或数据源配置失败时返回 FAILURE。
  • 数据流／回调：创建带 ROS Timer 接口的 TF Buffer 和 TransformListener，调用 getParameters()，再创建输入速度 Subscription 和输出速度 LifecyclePublisher。
  • 包外调用：由 Lifecycle 状态机触发；调用 TF2 ROS、nav2_util 参数工具和 ROS 2 Topic API。

4.6 CollisionMonitor::on_activate() ​

  • 作用：打开速度输出、区域可视化和主处理开关。
  • 输入：Lifecycle 状态参数，当前实现不使用。
  • 输出：返回 SUCCESS。
  • 数据流／回调：先激活输出发布器与每个 Polygon 发布器，主动发布一次区域用于启动显示，再把 process_active_ 设为 true，最后创建 Lifecycle Bond。
  • 包外调用：由 Lifecycle Manager 或外部 Lifecycle 客户端触发；Bond 用于管理节点存活状态。

4.7 CollisionMonitor::on_deactivate() ​

  • 作用：停止主处理并关闭 Lifecycle 资源。
  • 输入：Lifecycle 状态参数。
  • 输出：返回 SUCCESS。
  • 数据流／回调：先把 process_active_ 置为 false，重置上一动作，再停用 Polygon 和速度发布器，最后销毁 Bond。
  • 包外调用：由 Lifecycle 状态机触发。它不会主动发布一条最终零速，停用前的底盘安全收口需由系统级速度链保证。

4.8 CollisionMonitor::on_cleanup() ​

  • 作用：释放配置阶段创建的全部主要资源。
  • 输入：Lifecycle 状态参数。
  • 输出：返回 SUCCESS。
  • 数据流／回调：重置输入订阅器、输出发布器、TF Listener 与 Buffer，并清空 Polygon 和 Source 容器。
  • 包外调用：由 Lifecycle 清理转换触发。清空对象会连带销毁其订阅器和参数回调句柄。

4.9 CollisionMonitor::on_shutdown() ​

  • 作用：响应 Lifecycle 关闭状态并记录日志。
  • 输入：Lifecycle 状态参数。
  • 输出：直接返回 SUCCESS。
  • 数据流／回调：没有额外清零速度或显式释放动作。
  • 包外调用：由 Lifecycle 状态机触发；进程资源最终由析构和 ROS 关闭流程回收。

4.10 CollisionMonitor::cmdVelInCallback() ​

  • 作用：接收原始速度并启动一次完整安全计算。
  • 输入：geometry_msgs/msg/Twist 常量共享指针。
  • 输出：没有直接返回值；有效消息最终可能产生一条安全速度。
  • 数据流／回调：先用 validateTwist() 拒绝任何包含 NaN 或 Inf 的六维 Twist；有效时只取 linear.x、linear.y 和 angular.z 构造包内 Velocity，再调用 process()。
  • 包外调用：由 ROS Subscription 触发，有限值校验来自 nav2_util。linear.z、angular.x、angular.y 只参与合法性检查，不参与二维控制。

4.11 CollisionMonitor::publishVelocity() ​

  • 作用：把选中的包内速度转换为 Twist，并限制持续零速的重复发布时间。
  • 输入：最终 Action。
  • 输出：通常发布一条 geometry_msgs/msg/Twist；持续停车超过 stop_pub_timeout_ 时不发布。
  • 数据流／回调：从非零转为零速时记录 stop_stamp_；后续仍有输入速度回调时，在超时内继续发布零速，超时后直接返回。恢复非零速度时正常发布。
  • 包外调用：调用 ROS 2 LifecyclePublisher。源码没有独立停车 Timer，因此“持续发布”仍依赖上游不断送入速度消息。

4.12 CollisionMonitor::getParameters() ​

  • 作用：读取节点级参数，并串联区域和数据源工厂。
  • 输入：两个字符串引用，用于回传输入和输出速度 Topic。
  • 输出：配置全部成功返回 true；任一工厂失败返回 false。
  • 数据流／回调：读取 base／odom 帧、TF 容差、数据超时、跨时刻补偿、零速发布超时，然后依次调用 configurePolygons() 与 configureSources()。
  • 包外调用：参数声明使用 nav2_util::declare_parameter_if_not_declared()；时间类型由 RCLCPP 和 TF2 转换。它不注册节点级动态参数回调，运行期修改这些值不会重建对象。

4.13 CollisionMonitor::configurePolygons() ​

  • 作用：按 polygons 名称数组创建 Polygon 或 Circle。
  • 输入：机器人基坐标系和 TF 容差。
  • 输出：全部对象创建并配置成功返回 true；未知类型、配置失败或异常返回 false。
  • 数据流／回调：逐个读取 <name>.type，根据 "polygon" 或 "circle" 构造对象，放进 polygons_，再调用最后一个对象的 configure()。
  • 包外调用：使用 ROS 参数系统和 C++ 智能指针。支持的类型在源码中写死，不通过 Pluginlib 扩展。

4.14 CollisionMonitor::configureSources() ​

  • 作用：按 observation_sources 创建三类传感器对象。
  • 输入：base 帧、odom 全局帧、TF 容差、数据超时和跨时刻基座位移补偿开关。
  • 输出：全部类型合法且配置未抛异常时返回 true，否则返回 false。
  • 数据流／回调：读取 <name>.type，构造 Scan、PointCloud 或 Range，立即调用其 configure()，再保存为 Source 共享指针。
  • 包外调用：依赖 ROS 参数和三类 Sensor Message。数据源类型同样是硬编码工厂；派生类 configure() 返回 void，失败通过异常传播。

4.15 CollisionMonitor::process() ​

  • 作用：组织一次从原始速度到最终安全速度的完整计算。
  • 输入：已通过有限值校验的 Velocity。
  • 输出：函数无返回值；可能发布速度和 Polygon 可视化。
  • 数据流／回调：记录统一当前时间，未激活时直接返回；遍历 enabled Source，把有效点追加到同一个 collision_points；用输入速度初始化 DO_NOTHING；遍历 enabled Polygon 计算候选，STOP 后提前结束；动作类型变化时打印日志，随后发布速度和区域，最后保存本次动作。
  • 包外调用：由输入速度回调调用。包外 TF、消息解析与 Footprint 读取都隐藏在 Source 和 Polygon 方法中。

4.16 CollisionMonitor::processStopSlowdown() ​

  • 作用：处理 STOP 或 SLOWDOWN 区域。
  • 输入：Polygon、统一障碍点、原始输入速度和可改写的当前 Action。
  • 输出：当前 Polygon 导致 Action 更新时返回 true，否则返回 false。
  • 数据流／回调：只有区域内点数严格大于 max_points 才触发。STOP 把三项速度清零；SLOWDOWN 用原始输入速度乘比例，并在候选平方和更小时替换当前结果。
  • 包外调用：没有包外调用。注意 max_points 表示“允许不触发的最大内点数”，等于阈值仍不触发。

4.17 CollisionMonitor::processApproach() ​

  • 作用：根据预测碰撞时间生成 APPROACH 速度候选。
  • 输入：Polygon、障碍点、原始速度和可改写 Action。
  • 输出：候选被采纳时返回 true。
  • 数据流／回调：先让 Polygon 更新动态 Footprint，再调用 getCollisionTime()；预测值非负时计算 collision_time/time_before_collision，用该比例同时缩放线速度和角速度，平方和更小时才替换结果。
  • 包外调用：动态 Polygon 可能通过 nav2_costmap_2d::FootprintSubscriber 读取包外 Footprint；其余计算都在本包完成。

4.18 CollisionMonitor::printAction() ​

  • 作用：仅在动作类型变化时输出可读日志。
  • 输入：最终 Action，以及可能导致动作的 Polygon。
  • 输出：没有返回值，产生 INFO 日志。
  • 数据流／回调：STOP 和 SLOWDOWN 打印区域名，APPROACH 打印目标时间裕量，DO_NOTHING 打印继续正常运行。process() 保证需要区域名的分支已有有效指针。
  • 包外调用：使用 RCLCPP 日志系统，不发布状态 Topic。测试引用的 nav2_msgs/msg/CollisionMonitorState 并未进入这份生产实现。

4.19 CollisionMonitor::publishPolygons() ​

  • 作用：发布所有 enabled Polygon 的可视化轮廓。
  • 输入：隐式读取 polygons_。
  • 输出：函数无返回值；每个可视化已开启的区域可能发布一条 PolygonStamped。
  • 数据流／回调：启动激活时主动调用一次，之后每次速度处理完成再调用。
  • 包外调用：实际发布由各 Polygon 的 LifecyclePublisher 完成；未启用区域不会发布。

五、Polygon 区域模型的二十个入口 ​

5.1 Polygon::Polygon() ​

  • 作用：构造一个具名 Polygon 基类对象并保存运行环境。
  • 输入：LifecycleNode 弱引用、区域名、TF Buffer、base 帧和 TF 容差。
  • 输出：尚未读取区域参数的对象；动作初始为 DO_NOTHING，减速比例为零，Footprint Subscriber 为空。
  • 数据流／回调：只保存依赖并记录创建日志，不创建发布器或参数回调。
  • 包外调用：由 configurePolygons() 直接构造，也作为 Circle 的基类构造函数被调用。

5.2 Polygon::~Polygon() ​

  • 作用：释放 Polygon 持有的动态资源。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：清空顶点数组并重置动态参数回调句柄；成员智能指针随后自动释放 Footprint Subscriber 和可视化发布器。
  • 包外调用：由共享指针生命周期触发。

5.3 Polygon::configure() ​

  • 作用：读取区域参数，按需建立动态 Footprint 和可视化发布器，再注册参数回调。
  • 输入：隐式使用构造时保存的节点、区域名、TF 与帧信息。
  • 输出：配置成功返回 true，参数不合法返回 false；节点弱引用失效时抛异常。
  • 数据流／回调：先调用虚函数 getParameters()；存在 footprint_topic 时创建 FootprintSubscriber；开启可视化时调用虚函数 getPolygon() 生成轮廓并创建 PolygonStamped LifecyclePublisher。
  • 包外调用：依赖 nav2_costmap_2d、ROS 参数、ROS Lifecycle Publisher。虚函数分派让 Circle 使用自己的半径参数和轮廓生成逻辑。

5.4 Polygon::activate() ​

  • 作用：激活区域可视化发布器。
  • 输入：隐式读取 visualize_。
  • 输出：没有返回值。
  • 数据流／回调：只有开启可视化时才调用 polygon_pub_->on_activate()。
  • 包外调用：由 CollisionMonitor::on_activate() 遍历调用。

5.5 Polygon::deactivate() ​

  • 作用：停用区域可视化发布器。
  • 输入：隐式读取 visualize_。
  • 输出：没有返回值。
  • 数据流／回调：未开启可视化时什么也不做。
  • 包外调用：由 CollisionMonitor::on_deactivate() 调用。

5.6 Polygon::getName() ​

  • 作用：返回区域配置名。
  • 输入：没有显式输入。
  • 输出：polygon_name_ 的字符串副本。
  • 数据流／回调：动作变化日志用它指出哪个区域触发 STOP 或 SLOWDOWN。
  • 包外调用：没有外部库调用。

5.7 Polygon::getActionType() ​

  • 作用：读取区域对应的安全动作类型。
  • 输入：没有显式输入。
  • 输出：DO_NOTHING、STOP、SLOWDOWN 或 APPROACH 枚举值。
  • 数据流／回调：主处理循环据此选择静态内点计数还是前向碰撞仿真。
  • 包外调用：没有。

5.8 Polygon::getEnabled() ​

  • 作用：读取区域当前是否启用。
  • 输入：没有显式输入。
  • 输出：布尔值。
  • 数据流／回调：主处理和可视化发布都先检查它；值可由 Polygon 的动态参数回调在运行期更新。
  • 包外调用：没有。

5.9 Polygon::getMaxPoints() ​

  • 作用：返回区域内允许的障碍点阈值。
  • 输入：没有显式输入。
  • 输出：整数 max_points_。
  • 数据流／回调：STOP／SLOWDOWN 使用“内点数严格大于阈值”，APPROACH 的初始静态检查却使用“大于等于阈值”，后续仿真又恢复为“严格大于”。
  • 包外调用：没有。

5.10 Polygon::getSlowdownRatio() ​

  • 作用：读取 SLOWDOWN 的速度缩放比例。
  • 输入：没有显式输入。
  • 输出：双精度比例值。
  • 数据流／回调：processStopSlowdown() 用它同时缩放 x、y 与 tw，日志也用它显示百分比。
  • 包外调用：没有。源码没有把该值限制在零到一之间。

5.11 Polygon::getTimeBeforeCollision() ​

  • 作用：读取 APPROACH 希望保持的碰撞前时间裕量。
  • 输入：没有显式输入。
  • 输出：秒数。
  • 数据流／回调：既限定前向仿真时间窗，也作为速度缩放比例的分母。
  • 包外调用：没有。源码没有显式拒绝零或负值，配置错误可能导致除零或异常比例。

5.12 Polygon::getPolygon() ​

  • 作用：复制 Polygon 的真实顶点。
  • 输入：输出数组引用。
  • 输出：函数无返回值；调用者数组被覆盖为 poly_。
  • 数据流／回调：配置可视化时用于生成 geometry_msgs/msg/Polygon。Circle 覆盖此虚函数，用 16 个采样点近似圆形。
  • 包外调用：没有。

5.13 Polygon::updatePolygon() ​

  • 作用：把最新动态机器人 Footprint 写入碰撞判定和可视化数组。
  • 输入：没有显式输入。
  • 输出：没有返回值；可能改写 poly_ 与 polygon_.points。
  • 数据流／回调：只有存在 footprint_sub_ 时才调用 getFootprintInRobotFrame()，随后按返回长度调整两个数组并逐点复制。
  • 包外调用：调用 nav2_costmap_2d::FootprintSubscriber。当前代码不检查该函数的布尔返回值，获取失败时最终采用其返回数组状态。

5.14 Polygon::getPointsInside() ​

  • 作用：统计输入障碍点中有多少位于 Polygon 内部。
  • 输入：只读二维点数组。
  • 输出：内部点数量。
  • 数据流／回调：逐点调用 isPointInside()，结果被 STOP、SLOWDOWN 和 APPROACH 使用。
  • 包外调用：没有，复杂度约为障碍点数乘以 Polygon 顶点数。

5.15 Polygon::getCollisionTime() ​

  • 作用：在 APPROACH 时间窗内离散模拟机器人运动，寻找最早碰撞。
  • 输入：固定障碍点集合和待执行速度。
  • 输出：静态已碰撞返回 0.0，预测到碰撞返回非负时间，时间窗内无碰撞返回 -1.0。
  • 数据流／回调：从原点 Pose 开始，复制速度和障碍点；先做静态检查，再反复调用 projectState() 推进机器人、调用 transformPoints() 转换障碍点并统计内点。
  • 包外调用：没有，完全是本包二维仿真。循环先推进一个 simulation_time_step，命中后却返回推进前的循环变量，因此报告时间比实际已投影时刻少一个步长。

5.16 Polygon::publish() ​

  • 作用：发布当前区域轮廓。
  • 输入：没有显式输入。
  • 输出：开启可视化时发布 geometry_msgs/msg/PolygonStamped；否则直接返回。
  • 数据流／回调：锁定父节点，使用当前时间和 base_frame_id_ 填 Header，把缓存的 polygon_ 放入消息后移动发布。
  • 包外调用：依赖 ROS 2 LifecyclePublisher。节点弱引用失效时抛异常。

5.17 Polygon::getCommonParameters() ​

  • 作用：读取 Polygon 与 Circle 共用的动作、阈值和显示参数。
  • 输入：字符串引用，用于回传可视化 Topic。
  • 输出：全部参数合法返回 true，否则返回 false。
  • 数据流／回调：把 "stop"、"slowdown"、"approach" 映射为枚举；读取 enabled、max_points；按动作类型读取 slowdown_ratio 或预测时间参数；最后读取 visualize 和发布 Topic。
  • 包外调用：使用 ROS 参数系统和 nav2_util 参数声明工具。除动作字符串外，数值范围没有集中校验。

5.18 Polygon::getParameters() ​

  • 作用：读取普通 Polygon 的专属几何参数。
  • 输入：可视化 Topic 和 Footprint Topic 两个输出字符串引用。
  • 输出：成功返回 true，点数组格式错误或异常返回 false。
  • 数据流／回调：先读取公共参数。APPROACH Polygon 不读静态顶点，而是返回 Footprint Topic；其他动作清空 Footprint Topic，再把扁平的 [x,y,...] 数组还原为 Point 顶点。
  • 包外调用：使用 ROS 参数系统。源码要求数组长度大于六且为偶数，因此普通 Polygon 至少需要四个顶点，不接受三角形。

5.19 Polygon::dynamicParametersCallback() ​

  • 作用：处理运行期参数更新。
  • 输入：一次参数提交中的参数数组。
  • 输出：始终返回 successful=true。
  • 数据流／回调：只识别本区域的布尔参数 <polygon_name>.enabled，并立即更新 enabled_；其他参数即使类型和名称合法也被忽略。
  • 包外调用：由 ROS 2 参数系统在设置参数时调用。动作类型、顶点、半径、阈值和比例都不能通过这个回调热更新。

5.20 Polygon::isPointInside() ​

  • 作用：用射线交点奇偶规则判断一个点是否位于任意 Polygon 内。
  • 输入：一个二维 Point。
  • 输出：X 正方向射线与边界相交奇数次时返回 true。
  • 数据流／回调：遍历相邻顶点，筛选跨过目标点 Y 坐标的边，计算交点 X，并在交点位于目标点右侧时翻转结果。
  • 包外调用：没有。边界点的归属由不对称的等号和严格比较共同决定，不能简单理解为“所有边界都算内部”或“所有边界都算外部”。

六、Circle 快速区域模型的五个入口 ​

6.1 Circle::Circle() ​

  • 作用：在 Polygon 基类之上构造圆形区域。
  • 输入：节点弱引用、区域名、TF Buffer、base 帧与 TF 容差。
  • 输出：尚未读取半径的 Circle 对象。
  • 数据流／回调：先执行 Polygon 构造，再记录 Circle 创建日志。
  • 包外调用：由 configurePolygons() 在 type="circle" 时创建。

6.2 Circle::~Circle() ​

  • 作用：记录 Circle 销毁，随后由基类析构完成公共资源清理。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：没有额外数组或订阅器需要手工释放。
  • 包外调用：由 C++ 多态析构链触发。

6.3 Circle::getPolygon() ​

  • 作用：为可视化生成圆的多边形近似。
  • 输入：输出点数组引用。
  • 输出：数组先清空，再写入约 16 个均匀角度采样点。
  • 数据流／回调：只影响可视化轮廓，不参与 Circle 的实际碰撞判定。
  • 包外调用：使用标准 sin()、cos() 和圆周率常量。

6.4 Circle::getPointsInside() ​

  • 作用：用半径平方快速统计圆内障碍点。
  • 输入：只读二维点数组。
  • 输出：满足 x²+y²<radius² 的点数。
  • 数据流／回调：替代 Polygon 的逐边射线判定，被区域动作和前向仿真直接调用。
  • 包外调用：没有。严格小于号意味着恰好落在圆周上的点不计入内部。

6.5 Circle::getParameters() ​

  • 作用：读取 Circle 公共参数和半径。
  • 输入：可视化 Topic 与 Footprint Topic 输出引用。
  • 输出：成功返回 true；参数异常返回 false。
  • 数据流／回调：读取公共动作参数后明确清空 Footprint Topic，再读取必填 radius 并缓存 radius_squared_。
  • 包外调用：使用 ROS 参数系统。Circle 即使配置为 APPROACH 也使用静态半径，不订阅动态 Footprint；负半径会因平方变成相同几何，源码没有拒绝。

七、Source 传感器抽象层的八个入口 ​

7.1 Source::Source() ​

  • 作用：保存所有传感器源共用的节点、TF、帧、时限和补偿策略。
  • 输入：节点弱引用、源名、TF Buffer、base 帧、全局帧、TF 容差、数据超时与 base_shift_correction。
  • 输出：尚未读取 Topic、尚未注册参数回调的抽象基类部分。
  • 数据流／回调：不创建订阅器，具体消息类型由派生类负责。
  • 包外调用：由 Scan、PointCloud、Range 构造函数调用。

7.2 Source::~Source() ​

  • 作用：提供虚析构边界，保证通过 Source 指针删除派生对象时走完整析构链。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：函数体为空，成员智能指针自动释放。
  • 包外调用：由 C++ 多态对象生命周期触发。

7.3 Source::getData() ​

  • 作用：定义“把最新传感器消息追加成 base 帧二维点”的纯虚接口。
  • 输入：本次处理统一当前时间，以及可追加的 std::vector<Point>。
  • 输出：没有返回值；派生类把有效点追加到同一数组。
  • 数据流／回调：CollisionMonitor::process() 只面向这个抽象接口，不关心源消息类型。
  • 包外调用：基类没有实现；实际执行落到 Scan、PointCloud 或 Range。把纯虚接口纳入入口计数，是因为它定义了主节点与全部传感器插件之间的数据契约。

7.4 Source::getEnabled() ​

  • 作用：返回当前数据源是否启用。
  • 输入：没有显式输入。
  • 输出：布尔值。
  • 数据流／回调：主节点在调用 getData() 前检查；值可由动态参数回调更新。
  • 包外调用：没有。

7.5 Source::configure() ​

  • 作用：为数据源注册运行期参数回调。
  • 输入：隐式使用父节点弱引用。
  • 输出：固定返回 true。
  • 数据流／回调：把 Source::dynamicParametersCallback() 绑定到父节点。派生类在创建传感器 Subscription 前调用它。
  • 包外调用：调用 ROS 2 参数回调 API。当前实现没有检查弱引用锁定结果再解引用，但正常配置链保证父节点仍存在。

7.6 Source::getCommonParameters() ​

  • 作用：读取全部传感器源共有的 Topic 和启用开关。
  • 输入：字符串引用，用于回传订阅 Topic。
  • 输出：没有返回值；写入 source_topic 和成员 enabled_。
  • 数据流／回调：Topic 默认值为 "scan"，enabled 默认 true；派生类配置时调用。
  • 包外调用：使用 ROS 参数与 nav2_util 参数声明工具。节点弱引用失效时抛异常。

7.7 Source::sourceValid() ​

  • 作用：按时间戳过滤过旧传感器缓存。
  • 输入：消息时间 source_time 和本次速度处理时间 curr_time。
  • 输出：两者差值大于 source_timeout_ 时返回 false，否则返回 true。
  • 数据流／回调：三类 getData() 都在 TF 查询前调用；失效时记录 WARN 并跳过该源。
  • 包外调用：使用 RCLCPP Time／Duration 和日志系统。未来时间戳产生负差值，不会被“过旧”条件拒绝。

7.8 Source::dynamicParametersCallback() ​

  • 作用：处理数据源运行期启停。
  • 输入：参数数组。
  • 输出：始终返回成功。
  • 数据流／回调：只识别 <source_name>.enabled 布尔参数并更新成员，Topic、高度、角度和超时都不会热更新。
  • 包外调用：由 ROS 参数系统触发。每个 Source 和每个 Polygon 都在同一节点注册自己的回调，单次参数提交会依次经过多个回调。

八、LaserScan 数据源的五个入口 ​

8.1 Scan::Scan() ​

  • 作用：构造 LaserScan 数据源。
  • 输入：Source 的全部共用构造参数。
  • 输出：data_ 为空的 Scan 对象。
  • 数据流／回调：调用 Source 构造并记录创建日志。
  • 包外调用：由 configureSources() 在类型为 "scan" 时创建。

8.2 Scan::~Scan() ​

  • 作用：释放 LaserScan Subscription。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：记录销毁日志并重置 data_sub_。
  • 包外调用：由 Source 容器清空或节点析构触发。

8.3 Scan::configure() ​

  • 作用：注册公共参数回调、读取 Topic，并创建 LaserScan Subscription。
  • 输入：隐式使用父节点。
  • 输出：没有返回值；成功后持有订阅器。
  • 数据流／回调：调用 Source::configure() 和 getCommonParameters()，使用 SensorDataQoS 订阅并绑定 dataCallback()。
  • 包外调用：依赖 ROS 2 SensorDataQoS 与 sensor_msgs/msg/LaserScan。

8.4 Scan::getData() ​

  • 作用：把最新激光束转换为 base 帧二维障碍点。
  • 输入：当前节点时间和共享输出点数组。
  • 输出：没有返回值；有效量测逐点追加到数组。
  • 数据流／回调：无缓存或数据过旧时返回；根据 base_shift_correction 选择跨时刻或普通 TF 查询；从 angle_min 开始遍历 ranges，保留处于 [range_min,range_max] 的束，先转笛卡尔坐标，再乘 TF。
  • 包外调用：调用 nav2_util::getTransform()、TF2 向量变换和 LaserScan 消息字段。TF 获取失败会跳过整个源，而不是使用未变换点。

8.5 Scan::dataCallback() ​

  • 作用：缓存最新 LaserScan。
  • 输入：LaserScan 常量共享指针。
  • 输出：没有返回值；旧指针被新指针替换。
  • 数据流／回调：由传感器 Subscription 触发，不做范围过滤、TF 或区域判断。
  • 包外调用：只由 ROS 2 Executor 调度。

九、PointCloud2 数据源的六个入口 ​

9.1 PointCloud::PointCloud() ​

  • 作用：构造 PointCloud2 数据源。
  • 输入：Source 的全部共用构造参数。
  • 输出：data_ 为空的对象。
  • 数据流／回调：调用 Source 构造并记录创建日志。
  • 包外调用：由数据源工厂在类型为 "pointcloud" 时创建。

9.2 PointCloud::~PointCloud() ​

  • 作用：释放点云 Subscription。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：重置订阅器并记录销毁日志。
  • 包外调用：由对象生命周期触发。

9.3 PointCloud::configure() ​

  • 作用：读取公共参数和点云高度参数，创建 PointCloud2 Subscription。
  • 输入：隐式使用父节点。
  • 输出：没有返回值。
  • 数据流／回调：注册 Source 参数回调，调用 getParameters()，再使用 SensorDataQoS 绑定 dataCallback()。
  • 包外调用：依赖 ROS 2 与 sensor_msgs/msg/PointCloud2。

9.4 PointCloud::getData() ​

  • 作用：把三维点云投影为经过高度过滤的 base 帧二维障碍点。
  • 输入：当前时间和共享输出点数组。
  • 输出：没有返回值；符合高度范围的点被追加为 {x,y}。
  • 数据流／回调：完成缓存、超时和 TF 检查后，创建 x/y/z 浮点字段迭代器；每个三维点先变换到 base 帧，再按变换后的 Z 是否位于闭区间过滤，最后丢弃 Z。
  • 包外调用：使用 sensor_msgs::PointCloud2ConstIterator<float>、TF2 和 nav2_util::getTransform()。消息缺少预期字段或字段类型不兼容时，迭代器可能抛异常。

9.5 PointCloud::getParameters() ​

  • 作用：读取 Topic、enabled 和点云高度窗口。
  • 输入：Topic 输出字符串引用。
  • 输出：没有返回值；填充 min_height_ 与 max_height_。
  • 数据流／回调：先调用 Source 公共参数读取，再声明读取默认 0.05 m 与 0.5 m 的高度边界。
  • 包外调用：使用 ROS 参数系统。源码没有验证最小高度是否小于最大高度。

9.6 PointCloud::dataCallback() ​

  • 作用：缓存最新 PointCloud2。
  • 输入：PointCloud2 常量共享指针。
  • 输出：没有返回值。
  • 数据流／回调：只替换 data_，全部解析推迟到输入速度到达。
  • 包外调用：由 ROS 2 Executor 调度。

十、Range 数据源的六个入口 ​

10.1 Range::Range() ​

  • 作用：构造红外或超声 Range 数据源。
  • 输入：Source 的全部共用构造参数。
  • 输出：data_ 为空的对象。
  • 数据流／回调：调用 Source 构造并记录创建日志。
  • 包外调用：由数据源工厂在类型为 "range" 时创建。

10.2 Range::~Range() ​

  • 作用：释放 Range Subscription。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：重置订阅器并记录销毁日志。
  • 包外调用：由对象生命周期触发。

10.3 Range::configure() ​

  • 作用：注册参数回调、读取 Range 参数并创建 Subscription。
  • 输入：隐式使用父节点。
  • 输出：没有返回值。
  • 数据流／回调：调用 Source 配置与 getParameters()，使用 SensorDataQoS 绑定回调。
  • 包外调用：依赖 ROS 2 与 sensor_msgs/msg/Range。

10.4 Range::getData() ​

  • 作用：把一个距离值展开为传感器视场圆弧上的一组二维障碍点。
  • 输入：当前时间和共享输出点数组。
  • 输出：没有返回值；有效距离会产生从负半视场到正半视场的一组圆弧边界点。
  • 数据流／回调：完成缓存与超时检查后，拒绝超出 [min_range,max_range] 的量测；取得 TF；按 obstacles_angle_ 扫描视场，并额外保证正半视场端点被加入。
  • 包外调用：使用 Range 消息、TF2 和 nav2_util::getTransform()。它只采样量测圆弧，不填充从传感器原点到圆弧之间的扇形内部。

10.5 Range::getParameters() ​

  • 作用：读取 Source 公共参数和圆弧采样角步长。
  • 输入：Topic 输出字符串引用。
  • 输出：没有返回值；填充 obstacles_angle_。
  • 数据流／回调：默认步长是一度对应的弧度值。
  • 包外调用：使用 ROS 参数系统。源码没有验证步长必须为正；视场为正而步长小于等于零时，采样循环无法向结束条件推进。

10.6 Range::dataCallback() ​

  • 作用：缓存最新 Range 消息。
  • 输入：Range 常量共享指针。
  • 输出：没有返回值。
  • 数据流／回调：只替换消息指针，不立即生成圆弧点。
  • 包外调用：由 ROS 2 Executor 调度。

十一、三种安全动作如何竞争 ​

11.1 STOP 的结果是绝对优先 ​

STOP 区域内点数超过阈值后，processStopSlowdown() 直接把三项速度写成零。主循环进入下一个区域前会检查当前动作类型，发现已经 STOP 就结束遍历。后面即使配置了更宽的 SLOWDOWN 或 APPROACH，也不能把零速重新放大。

11.2 SLOWDOWN 从原始输入速度计算 ​

每个 SLOWDOWN 区域都用本次 cmd_vel_in 乘自己的比例，而不是继续缩放前一个区域已经减速后的结果。多个减速区同时成立时，它们产生相互独立的候选，再由 Velocity::operator<() 选平方和更小的一项。因此 0.3 与 0.5 不会串联成 0.15，而会选更保守的 0.3 候选。

11.3 APPROACH 用预测碰撞时间形成比例 ​

APPROACH 先在 time_before_collision 时间窗内寻找碰撞。若预测在目标裕量结束前碰撞，速度比例为 collision_time/time_before_collision。静态已经碰撞时比例为零；时间越接近目标裕量，比例越接近一。该比例同样作用于线速度与角速度。

11.4 非 STOP 候选只按速度平方和仲裁 ​

SLOWDOWN 与 APPROACH 没有固定枚举优先级。谁生成的 x²+y²+tw² 更小，谁就覆盖当前候选。动作类型日志最终显示胜出的那一项，但这个启发式没有分别比较制动距离、角速度风险或各轴上限。

十二、APPROACH 前向仿真到底算了什么 ​

12.1 障碍物被视为静止 ​

getCollisionTime() 固定输入障碍点，只推进机器人 Pose。障碍物自身速度、跟踪 ID 和未来轨迹都没有进入模型。它适合回答“保持当前 Twist，机器人多久会让当前 Footprint 覆盖这些点”，不适合预测行人或车辆的独立运动。

12.2 Twist 在离散时间步内保持不变 ​

线速度和角速度没有加速度过程。projectState() 让 Pose 按当前车体速度平移，并让线速度方向随角速度旋转。simulation_time_step 越小，离散近似越细，但每次输入速度的计算量也越大。

12.3 动态 Footprint 只服务 Polygon APPROACH ​

普通 APPROACH Polygon 从 FootprintSubscriber 取得当前机器人 Footprint，因此可以跟随 Costmap 发布的动态轮廓。Circle 明确清空 Footprint Topic，APPROACH Circle 仍使用固定半径。STOP 和 SLOWDOWN Polygon 则使用参数中的静态顶点。

12.4 返回时间存在一个步长的偏移 ​

循环变量从零开始，但每轮先推进 simulation_time_step，再检查碰撞；命中时返回的却是推进前的循环变量。因此首次推进后命中会返回零。测试用“允许一个步长误差”的方式覆盖这一行为，调参时不应把返回值理解为连续时间上的精确碰撞时刻。

十三、当前 YAML 与项目实际接入状态 ​

13.1 示例只启用了 PolygonStop ​

示例参数把 polygons 设置为 ["PolygonStop"]。PolygonSlow 与 FootprintApproach 虽然在同一 YAML 中定义，但没有加入活动数组，不会被创建，也不会参与仲裁。只修改其内部 enabled: True 没有作用，必须把名称加入 polygons。

13.2 示例只启用了 scan ​

observation_sources 只有 ["scan"]。PointCloud 参数块同样只是预先写好，没有进入对象工厂；示例完全没有 Range 参数块。启用新源时既要配置具体字段，也要把名称加入 observation_sources。

13.3 默认速度链需要显式接线 ​

示例输入是 cmd_vel_raw，输出是 cmd_vel。如果现有控制器仍直接向 cmd_vel 发布，而底盘也订阅同名 Topic，Collision Monitor 就会被旁路。正确接入需要保证上游只发布原始速度 Topic，下游只消费过滤后的 Topic，并避免多个节点同时拥有最终底盘速度发布权。

13.4 TF 与时钟必须共同成立 ​

默认 base 帧是 base_footprint，全局修正帧是 odom，Launch 默认 use_sim_time=True。开启 base_shift_correction 时，TF 查询需要同时连接“传感器帧在消息时刻”和“base 帧在当前时刻”，并以 odom 作为固定帧。仿真时钟、消息时间戳或 TF 历史不一致时，该数据源会被跳过。

十四、最容易忽略的源码边界 ​

14.1 多源合并后不保留来源身份 ​

Scan、PointCloud 和 Range 都把点追加到同一个 std::vector<Point>。进入区域判断后，点不再携带来源名、时间戳、置信度或高度。max_points 统计的是所有 enabled 源的合计，增加传感器或提高采样密度可能直接改变触发灵敏度。

14.2 时间有效性只拒绝过旧消息 ​

sourceValid() 判断 curr_time-source_time > source_timeout。未来时间戳得到负差值，因此不会被这一条件拒绝。它也不检查不同源之间是否同步，只保证每个源没有超过自己的统一超时。

14.3 参数热更新范围非常小 ​

运行期真正会应用的只有每个 Polygon 和 Source 的 enabled。Topic、帧、超时、Polygon 顶点、Circle 半径、阈值、减速比例、仿真步长和点云高度窗口即使参数服务接受了新值，包内对象也不会重新读取。改变这些配置需要重新走 Lifecycle 配置流程。

14.4 零速度不是独立看门狗输出 ​

stop_pub_timeout 只是限制在持续收到输入速度时重复发布零速的最长时间。节点没有周期 Timer，也不会在传感器回调里主动制动。若上游速度流突然中断，下游是否安全停车要依赖底盘或其他速度平滑器自身的超时机制。

14.5 这是安全辅助层，不是可认证的最后防线 ​

源码不建模障碍速度、制动加速度、执行延迟、轮胎打滑或通信丢包，也没有对多项关键数值参数做完整范围校验。它能显著增强 Nav2 的近场防护，但真实机器人仍需要底盘急停、驱动超时、硬件安全回路和与制动性能匹配的区域尺寸。

十五、读完 74 个入口后应该记住什么 ​

15.1 主链只有一句话 ​

传感器回调缓存最新消息，速度回调读取并转换所有有效点，Polygon／Circle 生成 STOP、SLOWDOWN 或 APPROACH 候选，主节点选出更保守速度并发布。

15.2 真正的性能热点很集中 ​

Scan 的束遍历、PointCloud 的三维点遍历、Polygon 的点乘边判定，以及 APPROACH 的“时间步乘点数乘顶点数”仿真构成主要计算量。传感器密度、区域数量和仿真步长比类的数量更直接影响实时负载。

15.3 真正的接入难点不在编译 ​

把包构建出来并不等于获得安全效果。需要同时保证速度 Topic 串联、Lifecycle 激活、TF 历史、ROS 时钟、传感器超时、区域阈值、下游零速看门狗和单一底盘速度发布者都正确。任何一个边界被旁路，这道“速度安全门”都可能形同虚设。
