A* 不只会“走格子”：Nav2 Smac Planner 如何把转弯半径、倒车与避障写进搜索？ ​

提到 A*，很多人脑中浮现的是一个小圆点在方格地图里上下左右移动。可真实机器人不是质点：汽车不能横移，转弯半径不能无限小；差速机器人可以原地旋转，却也不能让长方形车身穿过窄角。

Nav2 Smac Planner 的关键，不是重新包装一遍 f=g+h，而是把“机器人允许怎样移动”写进搜索节点。开放队列、父指针和松弛循环只保留一套，二维栅格、Hybrid-A* 和 State Lattice 通过不同的 Node 类型，换掉状态空间、运动扩展、碰撞语义、通行代价与启发函数。

本文基于当前本地 navigation2、nav2_smac_planner 1.1.20 源码、测试和现用参数，只拆共享 A*、三类 Node、代价与双启发、解析扩展、运动基元、路径回溯和平滑等核心算法。

一、同一套 A* 装入三种运动世界 ​

1.1 Smac2D 搜索 x 与 y ​

SmacPlanner2D 的状态只有栅格坐标 (x,y)。每个节点向八邻域扩展，不在搜索中保存机器人航向，也不约束最小转弯半径。

它适合只关心二维可通行性的场景。圆形、全向机器人可以直接使用；差速机器人也能使用，但路径折角需要后续平滑器和控制器消化。

1.2 Hybrid-A* 搜索 x、y 与 theta ​

SmacPlannerHybrid 的状态是 (x,y,theta_bin)。同一个栅格位置，只要朝向 bin 不同，就是不同搜索节点。

当前 angle_quantization_bins=72，整圈被离散成七十二个方向，每个 bin 约五度。状态空间从二维平面扩展为离散 SE2，规模也从 W×H 变成 W×H×72。

1.3 State Lattice 同样搜索 SE2 ​

SmacPlannerLattice 也使用 (x,y,heading_bin)，但邻居不是运行时按转弯半径算出来，而是从 JSON 文件加载预生成运动基元。

当前文件描述 5 cm 栅格、0.5 m 最小转弯半径和差速模型。每条基元带有完整中间轨迹，因此它能表达直行、转弯、原地旋转以及文件中定义的其他底盘动作。

1.4 模板只保留不随车型变化的部分 ​

三种插件最终都实例化：

text
AStarAlgorithm<Node2D>
AStarAlgorithm<NodeHybrid>
AStarAlgorithm<NodeLattice>

模板 A* 管理 Graph、Open Queue、累计代价、父指针、终止条件与容差回退。Node 类型回答“邻居是谁、能不能去、走过去多贵、离目标还有多远”。

二、规划输入先离散成搜索状态 ​

2.1 世界坐标落入 Costmap 栅格 ​

三个插件都从 PoseStamped start 与 PoseStamped goal 开始，把世界坐标转换为 Costmap 栅格坐标。

2D 只保存整数 (mx,my)。Hybrid 把 yaw 除以角度 bin 大小并四舍五入。Lattice 则遍历运动基元文件中的 heading angles，选择角距离最小的 bin。

2.2 Hybrid 与 Lattice 保留终点航向 ​

Hybrid 和 Lattice 的目标不是“进入目标所在栅格”就结束，而是要到达目标 (x,y,theta_bin) 状态。车辆进入同一位置却朝向相反时，搜索仍未完成。

Smac2D 不搜索航向。其路径位置生成后，Smoother 根据相邻位置向量估算中间 yaw，最后一个 Pose 再按配置使用目标 yaw 或最终接近方向。

2.3 当前插件级降采样默认关闭 ​

Smac2D 与 Hybrid 支持在规划前把 Costmap 按 downsampling_factor 降采样，以更少网格换取更快搜索。

当前配置为：

text
downsample_costmap = false
downsampling_factor = 1

所以真实搜索仍使用 Global Costmap 原分辨率。窄门和细障碍信息不会在插件入口被主动压缩。

2.4 起终点状态完全相同会直接返回 ​

2D 在起终点落到同一 (x,y) 栅格时返回单 Pose。Hybrid 与 Lattice 还要求 heading bin 相同。

这条快速路径绕过 A*。2D 会根据 use_final_approach_orientation 决定单点 Pose 使用起始还是目标航向；Hybrid 与 Lattice 直接写入目标航向。

三、共享 A* 如何决定扩展顺序 ​

3.1 Graph 按离散状态索引节点 ​

Graph 使用 robin_hood::unordered_node_map<unsigned int, NodeT>。节点只有真正被请求时才构造，不会预先为整张 W×H×theta 空间分配完整对象。

每次规划设置碰撞检查器时，源码会清空 Graph，再根据当前 Costmap 尺寸初始化运动模型。搜索节点状态不会跨规划请求复用。

3.2 Open Queue 按 f 值取最小节点 ​

优先队列元素保存：

text
priority = g(node) + h(node)

g 是从起点累计到当前节点的真实搜索代价，h 是 Node 类型给出的剩余代价估计。比较器让最小 priority 位于队首。

起点以 priority 为零入队。弹出后才标记 visited，之后同一离散状态不再展开。

3.3 同一节点允许重复进入队列 ​

源码没有 decrease-key 操作。若某个未访问节点后来得到更小 g，它会带着新 priority 再次压入队列。

旧条目最终弹出时，可能已经指向同一 Graph 节点的最新数据。节点一旦 visited，队列中剩余重复条目会直接跳过。

3.4 松弛规则仍是标准 A* ​

当前节点为 n，邻居为 m：

text
g_new = g(n) + traversal_cost(n,m)

只有 g_new < g(m) 时，才更新邻居累计代价与 parent=n，再以 g_new+h(m) 入队。

Node 类型改变边成本和邻居生成，但不改变这一核心松弛规则。

3.5 迭代与时间共同限制搜索 ​

当前最大迭代次数都是 1000000。Smac2D 最大规划时间为 2.0 s，Hybrid 与 Lattice 为 3.5 s。

但时间不是每次扩展都检查。_timing_interval=5000，源码只在迭代数为五千倍数时读取时钟。因此超时精度取决于五千次扩展耗时，实际返回可能晚于参数值。

四、Node2D 是带 Costmap 代价的八邻域 A* ​

4.1 八个邻居包含直移和对角移动 ​

邻居偏移为水平、垂直和四个对角方向。源码还比较父子坐标差，阻止一维索引越过地图边界后从一行错误绕到另一行。

直移基础距离为 1，对角基础距离为 sqrt(2)。

4.2 通行代价直接吸收栅格代价 ​

子节点 Costmap 代价先归一化：

text
c_norm = cell_cost / 252

边成本为：

text
straight = 1 × (1 + cost_travel_multiplier × c_norm)
diagonal = sqrt(2) × (1 + cost_travel_multiplier × c_norm)

当前 cost_travel_multiplier=2.0。自由空间接近纯几何距离，靠近 Inflation 高代价区时，同样长度的移动明显更贵。

4.3 启发函数使用欧氏距离 ​

2D 的：

text
h = hypot(goal.x-node.x, goal.y-node.y)

不直接查看障碍。障碍影响被放在 g 的通行代价和节点合法性中。

4.4 碰撞语义是单栅格 ​

Node2D::isNodeValid() 按节点索引读取 Costmap。未知空间在 allow_unknown=true 时可通行，代价达到 INSCRIBED 及以上则判为碰撞。

2D 搜索不按每个方向旋转完整 Footprint。机器人几何主要依赖 Costmap Inflation 已经把障碍膨胀到合适范围。

五、Hybrid-A* 把车辆运动学写成在线原语 ​

5.1 Dubins 当前只生成三种前进动作 ​

当前 motion_model_for_search=DUBIN。每个状态生成：

  • 前进直行。
  • 前进左转。
  • 前进右转。

Reeds-Shepp 才会再增加后退直行、后退左转和后退右转。当前虽然配置了 reverse_penalty=2.1，Dubins 模型不会生成倒车邻居，因此该惩罚没有实际触发对象。

5.2 运动步长同时满足离格与曲率 ​

左／右转原语的角增量必须是 heading bin 大小的整数倍，还要让弦长足以离开当前栅格，并满足最小转弯半径。

源码从：

text
chord >= sqrt(2)
R = minimum_turning_radius / costmap_resolution

推导允许的角增量，再向上对齐到整数个角度 bin。这样邻居不会因为仍落在同一 (x,y,theta) 索引中而形成无效自环。

5.3 连续坐标投影后再离散索引 ​

原语投影保留浮点 x、y，用于路径几何连续性；Graph 索引则把投影坐标转为无符号整数，并附加 heading bin。

不同连续 Pose 可能落入同一离散状态。Graph 只保存当前更优路径对应的 Pose 和 parent，这正是 Hybrid-A* 在连续运动与有限搜索空间之间的折中。

5.4 边成本同时惩罚障碍、转弯与倒车 ​

Hybrid 基础边成本是运动原语长度，再乘以：

text
travel_distance_reward + cost_penalty × c_norm

当前 retrospective_penalty=0.025，所以 travel_distance_reward=0.975。转弯继续乘 non_straight_penalty=1.20；改变转弯原语再叠加 change_penalty=0.0；Reeds-Shepp 倒车才会乘 reverse_penalty。

这些惩罚不改变“能不能走”，只改变搜索更愿意选择哪一种可行动作。

六、State Lattice 把底盘动作写进 JSON ​

6.1 运动基元文件定义可达边 ​

Lattice JSON 保存：

  • 地图分辨率。
  • 最小转弯半径。
  • heading angles。
  • motion model。
  • 每条原语的起终朝向、长度与中间 Pose。

搜索不再假设邻居只能是直行和固定半径左／右转，而是直接查询当前 heading 下可用的原语集合。

6.2 当前差速原语与地图必须匹配 ​

现用文件安装后位于：

text
share/nav2_smac_planner/
sample_primitives/5cm_resolution/
0.5m_turning_radius/diff/output.json

插件会检查 JSON 的 grid_resolution 是否与 Costmap 分辨率一致。不匹配时，预生成的终点位移和栅格索引就失去物理含义，因此不是简单缩放一下参数就能继续使用。

6.3 基元中间点参与碰撞检查 ​

Lattice 不只检查基元终点。源码沿基元中间 Pose 采样，当相邻检查点位移超过约一个栅格对角线时，转换到当前搜索位置并检查完整 Footprint。

子节点的 cell cost 取整条基元检查过程中的最大值。边成本因此会对“中途擦近障碍、终点却很空旷”的动作保持敏感。

6.4 原地旋转有独立惩罚 ​

轨迹长度接近零的基元被识别为原地旋转，成本为：

text
rotation_penalty ×
(1 + cost_penalty × c_norm)

当前 rotation_penalty=5.0。原地转向可行，但搜索会优先寻找不需要频繁自旋的路径。

6.5 当前解析扩展禁止倒车 ​

allow_reverse_expansion=false 让 Lattice 的连续目标连接使用 Dubins 状态空间，不使用 Reeds-Shepp 倒车连接。

这只约束解析扩展。离散搜索是否具有倒车动作，还取决于运动基元文件本身以及 getMotionPrimitives() 返回的正反向集合。

七、碰撞检查把状态空间落回真实车身 ​

7.1 Hybrid 与 Lattice 使用方向化 Footprint ​

GridCollisionChecker 预先为每个角度 bin 旋转一次 Footprint。搜索节点检查碰撞时，直接取对应方向的预计算多边形并平移到当前世界位置。

同一 (x,y) 在不同 heading 下可能一个可行、一个碰撞。这正是 SE2 搜索相对 2D 栅格搜索的重要增量。

7.2 圆形机器人只查中心代价 ​

Costmap 使用机器人半径时，不需要方向化 Footprint。碰撞检查直接读取中心栅格，并假设 Inflation 已经表达圆形机器人安全距离。

长方形或非对称机器人则需要完整 Footprint；Lattice 倒车基元还会把朝向翻转 π，确保非对称车体倒着进入原语时几何正确。

7.3 低代价中心可以跳过多边形计算 ​

非圆形 Footprint 先读取中心格。如果中心代价低于可能内切碰撞阈值，源码直接认为安全；只有进入潜在碰撞代价区才计算完整多边形覆盖。

这项优化依赖 Inflation Layer 足够覆盖机器人最大截面。Inflation 太小或缺失时，中心低代价不能可靠代表整个 Footprint 安全。

7.4 地图外状态应当判碰撞 ​

inCollision(x,y,theta) 先检查坐标范围，地图外返回碰撞。

当前 outsideRange() 使用 value > max，不是 value >= max。因此 x==size_x 或 y==size_y 没被这一层拒绝，随后可能访问边界外栅格。这是本版本需要通过输入边界和测试额外防守的源码细节。

八、Hybrid 与 Lattice 使用两张启发地图 ​

8.1 障碍启发来自二维反向搜索 ​

SE2 搜索每次需要判断“当前位置到目标还要付出多少绕障代价”。源码把 Costmap 再降采样两倍，从目标向外执行二维代价搜索。

这张 obstacle heuristic 不包含朝向，却能看见障碍和 Inflation 代价。它不是一次性铺满整图，而是按主搜索请求的位置动态扩展到所需范围。

8.2 运动学启发来自无障碍最短曲线 ​

Hybrid 在目标附近查表得到 Dubins 或 Reeds-Shepp 无障碍最短距离。查表窗口由 lookup_table_size 控制，当前为 20.0 m。

Lattice 同样建立运动学距离表，并根据 allow_reverse_expansion 选择 Dubins 或 Reeds-Shepp 状态空间。它用于估计满足目标位置和朝向所需的最短曲线长度。

8.3 最终 h 取两者最大值 ​

源码返回：

text
h = max(obstacle_heuristic, motion_heuristic)

障碍启发知道“绕开墙要多远”，却不知道车头方向；运动学启发知道“按转弯半径怎样接近目标姿态”，却看不见墙。取最大值同时保留二者更强的下界。

8.4 当前 Hybrid 缓存障碍启发 ​

SmacHybrid.cache_obstacle_heuristic=true。目标离散状态未变化时，setGoal() 不重置障碍启发表。

这能加速同一目标附近的周期重规划，但缓存判断只比较 goal coordinates，不显式比较 Costmap 内容。动态障碍或清图后仍复用旧启发值时，启发顺序可能滞后；真实碰撞检查仍读取当前 Costmap，不会因为启发缓存直接放行碰撞节点。

8.5 当前 Lattice 每次重置障碍启发 ​

SmacLattice.cache_obstacle_heuristic=false。每次设置目标都会从当前 Costmap 重新初始化二维障碍启发。

计算开销更大，但对地图变化更及时。两种配置反映的是重复规划速度与启发新鲜度之间的选择。

九、解析扩展让搜索在目标附近“收尾” ​

9.1 2D 明确禁用解析扩展 ​

AnalyticExpansion<Node2D> 的特化直接返回空。Smac2D 只能依靠八邻域搜索进入目标或容差范围。

Hybrid 与 Lattice 才会使用 OMPL 的 Dubins／Reeds-Shepp 状态空间，尝试从当前节点生成连续曲线直达目标状态。

9.2 尝试频率随目标距离变化 ​

源码根据：

text
desired_iterations =
max(
  closest_distance / analytic_expansion_ratio,
  ceil(analytic_expansion_ratio)
)

决定间隔。离目标越近，尝试越频繁；同时保留下限，避免每次节点扩展都运行昂贵的连续曲线插值。

当前 analytic_expansion_ratio=3.5。

9.3 连接长度不能超过上限 ​

OMPL 曲线长度超过 analytic_expansion_max_length 时直接放弃。当前上限为 3.0 m。

这避免搜索还很远时，用一条穿越高代价区域的长曲线强行“抄近路”。离散 A* 先承担主要绕障任务，解析扩展只负责接近终点后的运动学收尾。

9.4 连续曲线仍要逐点碰撞检查 ​

解析曲线按约 sqrt(2) 栅格距离插值。每个中间状态被离散到 Graph 索引，写入连续 Pose 后调用 Node 的碰撞检查。

任何中间点碰撞、越界或重复到前一节点，整条解析连接失败，A* 继续正常扩展。

9.5 成功后还会向父链上游尝试优化 ​

找到有效解析连接后，源码最多沿 parent 每次回退五个节点，再尝试从更早位置直连目标，最多检查八轮。

如果更长的连接仍安全，就用它替换原结果，从而减少离散搜索尾部的锯齿。失败时保留上一个有效解析连接。

十、目标容差不是简单扩大 Goal 栅格 ​

10.1 搜索持续记录最小启发节点 ​

每次计算邻居启发时，如果 h 小于历史最佳值，就保存该节点索引。

tolerance=0.5 m 会转换为当前搜索 Costmap 上的栅格尺度。最佳启发小于该阈值时，说明搜索已经进入可接受目标范围。

10.2 进入容差后仍继续细化 ​

进入容差并不会立即返回。源码增加 approach_iterations，最多再扩展 max_on_approach_iterations=1000 次，希望找到精确目标或更好的近似节点。

达到补充迭代上限后，才回溯当前最小启发节点。

10.3 Open Queue 耗尽仍可容差成功 ​

如果搜索空间耗尽，但已记录的最佳节点仍在容差内，A* 也会回溯该节点。

因此结果有两种成功语义：精确到达完整目标状态，或者在容差内返回启发最优的近似状态。

10.4 容差改变目标碰撞校验 ​

当容差接近零时，areInputsValid() 会直接检查目标节点是否碰撞，碰撞则抛异常。

容差大于零时，不要求精确目标本身有效，搜索可以在附近找到替代状态。这不是忽略目标障碍，而是允许输出安全的邻近终点。

十一、父链回溯后还要恢复连续 Path ​

11.1 A* 内部路径方向是 goal 到 start ​

终态沿 parent 回溯，每个 Node 把自身状态追加到 path，直到起点。得到的 CoordinateVector 顺序为目标侧到起点侧。

插件转换为 ROS Path 时从 vector 尾部倒序读取，最终输出方向才是 start 到 goal。

11.2 Hybrid 回溯保留连续 Pose ​

Hybrid Graph 按离散索引管理节点，但节点内部保存浮点投影 Pose。回溯时输出这组连续 x、y，并把 heading bin 恢复为弧度。

因此路径不必严格落在栅格中心，离散状态只用于去重和搜索管理。

11.3 Lattice 会展开基元内部轨迹 ​

Lattice 回溯不只输出每条边终点。带有 MotionPrimitive 的节点会把基元中间 Pose 逆序加入路径。

解析扩展节点没有基元指针，则直接使用节点 Pose。插件转换到世界坐标时还会过滤位置与朝向都近乎相同的重复 Pose。

11.4 Smoother 在剩余预算内工作 ​

搜索耗时从 max_planning_time 中扣除，剩余时间交给内部 Smoother。

Smac2D 始终创建 Smoother。Hybrid 与 Lattice 受 smooth_path=true 控制，并且只有搜索迭代数大于一时才调用。

11.5 平滑公式同时保持原路径和局部连续 ​

每个内部点按：

text
y_i +=
  w_data × (x_i-y_i)
  + w_smooth × (y_(i+1)+y_(i-1)-2y_i)

迭代。w_data=0.2 把结果拉回原路径，w_smooth=0.3 抑制局部折线。

每次更新后只检查新点所在 Costmap 栅格代价，不检查完整 Footprint。发现致命代价、迭代超限或时间耗尽时，恢复到上一轮可用路径并返回失败状态；插件仍保留可行路径，不会仅因平滑失败把规划结果清空。

11.6 换向点与原地旋转会切断平滑段 ​

非完整约束路径先按 cusp 和原地旋转点切段。长度超过十个 Pose 的段才做平滑，边界处再尝试恢复起终姿态约束。

这样 Smoother 不会把前进／倒车切换或原地转向抹成违反车辆运动学的普通圆滑曲线。

十二、现用配置与源码边界 ​

12.1 三种 Smac 都已加载 ​

当前三套主要 Bringup 都加载 Smac2D、SmacHybrid 和 SmacLattice。

nav2_regulated_modules 与 myagv_test_bringup 默认仍选 GridBasedAstar，也就是 NavFn A*；mytb3_bringup 默认选择 SmacHybrid。只有实际选中的 planner ID 才会运行本文算法。

12.2 当前 Hybrid 是前进型汽车模型 ​

现用 DUBIN、最小转弯半径 0.40 m、七十二个角度 bin，允许未知空间，开启障碍启发缓存和路径平滑。

它能生成满足前进曲率约束的路径，但不能靠倒车完成狭窄调头。需要倒车时必须改为 Reeds-Shepp，并重新验证倒车惩罚、控制器跟踪和 Footprint。

12.3 当前 Lattice 是差速运动基元 ​

现用基元为 5 cm 分辨率、0.5 m 转弯半径的 diff 文件，启用原地旋转代价，解析扩展不允许倒车。

这套动作集合适合差速底盘，不应直接拿给 Ackermann 车辆使用。Lattice 的可执行性来自基元文件，而不是插件名本身。

12.4 2D 与 Lattice 忽略 worldToMap 返回值 ​

当前 Hybrid 明确检查起终点 worldToMap() 是否成功，地图外会抛异常。

Smac2D 与 Lattice 调用 worldToMap() 后没有检查返回值，再继续使用输出变量。虽然 Planner Server 通常会先保证目标处于 Global Costmap 范围内，但单独调用插件或边界状态下仍存在未初始化栅格坐标风险。

12.5 搜索全程持有 Costmap mutex ​

三种 createPlan() 都在搜索、回溯、坐标转换和平滑期间持有 Costmap mutex。

这保证搜索看到一致地图，却也意味着复杂 SE2 搜索、百万级迭代上限或耗时平滑会延长 Costmap 写更新等待。max_planning_time 不只影响 Action 响应，也影响地图并发占用。

12.6 真正的核心是可替换的 Node 语义 ​

Smac 的 A* 循环并不神秘：

text
弹出最小 f
→ 检查目标与解析扩展
→ 生成合法邻居
→ 计算边成本并松弛
→ 更新 parent 与 Open Queue
→ 回溯并平滑

真正决定路径形态的是 Node：

  • Node2D 把机器人看成二维通行点。
  • NodeHybrid 把最小转弯半径和可选倒车写进在线运动原语。
  • NodeLattice 把真实底盘动作写进预生成轨迹。

A* 只负责在这些“允许动作”之间寻找低代价组合。Nav2 Smac Planner 最有价值的设计，正是让搜索框架保持稳定，同时让机器人的运动学成为可以替换的算法模块。
