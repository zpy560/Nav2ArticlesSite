先别急着走：Nav2 Rotation Shim 如何在路径跟踪前把方向“扶正”？ ​

一条新路径已经规划出来，机器人却正横着面对它。此时直接把控制权交给 DWB、RPP 或 MPPI，主控制器既要纠正巨大航向误差，又要开始平移，起始轨迹很容易拐出大弧、贴近障碍，甚至根本找不到有效速度。

Nav2 Rotation Shim Controller 的思路很直接：它不再发明一套路径跟踪算法，而是在主控制器前面加一道“方向门”。新路径到来时，先观察路径前方的粗略走向；方向差太大就原地旋转，方向进入安全窗口后立即退出，把同一条 Path 交还给真正的主控制器。

本文基于当前本地 navigation2、nav2_rotation_shim_controller 1.1.20 源码、单元测试和现用参数，只拆路径初始航向采样、旋转接管与退出、角速度生成、原地碰撞预测、目标末端旋转，以及向嵌套主控制器委托的核心算法。

一、它是控制器前面的接管层 ​

1.1 输入与普通 Controller 完全相同 ​

RotationShimController 实现 nav2_core::Controller。Controller Server 每个控制周期仍然传入：

  • 当前机器人 PoseStamped。
  • 当前机器人 Twist。
  • 当前任务使用的 GoalChecker。
  • 之前通过 setPlan() 保存的全局 Path。
  • TF、Local Costmap 和机器人 Footprint。

输出仍是一个 TwistStamped。Rotation Shim 接管时只填写 angular.z，线速度保持零；不需要接管时，输出就是内部主控制器的结果。

1.2 它不负责正常路径跟踪 ​

配置项 primary_controller 指定真正的跟踪器。当前三套主要配置都把它设为：

text
primary_controller = dwb_core::DWBLocalPlanner

Rotation Shim 只解决“新路径起步方向差太大”这一个局部问题。通过退出阈值后，曲率跟踪、轨迹采样、避障打分、速度调节和终点收敛全部由 DWB 继续完成。

1.3 同一个插件标识承载两层参数 ​

内部主控制器使用与 Rotation Shim 相同的插件名完成 configure()。因此当前 YAML 的 RotationShimController 配置组前半部分是 Shim 参数，后半部分直接放置 DWB 参数。

这不是把两套算法混成一套，而是一个插件命名空间中嵌套了两个 Controller 对象。

1.4 当前已加载但不是默认控制器 ​

当前 nav2_regulated_modules、myagv_test_bringup 和 mytb3_bringup 都会加载 Rotation Shim，但默认控制器分别是 DWB、DWB 和 GracefulController。

因此本文解释的是当前可切换使用的算法与参数，不代表现有启动链默认会经过这层 Shim。

二、新 Path 会重新打开方向门 ​

2.1 setPlan 同时喂给两层控制器 ​

收到新 Path 时，setPlan() 完成四件事：

text
path_updated_ = true
current_path_ = path
primary_controller_->setPlan(path)
position_goal_checker_->reset()

current_path_ 供 Shim 计算路径初始方向，原始 Path 同时交给 DWB。等方向对齐后，无需再次复制或转换路径，主控制器可以立即开始工作。

2.2 path_updated_ 是一次路径级触发器 ​

只有 path_updated_=true 时，起步旋转逻辑才会运行。方向已经进入退出窗口后，源码把它置为 false，之后每个周期都直接委托主控制器。

这意味着 Shim 不会在整条路径跟踪期间持续检查局部路径切线。它处理的是“新 Path 的开场”，不是每一个急弯。

2.3 每次重规划都可能重新接管 ​

上游再次调用 setPlan() 时，即使机器人正在正常跟踪，path_updated_ 也会重新置为 true。下一周期会重新采样新 Path 的前向点，并决定是否再次原地旋转。

所以它对全局重规划、控制器恢复后重新下发路径、目标更新都敏感。

2.4 采样或 TF 失败会放弃 Shim ​

找不到有效采样点、TF 变换失败，或者旋转碰撞预测抛出异常时，起步分支捕获异常并清除 path_updated_，然后继续调用主控制器。

这里的语义不是“Shim 失败则整周期停止”，而是“无法安全完成前置修正时，把决定权交还主控制器”。如果主控制器也失败，异常才继续向 Controller Server 传播。

三、路径航向来自前方一个采样点 ​

3.1 搜索从 Path 首 Pose 开始 ​

getSampledPathPt() 要求 Path 至少包含两个 Pose。它把首 Pose 记作起点，然后向后寻找首个满足：

text
hypot(
  pose_i.x - pose_0.x,
  pose_i.y - pose_0.y
) >= forward_sampling_distance

的 Path Pose。

当前 forward_sampling_distance=0.5 m。因此算法不会直接使用紧邻首点的离散 Pose，而是尽量避开路径首端的密集点、量化噪声和极短折线。

3.2 这里测量的是弦长 ​

搜索条件使用采样点到 Path 首点的欧氏距离，不是沿 Path 累计的弧长。

如果起始路径先绕出弯再回到首点附近，累计长度可能已经超过 0.5 m，但欧氏距离仍不足，Shim 会继续向后找。它得到的是“半米尺度上的净前进方向”，不是严格的路径切线。

3.3 采样点被变换到 base frame ​

找到的 Pose 使用 Path 的 frame 和当前时间戳，经 nav2_util::transformPoseInTargetFrame() 变换到机器人 base frame。

在 base frame 中机器人位于原点并朝向 +x。采样点坐标为 (x_s,y_s) 时，待对齐角度就是：

text
e_theta = atan2(y_s, x_s)

e_theta>0 表示路径粗略方向在机器人左侧，e_theta<0 表示在右侧。

3.4 采样不到不强制旋转 ​

如果整条 Path 都没有点达到 forward_sampling_distance，函数抛出异常。外层随后关闭本次路径的 Shim 检查并委托主控制器。

短路径因此不会因为缺少半米采样点而永久卡在前置逻辑中。代价是主控制器必须自己处理短路径的大航向误差。

四、双阈值迟滞阻止控制权抖动 ​

4.1 进入旋转使用大阈值 ​

尚未进入旋转状态时，比较条件为：

text
abs(e_theta) > angular_dist_threshold

当前 angular_dist_threshold=0.785 rad，约为四十五度。误差没有超过该值时，Shim 不接管，直接把 Path 交给 DWB。

4.2 已旋转时使用更小的退出阈值 ​

一旦 in_rotation_=true，下一周期改用：

text
abs(e_theta) > angular_disengage_threshold

当前 angular_disengage_threshold=0.3925 rad，约为二十二点五度。误差降到该范围内，源码才会清除 path_updated_，结束前置旋转。

4.3 中间区间形成迟滞带 ​

误差位于 0.3925～0.785 rad 时，行为取决于历史状态：

  • 从未接管过：继续由 DWB 跟踪。
  • 已经在旋转：继续旋转，直到误差小于退出阈值。

这段迟滞带防止 TF 噪声、里程计抖动或离散 Path 点变化让控制权在 Shim 与 DWB 之间反复切换。

4.4 比较条件都是严格大于 ​

误差恰好等于进入阈值时不会接管，恰好等于退出阈值时也会退出旋转。

这是实现上的边界值语义。调参时不应把阈值当成带滞回容差的近似比较。

五、角速度是目标值与单周期可达窗口的交集 ​

5.1 航向误差只决定旋转方向 ​

目标角速度幅值固定为 rotate_to_heading_angular_vel：

text
w_target =
  sign(e_theta) * rotate_to_heading_angular_vel

当前目标幅值为 0.8 rad/s。误差九十度和误差一百七十度会得到相同的目标角速度，只是需要持续不同时间。

5.2 闭环模式读取实测角速度 ​

closed_loop=true 时，当前角速度取本周期输入的：

text
velocity.angular.z

也就是 Controller Server 提供的 Odom 速度反馈。Shim 的加速度窗口围绕实际旋转速度展开，能够补偿执行器未完全跟随上一条命令的情况。

5.3 开环模式读取上一条命令 ​

closed_loop=false 时，当前角速度取 last_angular_vel_。激活时该变量先放入一个最大浮点数哨兵，首条命令再把它解释为零。

之后每周期都以上一条输出作为当前状态。单元测试在 Odom 故意给出错误角速度时，开环输出仍按 -0.16、-0.32 rad/s 连续递增，证明反馈值没有进入开环窗口。

5.4 加速度限制由控制频率离散化 ​

源码计算：

text
dt = 1 / controller_frequency
w_min = w_current - max_angular_accel * dt
w_max = w_current + max_angular_accel * dt
w_cmd = clamp(w_target, w_min, w_max)

当前 Controller Server 为 20 Hz，dt=0.05 s，max_angular_accel=3.2 rad/s²，所以每周期角速度最多变化：

text
delta_w_max = 3.2 * 0.05 = 0.16 rad/s

从静止开始时，命令会按 0.16、0.32、0.48、0.64、0.8 rad/s 逐步爬升。

5.5 源码没有按剩余角度提前刹停 ​

这里与 RPP 的原地旋转算法不同。Rotation Shim 只有目标角速度和加速度窗口，没有：

text
sqrt(2 * max_angular_accel * abs(e_theta))

这样的制动距离上界。

接近退出阈值时，命令仍可能保持较高角速度，直到下一周期误差进入退出窗口，再突然把控制权交给 DWB。实际制动依赖底盘、下游 Velocity Smoother 和主控制器接手后的命令变化。

5.6 setSpeedLimit 不限制 Shim 自己 ​

setSpeedLimit() 只把速度限制转发给 primary_controller_。它不会缩放 rotate_to_heading_angular_vel 或 max_angular_accel。

因此 Controller Server 对该插件施加 SpeedLimit 时，内部 DWB 会响应，而前置原地旋转仍使用 Shim 自己的固定参数。

六、每条旋转命令先推演 Footprint ​

6.1 推演模型只有 yaw 变化 ​

旋转命令生成后，isCollisionFree() 保持机器人 x、y 不变，只推进：

text
yaw(t) = initial_yaw + w_cmd * t

时间按 control_duration 离散递增，最多检查到 simulate_ahead_time。当前是每 0.05 s 检查一次，最远预测 1.0 s。

6.2 每个预测姿态检查完整 Footprint ​

每个模拟 yaw 都调用 FootprintCollisionChecker::footprintCostAtPose()。虽然机器人中心没有平移，长方形或不对称 Footprint 在旋转时会扫过新的 Costmap 栅格，因此原地旋转仍可能碰撞。

返回代价达到 LETHAL_OBSTACLE 时，函数抛出碰撞异常。

6.3 未知空间在跟踪未知区域时也被拒绝 ​

如果 Footprint 代价为 NO_INFORMATION，并且 Layered Costmap 正在跟踪未知空间，源码同样把它视为潜在碰撞并抛出异常。

这是一种保守策略：未知区域不是“没有障碍证据”，而是“缺少安全证据”。

6.4 推演试图在交还控制权前停止 ​

源码先计算：

text
remaining =
  abs(e_theta) - angular_dist_threshold

然后试图在预计旋转量达到 remaining 时停止模拟，避免继续检查本应由主控制器接管的姿态。

但这里始终使用进入阈值 angular_dist_threshold，没有在 in_rotation_ 状态下切换为更小的 angular_disengage_threshold。实际控制会旋转到退出阈值附近，而碰撞推演可能更早停止。

6.5 正负方向的提前停止判断不对称 ​

当前停止条件是：

text
shortest_angular_distance(
  simulated_yaw,
  initial_yaw
) >= remaining

remaining 是非负标量，但顺时针旋转得到的 shortest angular distance 为负值。于是逆时针分支可能提前停止，顺时针分支通常不会命中这个条件，会继续推演到完整 simulate_ahead_time。

当误差已经小于进入阈值时，remaining 还是负数，逆时针分支甚至可能在初次 Footprint 检查前就退出循环。

这是当前本地源码的实现边界，不是期望中的方向对称安全模型。若把 Shim 用于紧邻障碍的起步旋转，应针对正负角误差分别做场景验证。

七、末端航向旋转是一个可选高优先级分支 ​

7.1 当前配置默认关闭 ​

rotate_to_goal_heading=false，所以现用配置只做新路径初始旋转，目标末端航向继续由内部 DWB 和外部 GoalChecker 处理。

启用后，这个分支位于 computeVelocityCommands() 的最前面，优先级高于新路径初始旋转和主控制器委托。

7.2 先判断目标位置是否到达 ​

Shim 读取 Path 最后一个 Pose，把它变换到当前机器人 Pose 的 frame，再从外部 GoalChecker 获取 XY 容差，并写入内部 PositionGoalChecker。

只有机器人位置进入 XY 容差时，才计算：

text
e_goal =
  shortest_angular_distance(robot_yaw, goal_yaw)

随后复用同一套角速度生成和碰撞预测。

7.3 它没有独立的目标航向完成阈值 ​

位置满足后，源码不再检查一个 Shim 自己的 yaw tolerance。只要内部 PositionGoalChecker 仍判断位置到达，每周期都会调用旋转命令生成。

当 e_goal=0 时，符号表达式仍选择负方向，并给出负目标角速度，经加速度窗口限制后可能不是零。

因此在这份 1.1.20 实现中，开启 rotate_to_goal_heading 需要特别验证零误差和最终停止行为。当前配置保持关闭，避开了这一边界。

八、异常回退不是统一的安全停止 ​

8.1 初始旋转异常会委托主控制器 ​

新路径采样、TF 或碰撞检查失败时，起步分支记录调试日志、清除 path_updated_，随后调用 DWB。

这让系统不会因为 Shim 自己无法工作而永久阻塞，但也意味着“Shim 检测到旋转碰撞”不等于“本周期一定输出零速度”。最终行为取决于 DWB 是否能生成安全命令。

8.2 末端旋转异常也会继续向下 ​

目标末端分支捕获异常后没有立即停止，而是继续检查新路径旋转，最后仍可能委托主控制器。

Rotation Shim 的安全语义是拒绝当前这条原地旋转候选，不是为整个 Controller Server 实现急停。

8.3 主控制器异常仍会向上传播 ​

委托 DWB 后，源码不再捕获其 computeVelocityCommands() 异常。DWB 找不到合法轨迹、Path 无效或 TF 失败时，错误会继续交给 Controller Server 的失败处理链。

8.4 碰撞检测锁住当前 Costmap ​

新路径起步分支先取得 Costmap mutex，再锁住 Shim 自身 mutex，采样、TF、命令生成和 Footprint 推演都在锁内完成。

它保证本次预测看到一致的 Costmap，但 TF 等待或多步 Footprint 查询也会延长 Costmap 被占用的时间。

九、现用参数如何共同塑造行为 ​

9.1 当前核心参数快照 ​

text
primary_controller           = dwb_core::DWBLocalPlanner
angular_dist_threshold       = 0.785 rad
angular_disengage_threshold  = 0.3925 rad
forward_sampling_distance    = 0.5 m
rotate_to_heading_angular_vel= 0.8 rad/s
max_angular_accel            = 3.2 rad/s²
simulate_ahead_time          = 1.0 s
rotate_to_goal_heading       = false
closed_loop                  = true
controller_frequency         = 20 Hz

这组参数表达的是：路径粗略方向偏差超过四十五度才接管，旋转到二十二点五度以内再退出；用半米尺度观察路径方向，以最高 0.8 rad/s 原地旋转，每周期最多改变 0.16 rad/s，并向前检查一秒 Footprint。

9.2 forward_sampling_distance 决定看的是局部噪声还是整体趋势 ​

取值太小，采样点容易受路径首端离散噪声影响，Shim 可能对一个很短的小折线做激烈旋转。

取值太大，起始急弯会被平均成更远的净方向，机器人对最初可行走廊反应不足；短 Path 还可能根本找不到采样点，直接回退 DWB。

9.3 两个角阈值必须保留合理间隔 ​

angular_disengage_threshold 应小于 angular_dist_threshold，才能形成真正的迟滞。

两者太接近，噪声更容易造成边界抖动；退出阈值太小，则原地旋转时间更长，而且当前碰撞推演却仍按进入阈值估算停止点，安全检查和真实接管区间的偏差会扩大。

9.4 角速度与加速度不能脱离底盘能力 ​

rotate_to_heading_angular_vel 决定稳定旋转幅值，max_angular_accel 决定爬升和换向速度。

提高目标角速度却不增加安全前视时间，会让相同一秒内扫过更大的角度；提高加速度又缺少剩余角度制动约束，会增加越过退出窗口的风险。

9.5 closed_loop 依赖可靠 Odom ​

闭环模式能基于真实响应限制下一周期命令，是更符合物理系统的选择。但 Odom 延迟、角速度符号错误或长期为零，会让加速度窗口围绕错误状态展开。

开环不依赖反馈，却默认底盘忠实执行上一条命令。两种模式不是“一个先进、一个落后”，而是使用不同的状态来源。

十、一次控制周期的数据流 ​

10.1 目标位置分支先获得检查机会 ​

启用末端航向旋转时，先读取 Path 末点、完成 TF、同步 XY 容差并判断位置是否到达。命中后生成旋转命令和碰撞预测，安全则立即返回。

10.2 新路径分支计算粗略航向 ​

path_updated_ 为真时，从 Path 首点向前寻找半米采样点，变换到 base frame，计算 atan2(y,x)，再根据 in_rotation_ 选择进入或退出阈值。

10.3 需要接管时只输出角速度 ​

误差超过当前阈值时，目标角速度先经过闭环或开环加速度窗口，再推演 Footprint。安全时返回 linear.x=0、angular.z=w_cmd。

10.4 不需要接管时永久交还本条 Path ​

误差进入退出窗口后，path_updated_ 被清除。当前周期随即调用 DWB；后续周期继续直达 DWB，直到下一次 setPlan()。

10.5 last_angular_vel_ 连接两种输出来源 ​

无论输出来自 Shim 还是 DWB，源码都会保存其 angular.z 到 last_angular_vel_。

开环模式下，下一次 Shim 接管可以从上一条实际下发命令附近继续限加速度，而不是总从零开始。代价是 DWB 的末次角速度也会成为 Shim 的开环初值。

十一、真正值得记住的算法结论 ​

11.1 Shim 解决的是控制器接入条件 ​

它不优化 Path，也不替代 DWB。它把“大航向误差下直接平移跟踪”变成“先原地把方向拉回可处理区间，再正常跟踪”。

11.2 半米采样加双阈值构成核心 ​

前方采样点提供稳定的粗略路径方向，进入／退出双阈值提供状态迟滞。这两部分共同决定是否接管和何时交还控制权。

11.3 角速度控制只有加速度窗口 ​

当前实现没有按剩余角度建立制动上界。控制是否平顺不仅取决于 Shim 参数，也取决于底盘响应、Odom、Velocity Smoother 和 DWB 接手后的命令。

11.4 碰撞推演必须按源码边界理解 ​

它确实检查旋转 Footprint，但提前停止使用进入阈值，且正负旋转的符号判断不对称。紧邻障碍应用不能只看到 simulate_ahead_time=1.0 就认为两侧都得到等价的一秒安全覆盖。

11.5 当前配置关闭末端旋转是重要事实 ​

现用 Rotation Shim 只做起步方向扶正。末端航向由 DWB 与 GoalChecker 处理，也避开了本版本末端分支在零角误差时仍可能生成负向命令的边界。

Rotation Shim 的价值，不是让控制器更聪明，而是让主控制器在更合适的初始条件下开始工作。机器人先把方向扶正，再把复杂问题交给真正擅长路径跟踪的算法，这正是它简单却实用的原因。
