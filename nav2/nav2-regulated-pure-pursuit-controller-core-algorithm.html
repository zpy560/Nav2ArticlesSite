只追一根“胡萝卜”，为何还能过急弯、贴窄道？拆解 Nav2 RPP 核心算法 ​

Pure Pursuit 的经典画面很简单：在路径前方放一个目标点，机器人不断追它。

可如果只按几何追踪，前视点过近会摇摆，急弯容易冲出路径，窄道贴近障碍时仍可能保持高速，接近终点也缺少自然减速。Nav2 的 Regulated Pure Pursuit，简称 RPP，正是在“追胡萝卜”外面加上速度调节、旋转接管、倒车换向和预测碰撞弧，把一个几何控制律变成工程可用的局部控制器。

RPP 不采样数百条轨迹，也不运行迭代优化。每个控制周期只选择一根 carrot、计算一条圆弧，再决定这条弧该以多快的速度执行，以及在执行前是否会碰撞。

本文基于当前本地 navigation2、nav2_regulated_pure_pursuit_controller 1.1.20 源码与现用参数，只拆局部路径、动态前视、Pure Pursuit 曲率、三路速度闸门、原地旋转、倒车 cusp 和 Footprint 碰撞预测等核心算法。

一、RPP 每周期只求一条候选运动弧 ​

1.1 输入不是一张静态几何题 ​

computeVelocityCommands() 每周期获得：

  • 当前机器人 Pose。
  • 当前机器人 Twist。
  • 当前任务使用的 GoalChecker。
  • 之前通过 setPlan() 缓存的全局 Path。
  • Local Costmap、机器人 Footprint 与 TF。

它输出一个 TwistStamped，只有前向线速度 linear.x 和角速度 angular.z。

当前 Twist 并不直接代入 Pure Pursuit 曲率公式，但会影响速度缩放前视距离，也会限制原地旋转分支的单周期角速度变化。

1.2 核心链路由几何、调节和安全组成 ​

RPP 的控制链可以压缩为：

text
全局 Path
→ 裁剪并变换到机器人坐标系
→ 计算前视距离
→ 选择或插值 carrot
→ 计算 Pure Pursuit 曲率
→ 选择旋转或正常跟踪分支
→ 调节线速度
→ 预测 Footprint 碰撞
→ 输出 TwistStamped

几何层回答“方向应该弯多少”，速度层回答“这条弧应该跑多快”，碰撞层回答“这个 Twist 能不能执行”。

1.3 RPP 不会主动生成绕障替代轨迹 ​

carrot 必须来自全局 Path。碰撞预测发现障碍时，RPP 抛出异常，不会把 carrot 横向挪开，也不会在障碍两侧生成候选轨迹。

绕障仍依赖上游规划器重新生成 Path，或者由外部导航编排触发重规划与恢复。RPP 的职责是跟踪、调速和拒绝危险命令，不是局部路径搜索。

1.4 当前配置加载了 RPP，但没有默认选择它 ​

当前 nav2_regulated_modules 一次加载 DWB、RPP、MPPI、GracefulController 和 RotationShimController，但 controller_id 仍为 DWB。

myagv_test_bringup 默认同样是 DWB，mytb3_bringup 默认是 GracefulController。本文分析的是当前已配置的 RPP 算法与参数，不代表现有启动链默认正在使用 RPP。

二、全局 Path 先收缩成机器人附近的局部 Path ​

2.1 最近点搜索被累计路径长度限制 ​

RPP 先把机器人 Pose 变换到全局 Path frame，再调用 first_after_integrated_distance()，只取路径起点向前累计 max_robot_pose_search_dist 的前缀。

当前参数为：

text
max_robot_pose_search_dist = 3.0 m

随后只在这段前缀中寻找与机器人欧氏距离最近的 Pose。

这个边界对环形或自交路径很重要。如果在整条 Path 上找最近点，机器人可能被匹配到空间位置很近、但路径进度已经很远的另一段。

2.2 局部变换范围由 Costmap 最大半边决定 ​

最近点之后的 Path 不会全部变换。源码计算：

text
max_costmap_extent =
  max(costmap_width_m, costmap_height_m) / 2

当某个 Path Pose 到机器人的欧氏距离超过该值，就停止局部截取。

这是一条以机器人为圆心的距离边界，半径取 Costmap 最大半边，不是矩形 Local Costmap 的精确几何边界。因此在非正方形 Costmap 中，局部 Path 可能包含落在短边外的 Pose。

2.3 局部 Path 被变换到 base frame ​

截取的每个 Pose 都被变换到 Costmap 的机器人基座坐标系。此后机器人位于原点，前方是 x>0，左侧是 y>0。

Pure Pursuit 的前视距离、carrot 方位角、曲率和倒车方向都能直接在这个坐标系中计算，不必反复处理机器人世界位姿。

2.4 已驶过的路径会永久裁掉 ​

最近点之前的全局 Path 前缀从 global_plan_ 中删除：

text
global_plan_.poses.erase(begin, closest_pose)

下个控制周期从新的路径起点继续处理。RPP 因此带有滚动路径状态，不是每周期都从原始全局路径首 Pose 重新开始。

2.5 空路径和主变换失败直接终止 ​

未设置 Path、机器人 Pose 无法变换到 Path frame，或变换后的局部 Path 为空时，RPP 都会抛出 PlannerException。

但逐个 Path Pose 的变换调用没有检查 transformPose() 返回值。单个 Pose 变换失败时，lambda 仍会返回输出对象，这是当前实现中需要额外关注的 TF 边界。

三、前视距离随当前速度伸缩 ​

3.1 固定前视模式直接使用 lookahead_dist ​

关闭速度缩放时：

text
Ld = lookahead_dist

当前 YAML 中 lookahead_dist=0.45 m，但当前同时配置：

text
use_velocity_scaled_lookahead_dist = true

所以这条固定值在当前 RPP 模式下不参与 carrot 距离计算。

3.2 速度缩放模式使用当前线速度绝对值 ​

当前模式的公式为：

text
Ld = clamp(
  |current_vx| * lookahead_time,
  min_lookahead_dist,
  max_lookahead_dist)

现用参数：

text
lookahead_time       = 1.5 s
min_lookahead_dist   = 0.25 m
max_lookahead_dist   = 0.75 m

静止时 Ld=0.25 m；当前线速度为 0.22 m/s 时，Ld=0.33 m；当前速度达到 0.50 m/s 后，前视距离封顶为 0.75 m。

3.3 速度越快，看得越远 ​

短前视距离对局部路径变化更敏感，能够更快收敛，但也更容易把稀疏路径或定位噪声放大成角速度摆动。

长前视距离让转向更平滑，却可能切弯。速度缩放把两者结合：慢速精细跟踪时 carrot 靠近，高速运行时 carrot 前移，降低几何控制的敏感度。

3.4 当前速度只在特定分支发挥作用 ​

正常 Pure Pursuit 的 applyConstraints() 虽然保留 curr_speed 形参，但当前源码把它标为未使用。正常跟踪没有基于当前线速度的加速度窗口。

当前速度真正影响的是：

  • |current_vx| 决定速度缩放前视距离。
  • current_wz 决定原地旋转单周期可达角速度。

正常线速度的加减速度整形主要交给下游 Velocity Smoother。

四、carrot 来自前视圆与 Path 的交点 ​

4.1 选点条件是欧氏半径，不是路径弧长 ​

getLookAheadPoint() 从局部 Path 起点向后查找首个满足：

text
hypot(pose.x, pose.y) >= Ld

的 Pose。

它比较的是机器人原点到各 Pose 的直线距离，不是沿 Path 累计到该 Pose 的弧长。路径强烈弯曲时，二者可能明显不同。

4.2 Path 不够长时使用末端 Pose ​

如果局部 Path 中没有 Pose 到达前视半径，RPP 使用最后一个 Pose 作为 carrot。

接近路径终点时，实际 carrot 距离自然小于理想 Ld。后续终点接近速度缩放正是利用局部 Path 剩余长度和末点距离让机器人减速。

4.3 稀疏 Path 通过圆线段交点插值 ​

如果启用 use_interpolation=true，并且找到的 Pose 不是局部 Path 首点，源码不会直接跳到这个离散 Pose。

已知：

  • 前一个 Pose 位于前视圆内。
  • 当前 Pose 位于前视圆上或圆外。
  • 圆心是机器人原点。

RPP 解析求解路径线段与：

text
x² + y² = Ld²

的交点，返回恰好距离机器人 Ld 的 carrot。

4.4 插值降低离散路径引起的命令跳变 ​

如果直接取圆外的首个 Pose，Path 点间距越大，carrot 越可能在相邻控制周期突然跳跃，曲率和角速度也会跟着突变。

圆线段解析交点把离散 Path 转成连续前视目标。它没有改变原路径拓扑，只是在相邻 Pose 之间恢复一个几何连续点。

五、Pure Pursuit 的几何核心只有一个曲率公式 ​

5.1 carrot 定义了唯一追踪圆 ​

在机器人坐标系中，carrot 坐标为 (x,y)。假设机器人当前航向与圆弧起点切线一致，并要求圆弧通过 carrot，可以得到：

text
L² = x² + y²
kappa = 2y / L²

其中 kappa=1/R 是曲率。

5.2 横向偏差决定转向符号 ​

carrot 位于左侧时 y>0，曲率为正；位于右侧时 y<0，曲率为负。

同样的前视半径下，|y| 越大，曲率绝对值越大。carrot 越靠近机器人，分母越小，控制器也会更激进。

5.3 极近 carrot 被当成直线 ​

源码只有在：

text
x² + y² > 0.001

时才计算曲率，否则令 kappa=0。

这避免 carrot 几乎落在机器人原点时发生除零或极端曲率。但它也形成一个很小的直线死区。

5.4 角速度在调节线速度之后计算 ​

正常跟踪分支不是先定角速度再减线速度，而是先让曲率、障碍和终点调节出最终线速度，然后执行：

text
omega = linear_velocity * kappa

因此几何曲率保持不变。线速度降低时，角速度同步降低，理想运动半径仍为 1/|kappa|。

六、三条控制分支有严格优先级 ​

6.1 目标航向旋转优先 ​

RPP 每周期从 GoalChecker 获取位置容差，当前为：

text
xy_goal_tolerance = 0.25 m

如果 carrot 到机器人原点的距离小于这个容差，并启用了 use_rotate_to_heading，控制器进入目标航向旋转分支。

目标角度来自局部 Path 最后一个 Pose 的 yaw，而不是 carrot 的连线方向。

6.2 路径航向旋转随后判断 ​

未进入目标旋转时，RPP 计算：

text
angle_to_path = atan2(carrot.y, carrot.x)

当前阈值为：

text
rotate_to_heading_min_angle = 0.785 rad

当 carrot 方位误差超过约四十五度时，控制器先原地对齐路径，再恢复 Pure Pursuit 跟踪。

6.3 正常分支才应用曲率速度调节 ​

目标旋转和路径旋转都不调用 applyConstraints()。只有两个旋转条件都不成立时，才执行：

text
曲率速度调节
→ Costmap 速度调节
→ 终点接近速度调节
→ omega = v * kappa

6.4 三条分支共享碰撞预测 ​

无论输出的是纯旋转还是曲率跟踪 Twist，都会进入 isCollisionImminent()。

所以旋转接管不是安全检查的旁路。机器人原地转动时，Footprint 扫过的区域同样要接受预测检查。

七、急弯通过曲率半径闸门减速 ​

7.1 正常分支从期望速度开始 ​

当前 RPP 配置：

text
desired_linear_vel = 0.22 m/s

正常分支把 linear_vel 初始化为这个值。若 Controller Server 下发 SpeedLimit，desired_linear_vel_ 会被临时改写，成为后续所有调节的基础上限。

7.2 转弯半径小于阈值才触发 ​

源码计算：

text
R = |1 / kappa|

当前曲率调节阈值：

text
regulated_linear_scaling_min_radius = 0.7 m

当 R>=0.7 m 时，曲率不降低线速度；当 R<0.7 m 时：

text
v_curvature = v_desired * R / 0.7

转弯半径减半，曲率候选速度也近似减半。

7.3 直线曲率自然跳过减速 ​

kappa=0 时，1/kappa 在浮点语义下得到无穷大，半径不会小于阈值，因此直线不会触发曲率调节。

源码没有为直线单独写一条分支，浮点无穷大在这里自然表达了“转弯半径无限大”。

7.4 曲率调节不直接限制角速度 ​

正常分支没有 max_angular_vel 参数，也没有角加速度窗口。即使曲率速度已经减小，最终：

text
omega = v * kappa

仍可能在极端小半径下得到较大的角速度。

当前下游 Velocity Smoother 配置 max_velocity.theta=1.0 rad/s，会继续限制最终角速度，但这属于 RPP 包外的速度链。

八、近障碍速度来自 Costmap 代价反解 ​

8.1 读取的是机器人中心当前栅格 ​

Costmap 调节使用：

text
costAtPose(robot_pose.x, robot_pose.y)

它读取机器人中心当前所在栅格的 Local Costmap 代价，不读取 carrot 代价，也不沿预测弧寻找最大代价。

路径前方障碍由后续 Footprint 碰撞预测负责拒绝；当前中心附近的膨胀代价负责提前降速。

8.2 Inflation 代价被反解为障碍距离 ​

当中心格既不是自由空间，也不是未知空间时，RPP 使用 Inflation Layer 的指数模型反解近似障碍距离：

text
d_obs =
  -ln(cost / 252) / inflation_cost_scaling_factor
  + inscribed_radius

当前 RPP 与 Local Costmap 都使用：

text
inflation_cost_scaling_factor = 5.0

两边一致，反解距离才有正确物理意义。

8.3 进入调节距离后按比例降速 ​

当前障碍调节参数：

text
cost_scaling_dist = 0.35 m
cost_scaling_gain = 0.8

当 d_obs<0.35 m：

text
v_cost =
  v_desired * 0.8 * d_obs / 0.35

越靠近障碍，Costmap 候选速度越低。

8.4 Inflation 参数不匹配会让速度语义失真 ​

如果 RPP 使用的 inflation_cost_scaling_factor 与 Local Costmap 不一致，同一个栅格代价会被反解成错误距离。

表现可能是机器人离障碍还很远就持续低速，或者已经很近却没有充分减速。排查这类问题应同时核对 RPP、Inflation Layer 和机器人 Footprint。

九、终点接近缩放最后接管线速度 ​

9.1 触发条件使用局部 Path 剩余积分长度 ​

RPP 先计算局部 Path 的累计长度：

text
remaining_path_length =
  calculate_path_length(transformed_path)

只有它小于：

text
approach_velocity_scaling_dist = 0.6 m

才进入终点接近缩放。

先用路径积分长度判定，可以避免一条弯曲 Path 的末端在欧氏距离上很近，却实际仍需沿弧走较长距离时过早减速。

9.2 缩放比例使用末端欧氏距离 ​

触发后，缩放比例改用机器人原点到局部 Path 最后 Pose 的直线距离：

text
scale =
  euclidean_distance_to_path_end / 0.6

候选接近速度为：

text
v_approach =
  max(current_v * scale, min_approach_linear_velocity)

当前最小接近速度是 0.03 m/s。

9.3 三路约束按特定顺序融合 ​

源码顺序为：

text
v = min(v_curvature, v_cost)
v = max(v, regulated_linear_scaling_min_speed)
v = min(v, v_approach)
v = clamp(|v|, 0, desired_linear_vel)

当前 regulated_linear_scaling_min_speed=0.05 m/s，但目标接近缩放发生在这层保护之后，所以最终速度仍可降到 min_approach_linear_velocity=0.03 m/s。

9.4 最低速度不是整条链的统一下限 ​

regulated_linear_scaling_min_speed 只保护曲率与 Costmap 两条调节链，防止急弯或高代价把机器人直接压到无法运动。

终点接近有自己的更低下限。理解这两个参数的先后关系，才能解释为什么配置了 0.05 m/s，终点附近仍可能看到 0.03 m/s。

十、原地旋转和倒车是互斥模式 ​

10.1 原地旋转先满足角加速度窗口 ​

旋转分支强制：

text
linear_vel = 0
omega_target =
  sign(angle_error) * rotate_to_heading_angular_vel

当前目标旋转速度为 0.8 rad/s。

控制频率为 20 Hz，所以 dt=0.05 s。当前角速度和最大角加速度形成单周期窗口：

text
omega ∈ [
  current_wz - 3.2 * 0.05,
  current_wz + 3.2 * 0.05
]

每周期角速度最多变化约 0.16 rad/s。

10.2 剩余角度还要满足刹停速度 ​

单周期裁剪后，源码再计算：

text
omega_stop =
  sqrt(2 * max_angular_accel * |angle_error|)

如果当前候选角速度大于这个值，就降到 omega_stop。这是由：

text
omega² = 2 * angular_acceleration * angle

得到的刹停边界，用于降低接近目标航向时的过冲。

10.3 倒车必须关闭旋转接管 ​

源码不允许：

text
use_rotate_to_heading = true
allow_reversing = true

同时成立。配置阶段会保留旋转接管并关闭倒车；动态更新阶段也会拒绝冲突组合。

当前配置启用旋转接管，allow_reversing 未显式设置，使用默认 false。

10.4 cusp 防止前视点跨过换向位置 ​

启用倒车后，RPP 遍历局部 Path 的相邻向量：

text
OA = pose[i]   - pose[i-1]
AB = pose[i+1] - pose[i]

当：

text
OA · AB < 0

就把 pose[i] 视为速度符号切换点 cusp。如果前视距离大于机器人到 cusp 的欧氏距离，就把前视距离截短到 cusp。

10.5 carrot 的 x 决定前进还是倒车 ​

允许倒车时：

text
carrot.x >= 0  → sign = +1
carrot.x < 0   → sign = -1

三路速度调节先计算正的速度幅值，末尾再乘 sign。随后 omega=v*kappa，所以线速度和角速度会一起随运动方向翻转。

10.6 尖锐折线也可能触发 cusp ​

点积小于零表示两段路径夹角超过九十度，并不只代表严格的一百八十度倒车换向。

如果上游路径包含没有运动学意义的尖锐折角，RPP 也可能把它当成 cusp。倒车模式应配合能表达前进／倒车方向且几何连续的规划器。

十一、候选 Twist 必须穿过预测碰撞弧 ​

11.1 当前 Footprint 先接受检查 ​

isCollisionImminent() 首先在机器人当前世界 Pose 上检查完整 Footprint。

如果当前姿态已经覆盖致命障碍，控制器直接判定碰撞，不再向前展开预测弧。

11.2 平移步长对应一个 Costmap 栅格 ​

普通路径跟踪使用：

text
projection_dt =
  costmap_resolution / |linear_vel|

于是每次一阶积分的平移距离约等于一个 Costmap 栅格：

text
delta_s = |v| * projection_dt
        = costmap_resolution

速度越快，时间步越短，但空间采样间距保持与地图分辨率一致。

11.3 纯旋转使用独立角度步长 ​

当 |v|<0.01 且 |omega|>0.01 时，RPP 根据机器人外接圆半径和 Costmap 分辨率计算旋转预测时间：

text
projection_dt =
  2 * sin((resolution / 2) / circumscribed_radius)
  / |omega|

目标是让 Footprint 最外侧每次转动约一个栅格尺度，而不是沿用平移步长。

11.4 未来 Pose 用一阶运动学积分 ​

每个预测步执行：

text
x += dt * v * cos(theta)
y += dt * v * sin(theta)
theta += dt * omega

它假设候选 Twist 在整个短时域内保持不变。每个未来 Pose 都用真实机器人 Footprint 查询 Local Costmap。

11.5 预测范围受时间和 carrot 双重限制 ​

当前最大碰撞预测时间：

text
max_allowed_time_to_collision_up_to_carrot = 1.0 s

此外，当预测 Pose 相对机器人起点的欧氏位移超过 carrot 距离时也会停止。

所以碰撞弧不会无条件沿当前圆弧预测一秒，更不会跨过当前控制决策真正瞄准的前视目标。

11.6 碰撞命中会拒绝整条命令 ​

任一未来 Footprint 的代价达到致命障碍阈值，RPP 发布已预测的碰撞弧并抛出 PlannerException。

Controller Server 决定是否在失败容忍窗口内暂时发布零速、重新调用控制器或最终终止 FollowPath。RPP 自己不返回一个“更慢但可用”的备选 Twist。

十二、核心算法之外还有四条速度与安全边界 ​

12.1 正常跟踪没有本地角速度上限 ​

RPP 的 rotate_to_heading_angular_vel 只用于原地旋转分支，不会限制正常 Pure Pursuit 的：

text
omega = v * kappa

当前 Controller Server 输出先进入 cmd_vel_nav，再由 CLOSED_LOOP Velocity Smoother 按：

text
max_velocity = [0.26, 0.0, 1.0]

继续限制线速度、横向速度和角速度，最后发布 cmd_vel。

12.2 SpeedLimit 改写的是期望线速度 ​

百分比限速按基础 desired_linear_vel 缩放，绝对限速直接写入当前期望速度。取消限速时恢复基础值。

当前 setSpeedLimit() 不获取 RPP 参数 mutex，而且绝对限速没有强制限制在基础速度以下。外部调用方需要保证 SpeedLimit 语义正确。

12.3 Costmap 外预测点被视为无碰撞 ​

碰撞预测 Pose 无法转换到 Costmap 栅格时，源码记录节流告警并返回 false。

这意味着预测弧越出 Local Costmap 不是“未知即危险”，而是继续按无碰撞处理。实车上应让 Costmap 尺寸、速度和预测时间相互匹配。

12.4 跟踪未知空间时 NO_INFORMATION 可视为安全 ​

Footprint 代价为 NO_INFORMATION 且 LayeredCostmap 正在跟踪未知空间时，inCollision() 返回 false。

这与地图边界行为叠加后，可能让预测弧在未知或覆盖不足区域继续执行。是否接受这种策略，取决于定位、传感器覆盖和具体安全要求。

12.5 一根 carrot 背后其实是完整控制闭环 ​

RPP 的核心不是复杂搜索，而是把简单几何放进正确的约束顺序：

text
局部 Path
→ 动态前视 carrot
→ Pure Pursuit 曲率
→ 旋转／跟踪分支
→ 急弯、近障碍、近终点减速
→ Footprint 预测碰撞
→ RPP Twist
→ Velocity Smoother
→ 底盘 cmd_vel

carrot 决定机器人想去哪里，曲率决定如何转过去，三路速度闸门决定该跑多快，预测碰撞弧则拥有最后否决权。

这正是 Regulated Pure Pursuit 比普通 Pure Pursuit 多出来的工程价值。
