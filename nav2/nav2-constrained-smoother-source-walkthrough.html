一条 Path，如何被四个残差“拉顺又避障”？拆解 Nav2 Constrained Smoother 的 Ceres 公式 ​

nav2_constrained_smoother 是 Nav2 的路径后处理插件。它不负责重新规划，也不直接输出速度，而是在规划器已经给出 nav_msgs/msg/Path 之后，把可优化的路径点交给 Ceres，利用几何平滑、曲率上限、原路径距离和 Costmap 代价四类残差，得到一条更适合机器人跟踪的路径。

这篇文章只抓住两条主线：它在 Nav2 的位置，以及源码中 Ceres 目标函数究竟如何写成公式。理解这两条主线，调参时就不会把“路径优化”“碰撞判定”和“控制执行”混成一件事。

一、先给结论：它在 Nav2 只做路径几何后处理 ​

1.1 插件边界很清楚 ​

nav2_constrained_smoother 实现 nav2_core::Smoother 接口，由 nav2_smoother::SmootherServer 通过 Pluginlib 动态加载。一次 SmoothPath 请求大致经历以下数据流：

规划器路径 → SmootherServer → ConstrainedSmoother → Ceres 优化 → 写回路径 → 可选 Footprint 碰撞检查。

它不会读取里程计来闭环，也不会发布 cmd_vel，更不会替代全局规划器。输入是带姿态的 Path，内部主要优化每个点的二维位置，最后再根据切线重新计算 yaw。

1.2 “软代价”不等于“硬安全证明” ​

优化器把 Costmap 数值作为连续代价，倾向于把路径从高代价区域推开。SmootherServer 在得到结果后还可以调用足迹碰撞检查器做离散安全检查。前者改变几何形状，后者判断当前离散路径是否碰撞，两者职责不同。

1.3 一张图看懂包外调用链 ​

当前项目的实际配置仍使用 simple_smoother，因此源码存在并不代表该插件已经进入运行链。要启用它，需要在 SmootherServer 的插件列表中声明对应插件类型，并让插件参数与当前 Costmap 配套。

二、Ceres 变量到底是什么 ​

2.1 每个参数块只有二维位置 ​

设原始路径包含点 P={p_0,p_1,...,p_N}，其中：

text
p_i = [x_i, y_i]^T

源码通过 ceres::AutoDiffCostFunction<SmootherCostFunction, 4, 2, 2, 2> 注册一个残差块。一次求值接收三个二维参数块：当前点 p_i、后一个点 p_{i+1} 和前一个点 p_{i-1}，输出四个残差分量。路径点的方向维 direction_sign 只记录前进或倒退方向，供 Cusp 检测、切线和足迹变换使用，不是 Ceres 的连续优化变量。

2.2 优化集合与边界点 ​

buildProblem 会根据路径降采样因子、Cusp、起终点保护和方向保持选项，决定哪些点真正加入优化。首尾点通常被固定，必要时还会固定首尾邻点来保护起点和终点朝向；没有可移动的内部点时，构建问题直接失败。

上层 Action 的剩余时间会写入 options_.max_solver_time_in_seconds。因此，Ceres 的时间上限不是一个脱离请求的全局常量，而是 Smoother 请求给出的本次预算。

2.3 operator() 是四类残差的总装配点 ​

源码把三个 Ceres 参数块映射成 Eigen 二维向量，再把四个 helper 的结果写入固定槽位：

cpp
template<typename T>
bool operator()(const T * const pt, const T * const pt_next,
  const T * const pt_prev, T * pt_residual) const
{
  Eigen::Map<const Eigen::Matrix<T, 2, 1>> xi(pt);
  Eigen::Map<const Eigen::Matrix<T, 2, 1>> xi_next(pt_next);
  Eigen::Map<const Eigen::Matrix<T, 2, 1>> xi_prev(pt_prev);
  Eigen::Map<Eigen::Matrix<T, 4, 1>> residual(pt_residual);
  residual.setZero();
  addSmoothingResidual(params_.smooth_weight, xi, xi_next, xi_prev, residual[0]);
  addCurvatureResidual(params_.curvature_weight, xi, xi_next, xi_prev, residual[1]);
  addDistanceResidual(params_.distance_weight, xi, original_pos_.cast<T>(), residual[2]);
  addCostResidual(costmap_weight_, xi, xi_next, xi_prev, residual[3]);
  return true;
}

代码解释：Eigen::Map 没有复制参数内存，只是把 Ceres 传入的裸指针解释成二维向量；residual.setZero() 很重要，因为曲率分支在直线或未超限时会直接返回，先清零才能保证该槽位保持零值；模板类型 T 允许 Ceres 把普通 double 换成自动求导的 Jet 类型。

三、总目标函数：四维残差先组装，再交给 Ceres ​

3.1 残差块的结构 ​

对每个可优化点 p_i，源码按固定顺序写入平滑、曲率、距离和 Costmap 四个分量：

text
r_i(P) = [ r_smooth(i), r_curve(i), r_dist(i), r_cost(i) ]^T
F(P) = Σ_{i∈I} || r_i(P) ||_2^2

其中 I 是真正加入 Ceres 问题的点集合，P 是所有未被固定的二维位置参数。Ceres 最小化的是所有残差平方和，并通过 AutoDiff 自动计算坐标到残差的 Jacobian。

3.2 源码里有一个容易忽略的“平方层级” ​

四个 helper 函数写入的并不是线性误差，而是已经平方过的量。例如平滑项写成 w_smooth * ||...||²，距离项写成 w_dist * ||...||²，Costmap 项写成 w_cost * C²。外层 Ceres 还会计算 ||r_i||²。

从单个分量的独立贡献看，实际进入总目标的形态近似为：

text
(w · e^2)^2 = w^2 · e^4

这不表示四项之间完全没有耦合，但说明参数名中的 weight 并不是简单线性地乘在最终代价上。调参时如果把权重当成传统的 w·e² 来理解，往往会低估大误差的放大速度。

这也解释了为什么源码把 helper 称为 residual，却在注释中写着 objective function value：helper 负责先算出一个可微的代价分量，Ceres 再把这个分量当作残差参与外层平方求和。阅读代码时，不能只看到 r += ... 就把它当成一次普通线性累加。

四、平滑与曲率：一组三点承担两种几何约束 ​

4.1 平滑项让相邻切向连续 ​

定义当前点两侧的位移：

text
d_i^+ = p_{i+1} - p_i
d_i^- = p_i - p_{i-1}

源码使用前后段长度比例 α_i 做尺度补偿，平滑残差为：

text
r_smooth(i) = w_smooth · || α_i d_i^+ - d_i^- ||_2^2

当采样点不等距时，α_i 可以避免仅比较坐标差导致的误判。路径经过前进到倒退的 Cusp 时，比例带负号，使残差能够表达方向翻转，而不是强行要求两侧位移同向。

4.2 曲率项只惩罚超过上限的弯折 ​

对 p_{i-1},p_i,p_{i+1} 求三点圆弧圆心 c_i。若三点近似共线或退化，源码返回无穷圆心，不施加曲率惩罚；对有限圆心，计算：

text
R_i = || p_i - c_i ||_2
κ_i = 1 / R_i
r_curve(i) = w_curve · max(0, κ_i - κ_max)^2
κ_max = 1 / minimum_turning_radius

所以它约束的是“超过最大允许曲率的部分”，而不是把所有弯道都拉成直线。minimum_turning_radius 越大，κ_max 越小，允许的弯折越保守。

4.3 平滑项的实现只有三行核心计算 ​

对应 addSmoothingResidual 的源码可以压缩成：

cpp
Eigen::Matrix<T, 2, 1> d_next = pt_next - pt;
Eigen::Matrix<T, 2, 1> d_prev = pt - pt_prev;
Eigen::Matrix<T, 2, 1> d_diff = next_to_last_length_ratio_ * d_next - d_prev;
r += static_cast<T>(weight) * d_diff.dot(d_diff);

代码解释：d_next 与 d_prev 是同一个局部窗口内的两段位移，next_to_last_length_ratio_ 负责抵消不等距采样带来的尺度差异，dot 计算平方范数后写入当前残差槽位。这里的 r 不是全局目标，而是 residual[0] 的引用。

4.4 曲率代码用“提前返回”实现铰链惩罚 ​

曲率 helper 的关键分支如下：

cpp
Eigen::Matrix<T, 2, 1> center = arcCenter(pt_prev, pt, pt_next, ratio < 0);
if (CERES_ISINF(center[0])) {
  return;
}
T turning_rad = (pt - center).norm();
T ki_minus_kmax = static_cast<T>(1.0) / turning_rad - params_.max_curvature;
if (ki_minus_kmax <= static_cast<T>(EPSILON)) {
  return;
}
r += static_cast<T>(weight) * ki_minus_kmax * ki_minus_kmax;

代码解释：无有限圆心时不把曲率强行设成一个大数；曲率没有超过上限时直接返回零；只有超限部分才进入平方惩罚。这就是公式中的 max(0, κ_i-κ_max)^2 在源码里的分支形式。

五、Costmap 与 Cusp：把避障代价变成可微项 ​

5.1 单点 Costmap 残差 ​

没有配置自定义足迹采样点时，当前优化点直接映射到 Costmap 网格，再由双三次插值器读取连续代价。设 Costmap 原点为 o、分辨率为 Δ，世界点对应的网格坐标为：

text
u_i = (p_i - o) / Δ
v_i = C_bicubic(u_i_y - 0.5, u_i_x - 0.5)
r_cost(i) = w_cost(i) · v_i^2

减去 0.5 是源码对网格中心坐标的换算。双三次插值让点在单元之间移动时，代价对 Ceres 来说更连续；它并没有把 Costmap 变成一条新的规划路径。

5.2 足迹采样点的刚体变换 ​

配置 cost_check_points 后，每三个数表示机器人坐标系中的采样点 (x_k,y_k) 及其归一化权重 β_k。源码利用路径切线建立二维刚体变换：

text
q_k = [x_k, y_k, 1]^T
T_i = [ t_x  -t_y  p_i_x
        t_y   t_x  p_i_y
         0     0     1  ]
r_cost(i) = w_cost(i) · Σ_k β_k · C(T_i q_k)^2

切线方向会根据前进或倒退符号翻转，避免车辆足迹朝向与运动方向相反。这样代价项关注的就不只是参考点，而是机器人局部轮廓在当前姿态下覆盖到的 Costmap 区域。

5.3 Cusp 附近的权重是渐变的 ​

识别到方向切换点后，源码把 Costmap 权重提升为：

text
w_cusp = w_cost · w_cost_cusp_multiplier
h = cusp_zone_length / 2
w_cost(s) = w_cusp · (1 - s/h) + w_cost · (s/h), 0 ≤ s ≤ h

这个线性插值同时作用于 Cusp 两侧的区域。它的意图是让倒车换向附近更重视障碍物代价，同时避免在边界处突然跳变。这个机制仍然是软约束，最终是否碰撞还要看服务器侧的足迹检查。

5.4 参考点 Costmap 分支如何读取连续代价 ​

没有足迹采样点时，核心代码只有一个坐标换算、一次插值和一次平方累加：

cpp
Eigen::Matrix<T, 2, 1> interp_pos =
  (pt - costmap_origin_.cast<T>()) / static_cast<T>(costmap_resolution_);
T value;
costmap_interpolator_->Evaluate(interp_pos[1] - static_cast<T>(0.5),
  interp_pos[0] - static_cast<T>(0.5), &value);
r += static_cast<T>(weight) * value * value;

代码解释：Costmap2D 的世界坐标先除以分辨率变成网格坐标，再交换插值器需要的行列顺序；BiCubicInterpolator 允许优化点在网格单元之间移动时得到连续近似值。代价读取本身不会修改 Costmap，也不会产生新的路径拓扑。

5.5 足迹分支先把机器人坐标变到世界坐标 ​

配置 cost_check_points 后，源码用路径切线组装刚体变换，并在循环中累加每个采样点。下面省略了插值坐标的重复展开，只保留变量关系：

cpp
transform << dir[0], -dir[1], pt[0],
             dir[1],  dir[0], pt[1],
             0,       0,      1;
for (size_t i = 0; i < params_.cost_check_points.size(); i += 3) {
  Eigen::Matrix<T, 3, 1> local_point(
    params_.cost_check_points[i], params_.cost_check_points[i + 1], 1);
  auto world_point = (transform * local_point).template block<2, 1>(0, 0);
  // world_point 映射到 Costmap 后得到 value
  r += static_cast<T>(weight) *
    static_cast<T>(params_.cost_check_points[i + 2]) * value * value;
}

代码解释：每组三元组是机器人坐标系中的 x、y、weight；dir 会根据前进／倒退方向翻转，保证足迹朝向与运动方向一致；采样点权重在参数读取阶段归一化，最终形成机器人轮廓而不是单个参考点的代价。

六、Ceres 如何求解 ​

6.1 AutoDiff 把公式变成 Jacobian ​

源码没有手写每个残差对 x_i,y_i 的导数，而是让 Ceres AutoDiff 根据模板类型 T 自动求导。对当前参数 P 做局部增量 δ 时，可以把核心近似理解为：

text
r(P + δ) ≈ r(P) + J(P) · δ
minimize || r(P) + J(P) · δ ||_2^2

J(P) 同时包含三点几何关系、圆弧曲率、原始点距离和 Costmap 插值的局部变化。源码允许 DENSE_QR 或 SPARSE_NORMAL_CHOLESKY 线性求解器，并用最大迭代次数、参数变化阈值、函数变化阈值和梯度阈值控制停止。

6.2 什么结果会被接受 ​

Smoother::smooth 只有在 summary.IsSolutionUsable() 为真，且 initial_cost - final_cost >= 0 时才接受结果。也就是说，求解必须给出可用状态，并且最终目标不能比初始值更差；如果没有可移动的内部点，构建问题阶段就会返回失败。

外层 Action 的 max_time 会限制 Ceres 的求解时间。低频规划、超长路径或足迹采样点较多时，时间预算会直接影响迭代是否有机会完成，因此不能只盯着权重参数。

6.3 buildProblem 把局部公式接到参数块 ​

构建问题时，源码为一个局部三点窗口创建代价对象，再把三个位置指针接入 Ceres：

cpp
auto * cost_function = new SmootherCostFunction(
  path[last_i].template block<2, 1>(0, 0), ratio, reversing,
  costmap, costmap_interpolator, params, costmap_weight);
problem.AddResidualBlock(
  cost_function->AutoDiff(), nullptr,
  path_optim[last_i].data(), pt.data(), path_optim[prelast_i].data());

代码解释：AutoDiff() 返回 4 个残差、3 个二维参数块 的 Ceres 代价函数；nullptr 表示没有额外的鲁棒核，当前实现使用普通平方和；三个 .data() 指针就是局部几何窗口的参数来源。SetParameterBlockConstant 随后把首尾及可选邻点锁定，避免优化破坏边界姿态。

6.4 结果验收代码决定是否写回 ​

求解结束后并不是无条件接受新路径：

cpp
ceres::Solver::Summary summary;
ceres::Solve(options_, &problem, &summary);
if (!summary.IsSolutionUsable() ||
    summary.initial_cost - summary.final_cost < 0.0) {
  return false;
}
upsampleAndPopulate(path_optim, optimized, start_dir, end_dir, params, path);

代码解释：不可用的 Solver 状态，或最终目标高于初始目标，都会在写回前被拒绝；只有通过这道门，才进入路径补点和姿态恢复。max_time、迭代上限和三个收敛阈值共同影响这段验收代码能否拿到可用结果。

七、为什么优化完还要贝塞尔上采样 ​

7.1 离散优化点不是最终输出密度 ​

为了控制 Ceres 问题规模，源码可以先对路径降采样；优化完成后，再在相邻优化点之间用三次 Bézier 曲线补点。设一段曲线端点为 p_0,p_3，端点切向为 t_0,t_3，段长为 L：

text
p_1 = p_0 + 0.4 · L · t_0 · sign
p_2 = p_3 - 0.4 · L · t_3 · sign
B(μ) = (1-μ)^3 p_0 + 3(1-μ)^2 μ p_1
       + 3(1-μ) μ^2 p_2 + μ^3 p_3

插值参数 μ 在 0 到 1 之间均匀取值，插值数量由相邻优化点距离和 path_upsampling_factor 决定；源码中的 cubicBezier 函数负责计算每个参数位置。这样既保留 Ceres 找到的整体形状，又恢复控制器需要的路径密度。

7.2 输出代码如何形成 Bézier 控制点 ​

源码在两个保留点之间计算控制点、插值参数和中间位置：

cpp
int interp_cnt = (last_i - prelast_i) * params.path_upsampling_factor - 1;
double dist = (last_pt - prelast_pt).norm();
Eigen::Vector2d pt1 = prelast_pt + prelast_dir * dist * 0.4 * prelast[2];
Eigen::Vector2d pt2 = last_pt - last_dir * dist * 0.4 * prelast[2];
double mu = j / static_cast<double>(interp_cnt + 1);
Eigen::Vector2d point = cubicBezier(prelast_pt, pt1, pt2, last_pt, mu);
path.emplace_back(point[0], point[1], 0.0);

代码解释：0.4 倍段长把控制点放在端点切线方向上；prelast[2] 把前进／倒退符号带入控制点方向；新点先写入位置，随后通过相邻点切线和 atan2 补齐 yaw。因此 Bézier 阶段是输出后处理，不会再次参与 Ceres 优化。

7.3 yaw 是后处理结果 ​

插值后的相邻点差分得到切线，再通过 atan2 计算 yaw 并写回 PoseStamped。因此，内部方向符号和最终消息里的四元数 yaw 不是同一个变量：前者服务于方向切换与足迹朝向，后者是输出路径的姿态表达。

八、调参要围绕公式，不要只看参数大小 ​

8.1 四个权重分别在拉什么 ​

  • smooth_weight：抑制相邻段切向突变，过大时路径可能过分追求平滑。
  • curvature_weight：抑制超过 max_curvature 的弯折，过大时可能把窄空间中的可行形状推向更远处。
  • distance_weight：把优化点拉回原始规划路径，过大时避障和曲率项的形变空间会变小。
  • costmap_weight：把路径推离高代价区域，过大时可能出现明显绕行或贴近代价梯度边界。

由于源码先在残差内部平方，Ceres 又对残差块做平方，四个权重不能简单按“增大一倍，影响增大一倍”来理解。应结合初始路径、Costmap 代价范围和最终目标下降量一起看。

8.2 更值得一起调的参数 ​

  • minimum_turning_radius 与 curvature_weight 共同决定弯折上限和超限惩罚。
  • cusp_zone_length 与 costmap_weight_cusp_multiplier 共同决定换向附近避障压力的范围和强度。
  • path_downsampling_factor、path_upsampling_factor 共同影响问题规模、输出密度和细节保留。
  • max_time、max_num_iterations、parameter_tolerance、function_tolerance 和 gradient_tolerance 共同决定求解是否有足够机会收敛。
  • cost_check_points 的长度必须是三的倍数；每组三元组的权重也应检查归一化和数值范围。

九、源码边界与工程结论 ​

9.1 这不是规划器，也不是控制器 ​

它优化的是已有 Path 的几何点。地图拓扑、目标可达性和全局绕行仍由规划器负责；速度限制、跟踪误差和实时控制仍由控制器负责。把 nav2_constrained_smoother 调得更激进，不能替代规划器的不可达判断，也不能替代控制器的碰撞保护。

9.2 当前项目是否真正启用要看 YAML ​

当前项目生产配置使用的是 simple_smoother，典型声明形态如下：

yaml
smoother_plugins: ["simple_smoother"]
simple_smoother:
  plugin: "nav2_smoother::SimpleSmoother"

只有将插件列表和类型改为 nav2_constrained_smoother::ConstrainedSmoother，并补齐对应参数，前面的 Ceres 公式才会进入运行时链路。

9.3 读源码时要留意的风险点 ​

  • 相邻点重复或几乎共线时，圆弧曲率项可能退化为不惩罚，不能把它误读成“曲率一定为零”。
  • cost_check_points 只检查长度是否能按三元组遍历，权重和是否合理需要配置侧自行保证。
  • Costmap 残差是软代价，不能单独当作离散足迹碰撞证明。
  • 求解失败路径与服务器异常转换属于包间边界，排查时应同时看 SmootherServer 日志和插件日志。

十、用一句话记住 ​

nav2_constrained_smoother 的核心不是“把折线画得好看”，而是把每个可移动路径点放进一个由平滑、曲率、原路径距离和 Costmap 代价组成的四维残差块，再交给 Ceres 在时间预算内寻找更适合跟踪的几何解；优化之后的安全性，仍由服务器侧的碰撞检查和控制链路共同兜底。
