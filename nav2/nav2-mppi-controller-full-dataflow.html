nav2 ~三 · 局部控制与速度生成2026-07-216 min read

一次采样 1000 条轨迹，机器人最后听谁的？拆解 Nav2 MPPI 全调用、状态与数据流 ​

MPPI 不从候选中硬选一条最低分轨迹，而是让大量带噪控制序列经过运动模型变成未来轨迹，再由 Critic 计算成本，最后用 softmax 权重把整批控制意见合成新的控制序列。

一、MPPI 是 Controller 插件 ​

1.1 ROS 边界在 Controller Server ​

MPPIController 实现 nav2_core::Controller，不创建独立节点。FollowPath Action、Odometry、Local Costmap、TF、GoalChecker、speed limit、Action 结果和最终 cmd_vel 都由 Controller Server 管理。

插件接收当前 Pose、Twist 与 GoalChecker，内部读取缓存 Path 和 Costmap，返回 TwistStamped。启用可视化时额外发布 /trajectories 与 transformed_global_plan。

1.2 优化从上一周期继续 ​

核心状态 control_sequence_ 跨周期保留，control_history_ 保存近期控制。每轮不是从全零开始，而是在上一轮解附近重新加噪和优化，最后滚动序列。

二、Lifecycle 与资源状态 ​

2.1 configure 组装优化流水线 ​

configure 创建 ParametersHandler、Optimizer、NoiseGenerator、PathHandler、MotionModel、CriticManager 和可视化 Publisher。Critic 列表在这里按配置顺序加载。

2.2 状态变化影响线程和回调 ​

activate() 激活 Publisher 与动态参数入口，deactivate() 停用输出，cleanup() 才停止噪声线程并释放对象。参数更新与控制周期使用同一互斥机制，更新后通常 reset 优化器。

持久数据包括控制序列、历史控制、批量速度张量、候选轨迹、成本向量、局部 Path tensor 和 Critic 共享缓存。

三、Path 怎样变成批量未来 ​

3.1 PathHandler 先形成局部参考 ​

机器人 Pose 被变换到 Path frame，在有限前缀中寻找最近点，再按 prune_distance 截取前方路径。Pose 逐点变换到 Local Costmap frame，越出地图范围即停止，机器人身后的旧 Path 被裁掉。

开启 enforce_path_inversion 时，相邻路径向量反向的位置形成 cusp。当前控制段在 cusp 处截断，只有到达位置和航向容差后才释放下一段。

3.2 Odometry 是 rollout 初始状态 ​

prepare() 写入当前 Pose 与 Twist，把局部 Path 转成 tensor，并清空 costs、失败标志和 Critic 缓存。MotionModel 把当前 vx、vy、wz 写入批量状态首列，再从这个真实运动状态向未来传播。

四、1000 条候选怎样产生 ​

4.1 控制序列叠加高斯噪声 ​

NoiseGenerator 为 vx、vy、wz 生成形状为 batch_size × time_steps 的独立高斯噪声。候选控制等于基准 control_sequence_ 加噪声，并按速度硬边界裁剪。

regenerate_noises=false 时复用噪声矩阵；为 true 时后台线程准备下一批噪声。noise mutex 负责矩阵交换，cleanup 必须唤醒并 join 线程。

4.2 MotionModel 决定可行运动 ​

  • DiffDrive 禁止横移。
  • Omni 允许 vy。
  • Ackermann 加入最小转弯半径约束。

本地模型从当前 Odometry 速度开始传播，再按 model_dt 积分为 batch_size 条未来轨迹；它没有把加速度作为独立状态。

五、成本怎样变成控制 ​

5.1 Critic 共同累加 costs ​

CriticManager 按配置顺序执行，每个 Critic 读取相同的轨迹、Path、Costmap、目标状态和共享缓存，把成本写入同一个 costs[batch_size]。cost_weight 调整量级，cost_power 调整非线性。

5.2 softmax 不是最小值选择 ​

算法先执行 cost - min(cost) 保持数值稳定，再计算近似权重：

text
weight_i = softmax(-cost_i / temperature)

每个时间步的噪声按这些权重加权，更新整个控制序列。temperature 越小，权重越集中于低成本候选；gamma 是控制噪声正则系数，不是 Critic 权重。

5.3 输出前还有硬约束与平滑 ​

新序列经过速度限制、Ackermann 转弯半径约束和 Savitzky-Golay 滤波。控制频率与 model_dt 匹配时可开启序列移位，返回当前应执行项后把剩余序列向前滚动。

六、十二类 Critic 怎样分工 ​

6.1 约束与安全 ​

ConstraintCritic 处理速度和运动模型边界；CostCritic 或 ObstaclesCritic 处理 Costmap 代价、footprint 与碰撞；VelocityDeadbandCritic 处理底盘死区。

6.2 路径与目标 ​

PathFollow、PathAlign、PathAlignLegacy 和 PathAngle 评价路径进度、整体贴合与朝向；Goal 与 GoalAngle 评价终点位置和 yaw。

6.3 行为偏好 ​

PreferForward 抑制不必要倒车，Twirling 抑制全向底盘无意义自旋。当前配置实际启用 Constraint、Cost、Goal、GoalAngle、PathAlign、PathFollow、PathAngle 和 PreferForward 八项。

Critic 决定“什么叫好”，采样标准差决定“探索多远”，两者不能用同一种权重思路调节。

七、碰撞失败怎样重试 ​

7.1 fail_flag 触发 Optimizer fallback ​

当安全 Critic 判断整批候选都碰撞时设置 fail_flag。Optimizer reset 控制序列并重新采样，未超过重试上限则再次优化，持续失败才抛异常。

Path 为空、TF 错误和局部 Path 变换失败发生在 Critic 之前，不进入这套 fallback。异常交给 Controller Server 后，failure_tolerance 决定短暂零速还是 FollowPath 失败。

7.2 SpeedLimit 改变运动边界 ​

百分比限速按比例缩放基础约束；绝对限速先换算为 vx 比例，再统一缩放相关速度边界。它不会同步缩小噪声标准差，因此低限速时仍要检查采样噪声是否过大。

八、当前配置如何运行 ​

8.1 预测规模 ​

本地配置使用 batch_size=1000、time_steps=56、model_dt=0.05 s、iteration_count=1 和 DiffDrive，形成约 2.8 s 的预测窗口。Controller Server 为 20 Hz，周期与 model_dt 相等，因此启用控制序列移位。

8.2 最终速度仍由下游约束 ​

MPPI 返回的是建议 Twist。Velocity Smoother 继续应用速度、加减速度、死区和超时，底盘适配器再转换为硬件控制指令。排障必须同时观察 MPPI 输出与最终 cmd_vel。

九、本地源码边界 ​

9.1 不能直接套用 latest 参数 ​

本地 1.1.20 使用 MotionModel 类型字符串，没有最新版插件化 MotionModel、加速度约束、TrajectoryValidator 和独立最优轨迹发布接口。调参前必须确认源码版本。

9.2 审计关注点 ​

  • PathHandler 部分 Costmap 查询早于 Costmap mutex。
  • 未识别动态参数也可能触发 Optimizer reset。
  • motion_model 与部分 Critic 动态回调绑定临时变量。
  • 从 false 热切换 regenerate_noises 不会创建后台线程。
  • setPlan() 与 setSpeedLimit() 没有本地互斥。
  • fallback 计数器为函数静态状态，可跨 Optimizer 实例共享。

十、总结与参考 ​

10.1 完整数据链 ​

text
Pose＋Odom＋Path → 控制序列＋高斯噪声
→ MotionModel 批量 rollout → Critic costs
→ softmax 加权 → 硬约束＋滤波
→ TwistStamped → Controller Server
→ Velocity Smoother → cmd_vel

MPPI 优化的不是一条离散轨迹，而是一段控制分布；低成本候选共同塑造下一周期的控制序列。
