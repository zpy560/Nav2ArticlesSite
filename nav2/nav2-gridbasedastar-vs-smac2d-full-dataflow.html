同样是 A*，Nav2 为什么给了两套答案？NavFn 与 Smac2D 全数据流拆解 ​

GridBasedAstar 和 Smac2D 都能在二维 Costmap 上做 A*，但它们不是同一算法换了个名字。一个继承 NavFn 势场体系，一个使用模板化标准 A*。本文基于当前项目源码，拆开两者的机制演变、代价模型、生命周期和完整输入输出数据流。

一、先给结论：真正的差异不在“A*”三个字符 ​

1.1 当前配置的两套二维 A* ​

当前工程同时配置了两套二维 A*：

  • GridBasedAstar：插件类型是 nav2_navfn_planner/NavfnPlanner，通过 use_astar: true 启用 NavFn 的 A* 优先策略。
  • Smac2D：插件类型是 nav2_smac_planner/SmacPlanner2D，内部使用 AStarAlgorithm<Node2D>。

两者共享 PlannerServer、Global Costmap、起点、终点和最终 nav_msgs::msg::Path，但搜索内核完全不同。

1.2 NavFn A* 的主流程 ​

1.2.1 设置势场源头 ​

把目标点作为势场源头。

1.2.2 传播导航势 ​

在四邻域上向机器人起点传播导航势。

1.2.3 加入启发项 ​

用欧氏距离改变传播优先级。

1.2.4 提取路径 ​

再沿连续势场梯度生成路径。

1.3 Smac2D 的主流程 ​

1.3.1 从起点开始搜索 ​

从机器人起点正向搜索。

1.3.2 计算搜索代价 ​

在八邻域上显式计算 g+h。

1.3.3 加入 Costmap 代价 ​

把 Costmap 代价直接加入每一步的通行成本。

1.3.4 回溯并平滑路径 ​

用父指针回溯栅格路径，再执行内置平滑。

一句话概括：NavFn A* 是“带 A* 引导的势场传播器”，Smac2D 是“带完整工程外壳的二维标准 A*”。

二、先别被名字骗了：插件 ID 不等于插件类型 ​

GridBasedAstar 和 Smac2D 都只是当前 YAML 中的插件 ID。ID 是调用方选择规划器时使用的字符串，可以由项目自行命名；真正决定 C++ 实现的是 plugin 字段。

当前 nav2_regulated_modules 的关键配置是：

yaml
selected_planner: "GridBasedAstar"
planner_plugins: ["GridBased", "GridBasedAstar", "Smac2D", "SmacHybrid", "SmacLattice", "ThetaStar"]

GridBasedAstar:
  plugin: "nav2_navfn_planner/NavfnPlanner"
  tolerance: 0.5
  use_astar: true
  allow_unknown: true

Smac2D:
  plugin: "nav2_smac_planner/SmacPlanner2D"
  tolerance: 0.5
  downsample_costmap: false
  downsampling_factor: 1
  allow_unknown: true
  max_iterations: 1000000
  max_on_approach_iterations: 1000
  max_planning_time: 2.0
  cost_travel_multiplier: 2.0

因此，当前默认运行的是 NavFn A*。Smac2D 虽然已经加载进 PlannerServer，但只有把 selected_planner 改为 Smac2D，或取消强制选择并在 Action Goal 中指定 planner_id: "Smac2D"，它才会参与本次规划。

还要注意一个本项目特有逻辑：PlannerServer 的 selected_planner 非空时，它会覆盖 Action Goal 里的 planner_id。这意味着只改行为树或客户端的 planner ID，不一定真的切换成功。

三、机制演变：从专用导航函数到模板化搜索框架 ​

理解两者差异，最有效的方法不是从参数表开始，而是看它们各自继承了什么架构。

3.1 NavFn：先有导航势场，再加入 A* 引导 ​

NavFn 的核心数据不是父指针图，而是整张地图的 potarr 势场数组。它采用四邻域平面波更新，并用横向、纵向两个最低势邻居做二次近似，得到更连续的导航势。

原始 Dijkstra 模式按势值逐层扩散。切换到 A* 后，势场计算方式没有换掉，只是在节点进入优先缓冲区时，加上当前位置到机器人起点的欧氏距离启发项。

因此，use_astar: true 改变的是“先扩展谁”，不是“最终路径按什么数据结构表示”。最终路径仍然来自势场梯度。

3.2 Smac：把 A* 抽成可以更换节点模型的模板 ​

Smac 的核心是 AStarAlgorithm<NodeT>。A* 框架只负责开放队列、图节点、终止条件、父指针和回溯；节点类型负责邻接关系、碰撞有效性、通行代价和启发函数。

同一框架可以装入：

  • Node2D：二维栅格 A*。
  • NodeHybrid：带朝向维度和运动学模型的 Hybrid-A*。
  • NodeLattice：状态格搜索。

Smac2D 就是这套框架的 Node2D 专门化。它不做朝向维度搜索，也不执行 Hybrid／Lattice 的解析扩展，但仍复用统一的超时、迭代限制、容差回退和图管理机制。

这次演变的重点不是“新算法替代旧算法”，而是从专用势场实现演变为可复用搜索内核，并把降采样、碰撞检查、调试发布和平滑等工程能力装入插件外壳。

四、共同调用链：ROS 接口其实都在 PlannerServer ​

两套规划器都不是独立 ROS 2 节点，也不各自提供 ComputePathToPose Action。它们是共享库插件，由 planner_server 通过 pluginlib 装载。

一次单目标规划请求的共同链路如下。

4.1 接收规划目标 ​

上层导航器向 /compute_path_to_pose 发送 Action Goal。

4.2 获取机器人起点 ​

PlannerServer 使用 Goal 中的起点，或从 Global Costmap 获取当前机器人位姿。

4.3 变换起终点坐标 ​

PlannerServer 把起点和终点转换到 Global Costmap 的全局坐标系。

4.4 选择规划插件 ​

PlannerServer 根据 selected_planner 或 planner_id 选中插件。

4.5 调用 createPlan() ​

在同一进程内直接调用 createPlan(start, goal)。

4.6 返回 Path ​

插件返回 nav_msgs::msg::Path。

4.7 发布规划结果 ​

PlannerServer 校验路径非空，发布相对话题 plan，并把路径写入 Action Result。

多目标 /compute_path_through_poses 会多次调用同一个规划插件，再把分段路径拼接起来。

4.8 间接数据边界 ​

两者都不直接订阅：

  • /map。
  • /goal_pose。
  • /tf 或 /tf_static。
  • 激光、点云或里程计。

地图和传感器数据先进入 Global Costmap。插件拿到的是进程内 Costmap2D 指针，而不是重新订阅一份 OccupancyGrid。

五、生命周期和输入输出边界 ​

5.1 共同生命周期接口 ​

两套插件都实现 nav2_core::GlobalPlanner 的共同生命周期接口：

  • configure()：保存父节点、插件 ID、Costmap 和全局坐标系，读取参数并创建算法资源。
  • activate()：启用运行期资源，并注册动态参数回调。
  • deactivate()：移除动态参数回调或停用发布器。
  • cleanup()：释放算法对象和相关资源。
  • createPlan()：执行一次规划。

5.2 NavFn 资源 ​

NavFn 在配置阶段创建 NavFn 对象，内部维护代价数组、势场数组、梯度数组和三个固定大小的优先缓冲区。

5.3 Smac2D 资源 ​

Smac2D 在配置阶段创建：

  • AStarAlgorithm<Node2D>。
  • GridCollisionChecker。
  • Smoother。
  • 可选 CostmapDownsampler。
  • unsmoothed_plan Lifecycle Publisher。

5.4 直接输入输出 ​

两者的直接输入都是起点、终点、Costmap 和参数；直接输出都是 nav_msgs::msg::Path。空 Path 最终由 PlannerServer 映射为规划 Action 失败。

六、NavFn A* 全数据流：先铺势场，再顺坡下山 ​

NavFn 的调用方向很容易看反。插件从 PlannerServer 收到了“起点到终点”的请求，但写入 NavFn 内核时，会把规划目标设置成势场传播起点，把机器人起点设置成传播终点。

这是因为势场从目标向外长，路径再从机器人位置沿低势方向回到目标。

完整流程如下。

6.1 复制并重映射 Costmap ​

插件先清空机器人起点栅格，然后锁住 Costmap，把原始 0…255 代价复制到 NavFn 自己的 costarr。

可通行代价被转换为：

navfn_cost = 50 + 0.8 × costmap_cost

其中：

  • 自由空间不再是 0，而是基础代价 50。
  • 0…252 被映射到大约 50…251。
  • 致命障碍和内切障碍被设为 254，禁止传播。
  • 未知栅格在 allow_unknown=true 时被设为 253，可以进入，但代价非常高。

这意味着 NavFn 也是代价感知的。Smac2D 并不独占“代价感知”这个能力，真正差异在代价怎样进入搜索。

6.2 初始化势场 ​

整张 potarr 被重置为 POT_HIGH。地图四周边界被强制写成障碍，目标栅格势值设为 0，它的上下左右邻居进入当前优先缓冲区。

6.3 四邻域平面波更新 ​

每个候选栅格读取上下左右四个势值，分别取水平方向和竖直方向的最低值，再结合本栅格通行成本做二次近似。

这里不是简单的：

potential = min_neighbor + cell_cost

而是尽量用两个方向的低势邻居逼近连续平面波。这也是 NavFn 后续可以沿梯度输出亚栅格路径的基础。

6.4 A* 启发项只影响优先级 ​

updateCellAstar() 先计算真实势值，再加上当前栅格到机器人起点的欧氏距离：

priority = potential + euclidean_distance_to_start × 50

加完启发项的值用于决定进入当前、下一或溢出优先缓冲区，但写回 potarr 的仍是没有启发项的真实势值。

6.5 命中起点后处理目标容差 ​

势场传播到机器人起点后停止。如果原始目标本身势值有效，就直接使用目标；否则在目标周围 ±tolerance 的方形区域内，以一个地图分辨率为步长扫描，并选取欧氏距离最近的可达点。

注意，这个搜索区域是方形采样，不是严格圆形半径。

6.6 沿梯度生成路径 ​

NavFn 从可达目标附近开始计算势场梯度，默认每次移动 0.5 cell。当周围势场不完整或检测到振荡时，退化为八邻域中最低势栅格。

插件取得内核路径后再逆序转换成从机器人到目标的世界坐标路径，并补上目标点或最终接近方向。

七、Smac2D 全数据流：显式 g+h、父指针和后处理 ​

Smac2D 更接近教科书里的 A*，但又多了许多实车需要的工程保护。

7.1 锁图与可选降采样 ​

createPlan() 先用插件互斥量保护运行期重初始化，再锁住 Global Costmap。若启用降采样且倍率大于 1，就生成低分辨率 Costmap。

默认降采样使用每个块内的最大代价，因此不会把一个高代价障碍块平均成低代价自由空间。代价是小障碍会在低分辨率图上显得更大，终点精度也会下降。

当前配置是 downsample_costmap: false，所以 Smac2D 直接使用原始分辨率地图。

7.2 碰撞有效性 ​

Node2D 使用一个角度量化，碰撞检查按圆形机器人半径模型工作。对每个栅格索引直接读取 Costmap 代价：

  • 未知栅格且 allow_unknown=true：允许通过。
  • 代价大于等于 INSCRIBED_INFLATED_OBSTACLE：视为碰撞。
  • 其他代价：有效，并保存为当前节点的 _cell_cost。

因此 Smac2D 的二维搜索不会逐姿态旋转多边形 Footprint。它依赖 Costmap InflationLayer 已经把机器人安全半径编码进栅格代价。

7.3 从起点正向加入开放队列 ​

起点以累计代价 g=0 入队。每轮取出 f 最小的节点，只允许真正访问一次；同一节点可以因更低代价被重复入队，旧队列项出队时会被跳过。

7.4 八邻域通行代价 ​

Node2D 固定扩展上下左右和四个对角，共八个邻居。

直行一步的成本为：

step_cost = 1 × (1 + multiplier × normalized_cost)

对角一步的成本为：

step_cost = sqrt(2) × (1 + multiplier × normalized_cost)

其中：

normalized_cost = child_cost / 252

当前 cost_travel_multiplier: 2.0。代价越高，g 增长越快，路径越倾向走通道中间的低代价区域。

7.5 欧氏启发函数 ​

Node2D 的 h 是当前位置到目标栅格的欧氏距离，不读取 Costmap：

h = sqrt(dx² + dy²)

开放队列按 f=g+h 排序。Costmap 代价全部进入 g，不是另建一张障碍启发图。

这里必须澄清一个常见误解：Smac 框架中的 Hybrid／Lattice 节点可以使用障碍启发缓存，但当前 Node2D 专门化只使用欧氏启发函数。把 Smac2D 描述成“动态规划障碍启发 A*”并不符合这份源码。

7.6 目标容差与接近细化 ​

精确到达目标时立即回溯。若搜索进入目标容差范围，会记录启发距离最小的节点，并继续最多 max_on_approach_iterations 次扩展，争取找到更接近目标的解。

若开放队列耗尽，但最佳节点仍在容差内，也会回溯这条近似路径。

7.7 父指针回溯与平滑 ​

每次发现更小的 g，邻居都会保存新的 parent。成功后从目标或容差内最佳节点沿父指针回溯，再反向转换为起点到终点的世界坐标。

原始折线路径会按需发布到相对话题 unsmoothed_plan。随后 Smac2D 把剩余 max_planning_time 交给内置 Smoother，用原始数据保持项和三点平滑项迭代更新路径。

平滑过程中如果新点进入高代价碰撞区，就恢复到上一次合法路径。当前实现对二维路径总会调用 Smoother；要近似关闭平滑，可以把 smoother.max_iterations 设为 0。

八、代价感知到底差在哪里 ​

两者都读取 InflationLayer 生成的连续代价场，但使用方式不同。

8.1 NavFn A* ​

  • 先把 Costmap 代价固定映射为 50 + 0.8 × cost。
  • 映射后的通行代价直接决定势场增长速度。
  • A* 欧氏距离只改变传播优先级。
  • 路径沿插值势场梯度生成，而不是严格沿搜索父指针。
  • 没有运行期参数可直接调整 50 和 0.8。

8.2 Smac2D ​

  • 保留原始 Costmap 代价语义。
  • 将栅格代价归一化后乘以 cost_travel_multiplier，加入每一步的 g。
  • 启发函数是独立的欧氏距离。
  • 路径严格沿 A* 父指针回溯，之后再由 Smoother 改变几何形状。
  • 可以直接调节代价对路径居中程度的影响。

因此，Smac2D 的“代价感知”更显式、更容易调参；NavFn 的代价感知更深地固化在势场计算里。

但两者都有一个共同前提：如果 InflationLayer 只在障碍边缘产生一圈窄代价，大片自由空间都是相同的 0，规划器就缺少“通道中心比贴墙更好”的连续信息。先调好 Costmap，再谈规划器优劣。

九、搜索方向和路径形态为什么不同 ​

9.1 NavFn A* ​

势场传播只看四邻域，但路径提取会插值梯度，并在边界情况下检查八邻域最低势。输出点可以落在亚栅格位置，视觉上不一定是标准的四连通折线。

代价场平滑时，它能自然形成较圆润路径；势场在狭窄障碍、鞍点或不连续区域中，也可能出现梯度伪影、振荡或路径跳变。

9.2 Smac2D ​

搜索本身就是八邻域，原始路径由栅格中心组成，直行和对角步长明确。它不会受势场梯度伪影影响，但未平滑路径会带明显的 45° 栅格折线。

内置 Smoother 会降低折线感，却不是重新搜索。它受原始拓扑、剩余时间和碰撞校验约束，也不保证车辆运动学可行。Ackermann 机器人如果需要曲率与朝向约束，应该比较 SmacHybrid 或 SmacLattice，而不是把 Smac2D 当成车式规划器。

十、容差策略看似相同，实际状态机不同 ​

两者都配置了 tolerance: 0.5，但执行语义并不相同。

10.1 NavFn A* ​

NavFn A* 在势场传播结束后，检查原目标势值。目标不可达时，它遍历目标周围的方形区域，选择欧氏距离最近的可达采样点，再沿势场生成路径。

10.2 Smac2D ​

Smac2D 在搜索过程中持续维护“启发距离最小节点”。进入容差后不会立刻结束，而是最多继续 max_on_approach_iterations 次，尝试找到精确目标或更近解。

所以：

  • NavFn 是“先铺完需要的势场，再在容差区选终点”。
  • Smac2D 是“搜索过程中跟踪近似解，并给接近阶段额外预算”。

同样的 0.5 m，可能得到不同终点、不同扩展数量和不同失败时延。

十一、时间、内存与 Costmap 锁 ​

11.1 NavFn A* ​

NavFn 每次规划都按 Costmap 尺寸准备整图数组，并复制一份代价地图。复制完成后会提前释放 Costmap 锁，势场传播和路径提取使用内部数组继续运行。因此，长搜索不会一直阻塞 Costmap 更新。

11.2 Smac2D ​

Smac2D 的图使用哈希容器按需创建已经触达的节点，不必预先构造整张节点图；但当前 createPlan() 从锁图开始，一直到搜索、路径转换和平滑结束才离开作用域，也就是整个流程都持有 Costmap 互斥锁。

Smac2D 还提供：

  • max_iterations：总扩展次数上限。
  • max_on_approach_iterations：进入容差后的细化上限。
  • max_planning_time：搜索与后处理的总时间预算。
  • 降采样：用更粗地图减少搜索规模。

NavFn 当前没有对外暴露等价的规划秒级超时和迭代上限；内核使用与地图尺寸有关的循环预算，路径提取也有最大循环数。

11.3 对比指标 ​

工程上不能只说谁更快。应该在同一张 Costmap、同一组起终点和相同 InflationLayer 下测量：

  • 搜索总耗时。
  • Costmap 锁持有时间。
  • 扩展节点数量。
  • 路径长度。
  • 最小障碍距离。
  • 规划成功率和容差落点误差。

十二、运行状态和失败出口 ​

两套插件都把失败压缩成空 Path，再由 PlannerServer 终止 Action，但内部原因不同。

12.1 NavFn A* 失败出口 ​

NavFn A* 常见失败包括：

  • 起点或终点超出 Global Costmap。
  • 目标和容差区内都没有合法势值。
  • 势场传播未到达机器人起点。
  • 梯度为零、进入高势边界、振荡修复失败或路径过长。

12.2 Smac2D 失败出口 ​

Smac2D 常见失败包括：

  • 起点处于碰撞区。
  • 目标碰撞且容差接近零。
  • 开放队列耗尽。
  • 超过 max_iterations。
  • 超过 max_planning_time。
  • 没有精确路径，且最佳节点不在容差内。

当前 Smac2D 插件在调用 worldToMap() 时没有检查返回值，再把栅格变量传给 A*。如果起点或终点在地图外，行为不如 NavFn 的显式越界返回清晰。这是当前仓库实现需要补回归测试的边界，不应把“外部通常已经变换坐标”当作越界校验。

十三、动态参数能力也不相同 ​

13.1 NavFn A* 动态参数 ​

NavFn A* 可在 Active 状态更新：

  • tolerance。
  • use_astar。
  • allow_unknown。
  • use_final_approach_orientation。

它甚至可以运行期在 Dijkstra 与 A* 之间切换，但没有互斥量保护动态参数和 createPlan() 并发访问。

13.2 Smac2D 动态参数 ​

Smac2D 可动态更新：

  • tolerance。
  • cost_travel_multiplier。
  • max_planning_time。
  • allow_unknown。
  • max_iterations。
  • max_on_approach_iterations。
  • downsample_costmap。
  • downsampling_factor。
  • use_final_approach_orientation。

它用同一个 _mutex 串行化重初始化和规划，搜索参数改变时重建 A*，降采样参数改变时重建 Downsampler。

当前实现还有一个边界：动态关闭降采样时，回调没有显式清空已经存在的 _costmap_downsampler。因此从开启切到关闭，旧对象可能仍然继续被使用。关键模式切换更适合在 Lifecycle 非活动状态完成并做一次验证。

十四、到底该选哪一个 ​

14.1 选择 NavFn A* ​

如果你的目标是成熟、参数少、当前系统已经稳定运行，而且对现有路径形态满意，GridBasedAstar 是低风险选择。它复制 Costmap 后释放锁，运行链短，也可以快速切回 Dijkstra 对照。

14.2 选择 Smac2D ​

如果你更在意显式的代价权衡、八邻域路径、可控的规划预算、降采样、原始路径观测和内置平滑，优先评估 Smac2D。它的 cost_travel_multiplier 比 NavFn 固定代价映射更容易围绕“路径长度与离障距离”做工程调节。

14.3 回归场景 ​

但不要凭单次 RViz 观感下结论。推荐建立同一批回归场景：

  • 长直走廊：看是否居中、是否抖动。
  • 窄门和斜通道：看可达性与最小障碍距离。
  • U 形障碍：看无效扩展和失败时间。
  • 目标被占用：看容差落点和接近误差。
  • 地图边界目标：看越界处理。
  • 大地图长距离：看总耗时和 Costmap 更新阻塞。
  • 未知区：看 allow_unknown 对路径和风险的实际影响。

比较时保持 Costmap、InflationLayer、起终点和机器 footprint 不变，只切规划器 ID。否则测到的是地图参数差异，不是算法差异。

十五、调参顺序：先地图，再代价权重，最后才是平滑 ​

推荐顺序如下。

15.1 确认 Global Costmap ​

确认 Global Costmap 的静态层、障碍层和 InflationLayer 正常，走廊内有连续而不是断崖式的代价梯度。

15.2 固定通行域与终点策略 ​

固定 allow_unknown 和 tolerance，保证两套规划器面对相同的可通行域和终点策略。

15.3 调整 Smac2D 通行代价 ​

对 Smac2D 调 cost_travel_multiplier。值增大通常会让路径更避开高代价格，但可能增加绕行和搜索时间；值为 0 时更接近只看几何距离的栅格 A*。

15.4 决定是否降采样 ​

降采样不是白送的加速，它会放大障碍、损失狭窄空间和目标精度。

15.5 调整 Smoother ​

最后调 Smoother。平滑只能改几何形态，不能替代正确的通行代价和搜索拓扑。

NavFn 没有等价的 cost_travel_multiplier，路径贴墙或不居中时，应优先检查 InflationLayer，而不是寻找一个并不存在的 NavFn 权重参数。

十六、结语 ​

GridBasedAstar 与 Smac2D 的共同点，是都把二维 Costmap 变成一条全局路径；它们真正的分水岭，是“路径从什么中长出来”。

NavFn A* 从目标向起点传播连续势场，A* 负责缩小传播方向，梯度负责生成最终路径。Smac2D 从起点正向维护标准 g+h，Costmap 代价直接进入 g，父指针决定原始路径，Smoother 再负责几何修整。

理解这条数据流之后，选型就不再是“旧规划器还是新规划器”，而是明确判断：你的机器人更需要势场路径的成熟简洁，还是标准 A* 的显式代价、预算控制和工程可观测性。
