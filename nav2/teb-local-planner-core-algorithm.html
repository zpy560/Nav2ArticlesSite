路径会被障碍“拽弯”，时间还会自己收缩：Nav2 TEB 图优化核心拆解 ​

一条普通路径只回答“经过哪里”，却没有回答“什么时候到这里”。没有时间，速度和加速度只能在路径生成后另算；空间绕障与时间可执行性也容易互相打架。

TEB 的做法更彻底：把未来轨迹写成一串二维位姿和时间间隔，让位置、朝向与时间一起成为优化变量。障碍物像斥力一样推开轨迹，目标时间不断拉短时间间隔，速度、加速度和底盘运动学又阻止轨迹收缩得过猛。最终结果不是某一条约束单独获胜，而是一张稀疏超图中所有误差共同妥协。

本文基于当前本地 navigation2、teb_local_planner 0.9.1 源码、测试与 myworld_bringup 现用参数，只拆 Timed Elastic Band、g2o 顶点与边、软约束、外内循环、障碍关联、可选同伦类和速度提取等核心算法。

一、TEB 优化的不是路径点，而是时空轨迹 ​

1.1 位姿顶点同时保存位置和朝向 ​

第 i 个 VertexPose 保存：

text
s_i = (x_i, y_i, theta_i)

位置决定轨迹形状，theta_i 决定机器人朝向。当前后的 Pose 一起变化时，速度、加速度、转弯和非完整运动学误差都会跟着变化。

1.2 时间顶点夹在相邻位姿之间 ​

相邻 Pose 之间保存一个正数 VertexTimeDiff：

text
ΔT_i > 0

若有 N 个 Pose，就有 N-1 个 TimeDiff。两类变量交替形成：

text
Pose_0 ─ ΔT_0 ─ Pose_1 ─ ΔT_1 ─ ... ─ Pose_N-1

因此，TEB 能通过移动 Pose 改变空间路径，也能通过修改 ΔT 改变速度计划。

1.3 起点和终点是固定顶点 ​

轨迹初始化后，首尾 Pose 被设置为 fixed。g2o 不移动它们，只调整中间 Pose 和全部 TimeDiff。

起点固定保证命令从机器人当前状态出发；终点固定保证局部轨迹仍到达当前局部目标。软约束之间的妥协主要发生在中间自由度上。

1.4 全局路径只是初值和可选参考 ​

初次规划时，initTrajectoryToGoal() 从裁剪后的全局路径构造 Pose。每段初始时间取平移时间和转向时间的较大值：

text
ΔT_init = max(
  translation_distance / max_vel_x,
  abs(delta_yaw) / max_vel_theta
)

全局路径不是不可改变的硬轨道。若没有 Via Point 约束，中间 Pose 可以被障碍、时间和运动学边显著拉离初始路径。

二、弹性带为什么会自动增删采样点 ​

2.1 时间间隔过大就一分为二 ​

autoResize() 发现：

text
ΔT_i > dt_ref + dt_hysteresis

就把该时间间隔平分，在两个 Pose 的平均位置插入一个新 Pose，并增加一个同样大小的新 TimeDiff。

当前 dt_ref=0.3 s、dt_hysteresis=0.1 s，所以超过 0.4 s 的段会被继续细分。

2.2 时间间隔过小就合并相邻段 ​

当：

text
ΔT_i < dt_ref - dt_hysteresis

且采样数高于最小值时，源码删除一个中间 Pose，把被删除段的时间加到相邻 TimeDiff。当前低于 0.2 s 的段可能触发合并。

这组上下阈值形成迟滞，避免采样点在 0.3 s 附近不断插入和删除。

2.3 动态障碍开关改变重采样深度 ​

optimizeTEB() 设置：

text
fast_mode = !include_dynamic_obstacles

fast_mode=true 时，autoResize() 扫描一遍就退出；否则最多重复一百轮，直到不再修改。

当前 myworld_bringup 没有覆盖 include_dynamic_obstacles，因此沿用默认 true，会进入非快速重采样。但现有 Costmap 障碍都被构造成静态点，动态障碍边实际上没有可连接对象。

2.4 热启动只剪掉已经走过的前段 ​

新目标与旧终点距离、角度变化不大时，TEB 不重新建带。updateAndPruneTEB() 最多向前检查十个 Pose，寻找最接近新起点的位置，删除已经走过的中间 Pose，再用机器人新位姿覆盖固定起点。

这让上周期优化结果成为本周期初值，降低重复求解成本，也让轨迹随机器人前进持续向前滚动。

三、一张 g2o 图里连接了哪些变量 ​

3.1 Pose 和 TimeDiff 都进入优化器 ​

AddTEBVertices() 按照 Pose、TimeDiff、Pose、TimeDiff 的顺序分配 g2o ID，并把 TEB 自己持有的顶点指针加入 SparseOptimizer。

图清理时，源码先断开顶点与边，再从优化器移除顶点，避免 g2o 把仍属于 TEB 的状态对象删除。

3.2 一元边约束单个变量 ​

典型一元边包括：

  • EdgeTimeOptimal：连接一个 TimeDiff，推动时间缩短。
  • EdgeObstacle：连接一个 Pose，惩罚机器人模型离障碍过近。
  • EdgeInflatedObstacle：同时表达最小安全距离和较缓的膨胀距离。
  • EdgeViaPoint：把某个中间 Pose 拉向参考点。

3.3 二元边约束相邻位姿 ​

典型二元边包括：

  • 差速非完整运动学边。
  • 车式最小转弯半径边。
  • 最短路径边。
  • 偏好旋转方向边。

它们只连接局部相邻状态，所以整张图保持稀疏。

3.4 多元边把空间与时间耦合起来 ​

速度边连接两个 Pose 和一个 TimeDiff。加速度边连接三个 Pose 与两个 TimeDiff。起步／停车加速度边还把实测起始速度或目标速度作为参数带入。

这正是 TEB 的核心：如果某段距离不变而 ΔT 变小，速度误差会上升；若相邻两段速度变化过快，加速度误差也会上升。空间与时间不可能各自独立优化。

3.5 总目标是加权误差平方和 ​

每条 g2o 边计算误差向量 e_k，信息矩阵 Ω_k 保存对应权重。LM 求解器最小化：

text
J = Σ e_kᵀ Ω_k e_k

权重不是物理单位换算器，而是不同目标之间的谈判筹码。把某个权重调得极大，会让优化优先满足该误差，但也可能恶化数值条件或挤压其他目标。

四、速度、加速度和时间如何互相制衡 ​

4.1 差速线速度来自位移与时间 ​

相邻位姿位移为 ΔS，方向符号由位移在前一 Pose 朝向上的投影确定：

text
v_i = signed_norm(ΔS) / ΔT_i
omega_i = normalize(theta_i+1-theta_i) / ΔT_i

当前 exact_arc_length=false，平移长度使用欧氏距离近似，不使用圆弧精确长度。

4.2 速度边只惩罚越界部分 ​

差速速度误差使用区间惩罚：

text
-max_vel_x_backwards ≤ v_i ≤ max_vel_x
abs(omega_i) ≤ max_vel_theta

落在允许区间内时误差为零；越过边界后误差线性增加，再由 g2o 目标函数平方并乘权重。

当前限制为前进 0.26 m/s、后退 0.05 m/s、角速度 1.0 rad/s。

4.3 加速度边比较相邻两段速度 ​

中间 Pose 对应的线加速度近似为：

text
a_i = 2 × (v_i+1-v_i) / (ΔT_i+ΔT_i+1)

角加速度同理使用相邻角速度。当前上限为 2.5 m/s² 和 3.2 rad/s²。

起点边还把当前 Twist 与首段预测速度比较；目标速度默认不自由，因此末段会被拉向零速度。

4.4 时间最优边持续压缩每个 ΔT ​

EdgeTimeOptimal 的误差就是：

text
e_time = ΔT_i

进入 g2o 后贡献 weight_optimaltime × ΔT_i²。它不断推动总时间缩短，但速度和加速度边会在收缩过度时产生更大的反向代价。

4.5 当前没有单独启用最短路径边 ​

weight_shortest_path 默认是零，AddEdgesShortestPath() 不会创建边。当前轨迹变短主要来自时间最优、障碍、运动学和初始几何的共同作用，不是显式最短路径项。

五、障碍如何把弹性带推开 ​

5.1 距离基于完整机器人模型 ​

EdgeObstacle 不只计算 Pose 中心到障碍点的距离，而是调用当前机器人模型的 calculateDistance()。

现用 TEB 模型是半径 0.22 m 的圆。障碍误差因此按圆形机器人外缘到障碍的距离计算。

5.2 最小距离和膨胀距离是两层斥力 ​

当前：

text
min_obstacle_dist = 0.25 m
inflation_dist = 0.45 m
weight_obstacle = 50.0
weight_inflation = 0.1

进入 0.25 m 内产生高权重安全距离误差；进入 0.45 m 内还会产生较弱的线性膨胀误差。这让轨迹在碰到硬边界前就开始远离障碍。

5.3 新关联策略不会让每个 Pose 连接全部障碍 ​

legacy_obstacle_association=false 时，每个自由 Pose：

  • 强制包含距离小于 min_obstacle_dist × force_inclusion_factor 的障碍。
  • 忽略距离大于 min_obstacle_dist × cutoff_factor 的障碍。
  • 其余障碍只保留最近的左侧和右侧对象。

这样把边数量从“Pose 数乘全部障碍数”压缩为局部相关集合。

5.4 当前左右侧判断存在坐标边界 ​

源码用 Pose 朝向向量与障碍质心的二维叉积判断左右，却没有先计算“障碍质心减 Pose 位置”的相对向量。

在地图原点远离机器人时，左右关联可能受绝对坐标影响。距离强制包含仍能抓住极近障碍，但普通左右筛选应通过偏移地图原点的回归场景验证。

5.5 Costmap 点障碍不是动态障碍 ​

当前插件扫描 Costmap 的致命栅格并创建 PointObstacle。这些对象没有速度，isDynamic() 为假。

虽然默认 include_dynamic_obstacles=true，AddEdgesDynamicObstacles() 会跳过所有现有点障碍。配置中的 Costmap Converter 实现又在当前移植代码中被注释，因此不能把动态障碍权重理解成已经生效。

六、差速运动学如何阻止横着滑 ​

6.1 非完整约束惩罚侧向位移 ​

差速运动学边的核心误差为：

text
e_nh =
abs(
  (cos(theta_i)+cos(theta_i+1)) × Δy
  - (sin(theta_i)+sin(theta_i+1)) × Δx
)

当相邻位姿连线与平均朝向一致时，误差接近零；出现横向滑移时误差增大。

6.2 前进偏好惩罚倒车方向 ​

另一个误差检查：

text
ΔS · heading_i

投影为负时产生惩罚。当前 weight_kinematics_forward_drive=1000，所以优化强烈偏好前进；这不是禁止倒车，速度边仍允许最低 -0.05 m/s。

6.3 当前选择差速边而非车式边 ​

buildGraph() 在 min_turning_radius=0 时创建 EdgeKinematicsDiffDrive。只有最小转弯半径和对应权重都非零，才改用 EdgeKinematicsCarlike。

当前 max_vel_y=0、min_turning_radius=0，因此是差速模型：不允许横移，但允许原地转向，不约束汽车式最小转弯半径。

七、四轮外循环如何逐步收紧障碍约束 ​

7.1 外循环先调整轨迹分辨率 ​

每轮先运行 autoResize()，让 TimeDiff 回到参考时间窗附近。顶点数量改变后，g2o 图必须重新构建。

7.2 构图后执行 LM 内循环 ​

buildGraph() 加入全部有效顶点和约束边，optimizeGraph() 初始化 g2o，再运行 Levenberg-Marquardt。

当前 no_inner_iterations=5、no_outer_iterations=4，一个控制周期最多执行四轮构图，每轮五次 LM 迭代。

7.3 每轮清图但保留优化后的 TEB ​

求解后，Pose 和 TimeDiff 的估计值已经写回 TEB 顶点。clearGraph() 删除边和优化器索引，却保留这些状态，下一外循环继续以新结果构图。

7.4 障碍权重逐轮倍增 ​

外循环初始 weight_multiplier=1，每轮乘默认 weight_adapt_factor=2。四轮构图的障碍主权重倍率依次为：

text
1 → 2 → 4 → 8

逐步加重障碍约束，比初始就设置极端大权重更有利于优化收敛。

八、多同伦类别怎样避免困在单一路线 ​

8.1 同伦类区分障碍左右绕行 ​

两条路径若无法在不穿过障碍的前提下连续变形成彼此，就属于不同拓扑类别。HomotopyClassPlanner 用 H-Signature 把候选路径编码为复数或时空签名，签名接近的候选视为同一类。

8.2 图搜索生成不同绕行候选 ​

图搜索在障碍两侧放置关键点，连接不碰撞且大致朝向目标的边，再用深度优先搜索枚举起点到终点的简单路径。每个新等价类初始化一条独立 TEB。

8.3 候选可以并行优化 ​

不同 TEB 没有共享优化变量，开启多线程时可分别执行完整的外内循环。候选成本由 g2o 边代价、可选总时间、障碍缩放和 Via Point 缩放组成。

8.4 选择器带有轨迹切换迟滞 ​

上一周期最佳轨迹的成本会乘 selection_cost_hysteresis，初始全局路径候选也可乘偏好系数。即使另一个候选短暂更优，switching_blocking_period 仍可阻止立即切换，减少控制振荡。

8.5 当前配置关闭这条分支 ​

当前 myworld_bringup 明确设置：

text
enable_homotopy_class_planning = false

所以现用控制链只维护一个 TebOptimalPlanner。障碍两侧的替代路线不会被同时生成、分别优化再择优；单条 TEB 更省算力，但更依赖初值并可能落入局部最优。

九、优化轨迹如何变成当前速度 ​

9.1 速度提取从轨迹起点向前看 ​

getVelocityCommand() 至少需要两个 Pose。它把 look_ahead_poses 限制在合法范围，并从开头累加 TimeDiff。

若累计时间达到：

text
dt_ref × look_ahead_poses

就提前停止，使用实际选中的前视 Pose。

9.2 差速命令由首尾状态差分得到 ​

当前差速模式下：

text
vx = sign(ΔS · heading_0) × norm(ΔS) / accumulated_dt
vy = 0
omega = normalize(theta_k-theta_0) / accumulated_dt

这不是直接读取某个 g2o 顶点中的速度，因为速度从未作为独立顶点保存；它由优化后的 Pose 与 TimeDiff 推导。

9.3 软约束之后还有硬限幅 ​

速度边只是优化软约束，有限迭代后仍可能轻微超限。插件外壳随后执行 saturateVelocity()，把最终 vx、vy、omega 限制到活动速度边界。

因此，图优化负责找到兼顾多目标的轨迹，硬限幅负责守住真正发布命令的最后边界。

十、当前配置真正运行的算法画像 ​

10.1 它是单轨迹差速 TEB ​

myworld_bringup 默认选择 TEB 控制器，使用圆形机器人模型、差速运动学和单条 TEB，不启用同伦类候选。

10.2 它偏好前进而非绝对禁止倒车 ​

前进偏好权重为 1000，后退速度仍允许到 0.05 m/s。只有在其他代价足够大时，优化才可能接受低速倒车。

10.3 它以时间最优为主而非显式最短路 ​

weight_optimaltime=1，weight_shortest_path=0。TEB 会压缩执行时间，同时由速度、加速度、障碍和运动学阻止不可执行的捷径。

10.4 它没有真正接通动态障碍预测 ​

Costmap 提供的仍是静态点障碍；动态边没有数据对象。若要使用时空动态避障，必须先让障碍输入携带速度，而不是只打开参数。

十一、最容易误解的算法边界 ​

11.1 权重不是硬约束 ​

障碍、速度、加速度与运动学首先都是优化误差。有限迭代可能留下残差，所以输出还需要碰撞可行性检查和速度硬限幅。

11.2 轨迹光滑不等于曲率连续 ​

TEB 优化离散 Pose 与时间差，没有直接构造连续曲率多项式。采样密度、运动学权重和局部几何共同决定视觉平滑度。

11.3 单条 TEB 不会主动跨越拓扑障碍 ​

局部优化擅长把当前初值拉到附近更优解，却不擅长穿过高代价障碍带去寻找另一侧路线。同伦类关闭后，这个局部最优属性更明显。

11.4 动态障碍参数不等于动态输入已存在 ​

算法边已经具备时间预测能力，但当前输入链只提供静态 Costmap 点。配置能力和真实数据流必须分开判断。

11.5 障碍关联值得做地图平移回归 ​

现有左右判断使用绝对质心向量。把同一局部场景整体平移后，理论上规划结果应保持等价；若关联集合变化，就能直接暴露坐标原点依赖。

十二、结语 ​

TEB 的本质不是“让路径更圆滑”，而是把轨迹几何和执行时间放进同一个稀疏非线性最小二乘问题。

Pose 决定往哪里走，TimeDiff 决定多快走；障碍边把轨迹推开，时间边让轨迹收紧，速度和加速度边限制收紧速度，运动学边阻止底盘做出不可能的横移。外循环持续重采样并提高障碍权重，LM 内循环寻找这场多目标拉扯的局部平衡。

读懂这张图后，TEB 调参就不再是盲目堆权重：先确认状态变量和底盘模型，再确认哪些边真实存在，随后观察哪类误差主导优化，最后才决定增加约束、改变时间分辨率或启用多同伦候选。
