一条折线路径如何被“拉顺又避障”？逐函数拆解 Nav2 Constrained Smoother 的 29 个入口 ​

nav2_constrained_smoother 不是给路径做简单均值滤波。它把路径点坐标交给 Ceres Solver，把平滑度、最小转弯半径、原路径偏移和 Costmap 代价同时写进一个非线性最小二乘问题，再把优化后的稀疏点恢复成带朝向的 nav_msgs/Path。

这套实现尤其照顾 Reeds-Shepp 路径中的前进／倒退切换。方向发生变化的位置称为 Cusp，机器人通常会在附近做大幅转向，因此源码会在 Cusp 两侧提高 Costmap 权重。它也支持从机器人坐标系选取多个检查点，而不只检查路径中心。

本文以本地 navigation2、包版本 1.1.20 为事实基线。生产范围包括 5 个头文件和 1 个实现文件，共 29 个显式函数入口；测试夹具和测试辅助函数不计入这个数字。

一、先把结论说清楚 ​

1.1 它优化的是路径几何，不是速度 ​

插件输入和输出都是 nav_msgs/Path。它修改 Pose 的二维位置与偏航角，不读取里程计，不计算 cmd_vel，也不决定控制器如何跟踪。速度、加速度和控制频率仍属于 Controller 与 Velocity Smoother 的职责。

1.2 它是软约束优化器，不是碰撞硬约束求解器 ​

Costmap、曲率、平滑和原路径距离都以残差形式进入 Ceres。高代价会推动路径远离障碍，但源码没有把碰撞区域设成绝对不可行域。因此，SmoothPath Goal 中的 check_for_collisions 仍有价值：插件返回后，nav2_smoother 可以再按 Footprint 对整条结果做硬碰撞检查。

1.3 它适合有界路径段 ​

Ceres 对路径中的优化点建立参数块和残差块，路径越长，问题越大。包 README 明确建议平滑长度受控的局部路径段，也明确不支持连续多个 Pose 位于同一坐标的原地旋转路径。实际 BT 可以在平滑前用 TruncatePathLocal 截取机器人附近的路径，并以距离条件周期触发。

1.4 当前项目尚未在生产参数中选用它 ​

当前仓库的生产 YAML 都把 smoother_plugins 指向 simple_smoother。本包已正确导出 nav2_constrained_smoother/ConstrainedSmoother，但只有本包 README 和平滑器基准工具给出了启用示例。阅读本文得到的是当前源码能力，不代表现有 Bringup 已经运行该插件。

二、包边界与完整调用链 ​

2.1 从 BT 到插件的同步调用 ​

行为树 SmoothPath 节点把未平滑路径、插件 ID、最大平滑时长和碰撞检查开关写进 nav2_msgs/action/SmoothPath Goal。nav2_smoother::SmootherServer 接收 Goal，通过 Pluginlib 找到已加载的插件，把 Goal Path 复制到 Result Path，然后同步调用插件的 smooth()。

插件内部没有 ROS Topic 回调，也没有自己的 Action Server。它的主计算发生在 Smoother Server 的 Action 执行线程中。Ceres 返回后，Smoother Server 记录耗时、发布 /plan_smoothed，按 Goal 要求执行 Footprint 碰撞检查，最后把结果交还 BT。

2.2 包内数据如何分层 ​

  • ConstrainedSmoother 是 nav2_core::Smoother 插件壳体，负责 Lifecycle 接口、ROS 参数、Path 消息与 Eigen 数据转换。
  • Smoother 负责 Ceres 配置、路径下采样、问题构建、求解以及上采样。
  • SmootherCostFunction 负责单个中间点对应的四维残差。
  • SmootherParams 与 OptimizerParams 负责参数读取和有限校验。
  • arcCenter()、tangentDir() 与 cubicBezier() 负责圆弧、切向和插值几何。

三、插件壳体的七个函数 ​

3.1 ConstrainedSmoother::ConstrainedSmoother() ​

  • 作用：默认构造插件对象，不主动创建订阅器、线程或 Ceres 问题。
  • 输入：没有显式输入。
  • 输出：一个尚未配置的 ConstrainedSmoother 实例。
  • 数据流／回调：Pluginlib 创建实例时触发，后续必须由 Smoother Server 调用 configure()。
  • 包外调用：调用点位于 nav2_smoother::SmootherServer::loadSmootherPlugins() 的 createUniqueInstance() 内部。

3.2 ConstrainedSmoother::~ConstrainedSmoother() ​

  • 作用：使用默认析构流程释放内部 unique_ptr<Smoother> 和共享引用。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：插件容器清空或 Smoother Server 生命周期结束时触发。
  • 包外调用：由 C++ 对象生命周期和 Pluginlib 管理，不是 ROS 回调。

3.3 ConstrainedSmoother::configure() ​

  • 作用：把插件接到 Smoother Server 的运行环境，读取两组参数并初始化内部求解器。
  • 输入：Lifecycle Node 弱引用、插件实例名、TF Buffer、Costmap Subscriber 和 Footprint Subscriber。
  • 输出：没有返回值；成员 costmap_sub_、tf_、plugin_name_、logger_、smoother_、optimizer_params_ 和 smoother_params_ 被填充。
  • 数据流／回调：先锁定父节点；失败就抛出 runtime_error。随后构造内部 Smoother，调用 OptimizerParams::get()、SmootherParams::get() 和 Smoother::initialize()。
  • 包外调用：由 SmootherServer::loadSmootherPlugins() 在插件实例创建后调用。

这个函数接收了 TF 和 Footprint Subscriber，但当前算法只保存 TF、完全忽略 Footprint 参数；后续计算也不读取 TF。真正被优化器使用的是 Costmap Subscriber。Footprint 碰撞检查在包外的 Smoother Server 中完成。

3.4 ConstrainedSmoother::cleanup() ​

  • 作用：响应 Lifecycle 清理阶段并记录插件名。
  • 输入：没有显式输入，读取 logger_ 与 plugin_name_。
  • 输出：没有返回值，也没有主动重置成员资源。
  • 数据流／回调：Smoother Server 的 on_cleanup() 遍历插件表时调用。
  • 包外调用：位于 nav2_smoother 包的 Lifecycle 清理链。

3.5 ConstrainedSmoother::activate() ​

  • 作用：响应 Lifecycle 激活阶段并记录日志。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：不创建线程、不启动定时器，也不激活发布器。
  • 包外调用：Smoother Server 的 on_activate() 在激活 Action Server 前调用所有插件的 activate()。

3.6 ConstrainedSmoother::deactivate() ​

  • 作用：响应 Lifecycle 停用阶段并记录日志。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：不取消 Ceres 任务，也不释放内部平滑器。
  • 包外调用：Smoother Server 的 on_deactivate() 在停用链中调用。

3.7 ConstrainedSmoother::smooth() ​

  • 作用：完成 ROS Path 与内部优化数据之间的全部适配。
  • 输入：可原地修改的 nav_msgs::Path & path，以及 Action Goal 给出的最大平滑时长。
  • 输出：成功时返回 true，并以优化后的 Pose 序列覆盖原 Path；Ceres 解不可用时走失败分支。
  • 数据流／回调：少于两个 Pose 时直接返回成功。普通路径会逐点读取位置和四元数偏航角，把数据编成 (x, y, direction_sign)；内部求解完成后再把第三维改写为偏航角并恢复成四元数。
  • 包外调用：由 SmootherServer::smoothPlan() 同步调用。插件只改 Result Path，不发布 Topic。

direction_sign 不是偏航角。当前点朝向向量与“当前点到下一点”的位移向量点积小于零时，源码把该段标成 -1，否则标成 +1。末点没有后继段，因此复制倒数位置对应的方向符号。起点和终点的原始朝向单独保存在 start_dir、end_dir，供输出重建使用。

四、参数结构的四个函数 ​

4.1 SmootherParams::SmootherParams() ​

  • 作用：构造平滑参数容器。
  • 输入：没有显式输入。
  • 输出：成员使用类内初值，其中权重初值多为零，采样因子为一，前进／倒退识别和端点朝向保持默认开启。
  • 数据流／回调：真正的运行默认值并不只由这些初值决定，get() 会从 ROS 参数读取声明值。
  • 包外调用：由 ConstrainedSmoother 成员构造自动触发。

4.2 SmootherParams::get() ​

  • 作用：声明并读取平滑算法全部 ROS 参数。
  • 输入：Lifecycle Node 裸指针与插件实例名，例如 SmoothPath。
  • 输出：填充最大曲率、四类基础权重、Cusp 权重、Cusp 区域长度、Costmap 检查点、上下采样因子、倒车识别和端点朝向策略。
  • 数据流／回调：参数名都以插件实例名为前缀。minimum_turning_radius 被换算为 max_curvature=1/radius；w_cost_cusp_multiplier 与 w_cost 相乘得到 Cusp 中心权重。
  • 包外调用：只由 ConstrainedSmoother::configure() 调用，不是动态参数回调。

cost_check_points 按 [x, y, weight] 三元组解释。元素数不能被三整除时立即抛出 runtime_error。各检查点权重随后按总和归一化，但源码没有拒绝“非空且权重总和为零”的配置，这种输入会在归一化时产生非有限值。

4.3 OptimizerParams::OptimizerParams() ​

  • 作用：给 Ceres 配置结构体设置初始值。
  • 输入：没有显式输入。
  • 输出：debug=false、max_iterations=50，以及参数、函数、梯度三类容差的结构体初值。
  • 数据流／回调：这些值会被 get() 读取的 ROS 参数覆盖。
  • 包外调用：由 ConstrainedSmoother 成员构造自动触发。

4.4 OptimizerParams::get() ​

  • 作用：读取并校验 Ceres 线性求解器与停止条件。
  • 输入：Lifecycle Node 裸指针与插件实例名。
  • 输出：填充 linear_solver_type、param_tol、fn_tol、gradient_tol、max_iterations 和 debug。
  • 数据流／回调：当前只允许 DENSE_QR 与 SPARSE_NORMAL_CHOLESKY。非法字符串会打印全部可选值并抛出 runtime_error。
  • 包外调用：由 ConstrainedSmoother::configure() 调用。

这些参数只在配置阶段读取。当前包没有注册动态参数回调，运行中修改参数不会自动重建 SmootherParams 或 ceres::Solver::Options。

五、内部求解器的七个函数 ​

5.1 Smoother::Smoother() ​

  • 作用：构造内部求解器对象。
  • 输入：没有显式输入。
  • 输出：一个尚未写入 Ceres Options 的 Smoother。
  • 数据流／回调：不建立 Costmap 网格，不分配路径参数块。
  • 包外调用：由 ConstrainedSmoother::configure() 通过 make_unique 创建。

5.2 Smoother::~Smoother() ​

  • 作用：析构求解器对象及其持有的 Costmap 网格共享指针。
  • 输入：没有显式输入。
  • 输出：没有返回值。
  • 数据流／回调：默认析构，不执行 Ceres 取消或 ROS 清理。
  • 包外调用：随插件对象释放。

5.3 Smoother::initialize() ​

  • 作用：把 ROS 层读取到的优化器参数映射为 ceres::Solver::Options。
  • 输入：按值传入的 OptimizerParams。
  • 输出：更新线性求解器类型、最大迭代数、三类容差和日志策略。
  • 数据流／回调：调试开启时逐迭代输出进度；关闭时设置为静默。
  • 包外调用：只由插件 configure() 调用。

最大求解时间没有在这里设置，因为它来自每个 SmoothPath Goal。真正求解前，Smoother::smooth() 才把 params.max_time 写进 max_solver_time_in_seconds。

5.4 Smoother::smooth() ​

  • 作用：组织一次完整的 Ceres 求解。
  • 输入：带方向符号的 Eigen 路径、起终点方向向量、只读 Costmap 和本次平滑参数。
  • 输出：原地更新 Eigen 路径；可用解返回 true，不可用或代价变差返回 false。
  • 数据流／回调：创建局部 ceres::Problem、优化路径副本和优化标志，调用 buildProblem()；有可优化变量时运行 ceres::Solve()，随后无论是否真正建模都调用 upsampleAndPopulate()。
  • 包外调用：只由 ConstrainedSmoother::smooth() 调用。

路径少于两个点会在这里抛出 runtime_error，不过外层插件已经对少于两个 Pose 的情况提前返回。求解结果只检查 IsSolutionUsable() 和“最终代价是否高于初始代价”。源码没有检查 Ceres 的终止类型，所以时间上限触发后，只要仍有可用且未变差的解，函数仍可能返回成功。

5.5 Smoother::buildProblem() ​

  • 作用：把路径和 Costmap 变成 Ceres 参数块、残差块与常量块。
  • 输入：原路径、Costmap、平滑参数，以及四个输出容器。
  • 输出：填充 problem、path_optim 和 optimized；存在可优化中间 Pose 时返回 true。
  • 数据流／回调：复制 Costmap 字节数组到 Ceres Grid，建立双三次插值器；遍历路径时执行下采样、Cusp 识别、Cusp 前后权重更新和三点残差块创建。
  • 包外调用：只由内部 smooth() 调用。

每个残差块连接前一优化点、当前优化中心点和后一优化点。首点与末点始终设为常量；要求保持起点朝向时，紧邻起点的点也固定；要求保持目标朝向时，紧邻终点的点也固定。扣除这些约束后没有可优化 Pose，就返回 false，上层会直接进入路径重建。

5.6 Smoother::upsampleAndPopulate() ​

  • 作用：把稀疏优化结果恢复为完整路径，并为每个点计算朝向。
  • 输入：优化路径、优化标志、起终点方向、采样参数和输出路径引用。
  • 输出：清空并重新填充最终 Eigen 路径，第三维由方向符号变成偏航角。
  • 数据流／回调：遍历实际参与优化的节点，在相邻节点间按采样因子插入三次贝塞尔点；利用三点切向计算中间朝向，并按前进／倒退符号修正方向。
  • 包外调用：只由内部 smooth() 调用。

path_upsampling_factor=0 时保留下采样后的优化节点；取值为一时按原索引间隔恢复原粒度；大于一时产生比原路径更多的点。这里恢复的是几何密度，不是重新运行碰撞检查。

5.7 Smoother::cubicBezier() ​

  • 作用：计算三次贝塞尔曲线上的二维点。
  • 输入：端点 pt0、pt3，控制点 pt1、pt2，以及插值比例 mu。
  • 输出：比例位置对应的二维坐标。
  • 数据流／回调：upsampleAndPopulate() 以端点切向和两点距离构造控制点，控制臂长度固定为段长的 0.4 倍。
  • 包外调用：没有包外调用，仅用于内部路径重采样。

六、代价函数的九个函数 ​

6.1 SmootherCostFunction::SmootherCostFunction() ​

  • 作用：为一个待优化中心点保存残差计算上下文。
  • 输入：中心点原始位置、后一段与前一段的长度比、倒车标志、Costmap、共享双三次插值器、平滑参数和当前 Costmap 权重。
  • 输出：一个可被 Ceres 自动微分包装的函数对象。
  • 数据流／回调：同时缓存 Costmap 原点和分辨率，后续把世界坐标换成网格连续坐标。
  • 包外调用：由 Smoother::buildProblem() 为每个可建模中间点创建。

长度比带有方向语义。普通点使用正比值，Cusp 点使用负比值，让平滑残差和曲率几何把前进／倒退切换视为运动方向反转，而不是把两段当成普通连续前进。

6.2 SmootherCostFunction::AutoDiff() ​

  • 作用：把函数对象包装成 Ceres 自动微分代价函数。
  • 输入：隐式使用当前对象。
  • 输出：动态分配的 ceres::CostFunction *。
  • 数据流／回调：声明四维残差和三组二维参数块，分别对应中心点、后一节点和前一节点。
  • 包外调用：buildProblem() 把返回对象交给 Problem::AddResidualBlock()，所有权随后由 Ceres Problem 管理。

6.3 SmootherCostFunction::setCostmapWeight() ​

  • 作用：更新某个路径点的障碍代价权重。
  • 输入：新的双精度权重。
  • 输出：没有返回值，成员 costmap_weight_ 被覆盖。
  • 数据流／回调：发现 Cusp 时，buildProblem() 会回看半个 Cusp 区域内已创建的代价函数，把权重向 Cusp 中心值渐变。
  • 包外调用：没有包外调用。

6.4 SmootherCostFunction::getCostmapWeight() ​

  • 作用：读取某个路径点当前的障碍代价权重。
  • 输入：没有显式输入。
  • 输出：costmap_weight_。
  • 数据流／回调：用于比较同一残差函数是否已经被另一个更近的 Cusp 赋予更强权重，避免较弱更新覆盖更强更新。
  • 包外调用：没有包外调用。

6.5 SmootherCostFunction::operator() ​

  • 作用：为 Ceres 计算一个中心点对应的四维残差。
  • 输入：中心点、后一节点、前一节点的二维参数指针，以及四维输出数组。
  • 输出：依次写入平滑残差、曲率残差、原路径距离残差和 Costmap 残差，返回 true。
  • 数据流／回调：Ceres 在自动微分和迭代求解过程中反复调用；模板类型可能是普通浮点数，也可能是携带导数的 Jet。
  • 包外调用：只由 Ceres Solver 间接调用。

需要准确理解“残差”这个词。四个子函数写入的值本身已经含有权重和平方距离，Ceres 又最小化残差向量的平方和。因此最终目标不是四个注释公式的简单相加，而是这些残差分量再次平方后的总和。

6.6 SmootherCostFunction::addSmoothingResidual() ​

  • 作用：抑制相邻路径段的方向和长度突变。
  • 输入：平滑权重、中心点、前后节点和一个残差引用。
  • 输出：向残差加入带权的位移差平方。
  • 数据流／回调：后一位移先乘“后一段／前一段长度比”，再与前一位移比较；Cusp 使用负比值，等价于先翻转一侧运动方向再检查连续性。
  • 包外调用：只由 operator() 调用。

6.7 SmootherCostFunction::addCurvatureResidual() ​

  • 作用：只惩罚超过允许上限的曲率。
  • 输入：曲率权重、三点坐标和残差引用。
  • 输出：直线、退化圆弧或未超限时不改变残差；超限时加入 weight × (curvature-max_curvature)²。
  • 数据流／回调：先调用 arcCenter() 求圆心，以半径倒数得到局部曲率。Cusp 会先按运动方向翻转后一段再求圆。
  • 包外调用：只由 operator() 调用。

minimum_turning_radius 在参数层被换成最大曲率。将半径设为零会得到无穷大上限，源码效果是关闭曲率惩罚；负半径没有显式校验，不应作为合法调参方式。

6.8 SmootherCostFunction::addDistanceResidual() ​

  • 作用：限制优化点偏离原路径。
  • 输入：距离权重、当前优化坐标、原始坐标和残差引用。
  • 输出：加入 weight × squaredNorm(current-original)。
  • 数据流／回调：该项不读取 Costmap，也不关心前进／倒退。
  • 包外调用：只由 operator() 调用。

w_dist=0 时路径可在其他残差推动下较自由地移动；增大它会强化原路径锚定。它不是绝对边界，仍会与其他残差共同折中。

6.9 SmootherCostFunction::addCostResidual() ​

  • 作用：根据 Costmap 把路径推离高代价区域。
  • 输入：当前 Costmap 权重、三点坐标和残差引用。
  • 输出：加入路径中心点或多个车体检查点的带权 Costmap 值平方。
  • 数据流／回调：没有配置检查点时直接采样中心点；配置检查点时先用 tangentDir() 建立车体朝向，结合倒车标志确定正方向，再把每个机器人坐标系检查点变换到世界坐标并采样。
  • 包外调用：只由 operator() 调用。

Costmap 通过双三次插值以连续坐标读取，便于自动微分形成平滑梯度。这里使用的是 Costmap 字节值，不是二值碰撞结果；Footprint 也没有直接进入残差。长条形或不对称机器人可以通过检查点近似表达车体不同部位，但需要更多迭代，且最终仍应做包外碰撞检查。

七、几何工具的两个函数 ​

7.1 arcCenter() ​

  • 作用：求经过前一点、中心点和后一点的圆弧圆心。
  • 输入：三个二维点和 is_cusp 标志。
  • 输出：正常圆弧返回圆心；三点近共线时返回两个无穷大分量。
  • 数据流／回调：Cusp 情况会把后一段反向，再求两条线段中垂线交点，使曲率对应机器人真实运动连续性。
  • 包外调用：被 addCurvatureResidual() 和 tangentDir() 调用。

7.2 tangentDir() ​

  • 作用：计算中心点处的未定符号切向量。
  • 输入：三个二维点和 is_cusp 标志。
  • 输出：圆弧时返回半径的垂直向量；直线时返回首尾弦向量；极少数首尾重合情况返回前段的垂直向量。
  • 数据流／回调：函数只给出切线方向轴，不决定正负。调用端再结合下一段位移和前进／倒退符号翻转。
  • 包外调用：被 Costmap 检查点变换和输出朝向重建调用。

八、输入数据如何进入 Ceres ​

8.1 Path Pose 被拆成位置和运动方向 ​

外层插件从每个四元数提取偏航角，构造单位朝向向量。当前 Pose 到下一 Pose 的位移与朝向点积小于零，就代表机器人面朝一个方向、路径却向相反方向延伸，源码把该段记为倒车。

Eigen 路径在求解前的第三维只保存 +1 或 -1。Ceres 参数块却只连接每个点内存中的前两个 double，也就是 x、y；方向符号不参与优化，只作为 Cusp 判断和朝向恢复的离散标签。

8.2 Costmap 是每次请求时获取的快照 ​

插件在调用内部求解器前通过 costmap_sub_->getCostmap() 获取共享 Costmap。buildProblem() 用其字符数组创建 Ceres Grid，并为本次求解建立双三次插值器。优化期间没有 Costmap Topic 回调进入这个包，也不会在每次迭代重新抓取地图。

8.3 时间预算只约束 Ceres 求解阶段 ​

Action Goal 的 Duration 被换成秒并写入 SmootherParams::max_time，随后成为 Ceres 的 max_solver_time_in_seconds。Path 转换、Costmap 网格创建、问题构建、贝塞尔上采样和消息写回都发生在这个选项之外，因此 Action 观察到的总耗时可能略大于给 Ceres 的上限。

8.4 Ceres 参数块只优化二维坐标 ​

每个残差连接三组二维参数块。方向、Costmap 原点、分辨率、原始点位置、权重和倒车标志都是固定上下文。求解器通过自动微分得到相对于三点 x、y 的雅可比，最终只移动路径点，不直接优化 yaw。

九、Cusp 与下采样如何同时工作 ​

9.1 下采样不会跨过方向切换 ​

普通点只有在索引距离未达到 path_downsampling_factor 时才跳过。Cusp 点永远不会因这个条件被跳过，而且采样间隔从 Cusp 重新开始。端点朝向保护开启时，靠近起点和目标的必要点也不能被跳过。

9.2 Cusp 权重在两侧线性渐变 ​

cusp_zone_length 被分成前后两个半区。遍历到 Cusp 前，源码用队列保留最近半区内已经创建的代价函数；确认 Cusp 后，回头提高这些函数的 Costmap 权重。遍历越过 Cusp 后，再按累计距离从中心权重逐渐降回普通权重。

9.3 相邻 Cusp 取更强影响 ​

每个历史代价函数在更新前会读取当前 Costmap 权重。只有新权重更接近 Cusp 中心权重时才覆盖，这样两个 Cusp 区域重叠时，不会用较远 Cusp 的弱权重冲掉较近 Cusp 的强权重。

cusp_zone_length 没有正值校验。需要 Cusp 加权时应保持它大于零，避免半区长度为零参与插值除法。

十、输出路径如何恢复 ​

10.1 优化点先得到稳定切向 ​

每组三个优化点通过 tangentDir() 得到中心点切向轴，再与下一段实际位移做点积确定符号。倒车段会额外乘方向符号，保证 Pose 朝向可以与路径位移相反，而不是把所有点强制朝向行进方向。

10.2 被跳过的点由三次贝塞尔补回 ​

两端优化点是贝塞尔端点，沿两端切向、按段长的 0.4 倍构造控制点。插值数量由原索引间隔与 path_upsampling_factor 共同决定。这样恢复出的点不仅密度连续，方向也能沿曲线逐点重算。

10.3 端点朝向由参数决定 ​

keep_start_orientation 或 keep_goal_orientation 开启时，输出直接使用输入 Path 的端点方向，同时问题构建阶段固定相邻点以支撑该方向。关闭时，源码根据平滑后路径切向重新计算端点朝向。

十一、包外调用与回调边界 ​

11.1 Pluginlib 负责发现和创建 ​

nav2_constrained_smoother.xml 把实现类导出为 nav2_core::Smoother，插件 ID 是 nav2_constrained_smoother/ConstrainedSmoother。Smoother Server 根据 <plugin_id>.plugin 参数创建实例，不需要在服务器代码中直接包含实现类。

11.2 Lifecycle 由 Smoother Server 统一驱动 ​

服务器配置时调用插件 configure()，激活、停用和清理阶段分别调用同名 Lifecycle 方法。这个包的后三个方法只写日志，真正的 Action Server、发布器、TF Listener、Costmap Subscriber 和 Footprint Subscriber 都由 nav2_smoother 创建和管理。

11.3 SmoothPath Action 是公开运行入口 ​

Goal 输入包括：

  • path：待平滑路径。
  • smoother_id：选择已加载插件。
  • max_smoothing_duration：传给插件的求解时间预算。
  • check_for_collisions：要求服务器在插件返回后检查结果。

Result 输出包括：

  • path：平滑后的路径。
  • smoothing_duration：服务器统计的总平滑耗时。
  • was_completed：插件 smooth() 的布尔返回值。

这些字段是并列接口，不代表执行序号。

11.4 BT 只负责搬运黑板数据 ​

SmoothPathAction::on_tick() 从 BT 输入端口填充 Goal，on_success() 把 Result Path、耗时和完成标志写回输出端口。BT 不理解 Ceres 权重，也不会替插件判断曲率或 Costmap 梯度。

十二、参数应该如何理解 ​

12.1 平滑、曲率与原路径锚定 ​

  • w_smooth 增大会强烈抑制相邻段变化。
  • w_curve 控制超过最大曲率后的惩罚强度。
  • minimum_turning_radius 决定曲率上限，差分驱动或全向场景可按 README 用零关闭该项。
  • w_dist 增大会把结果拉回原路径。

这些量共同进入非线性最小二乘，而且残差还会被 Ceres 再平方，不能只按参数数值大小直接判断实际影响。有效调参必须固定路径、Costmap、采样因子和求解迭代数后比较输出。

12.2 Costmap 与 Cusp ​

  • w_cost 控制普通区域避障倾向。
  • w_cost_cusp_multiplier 决定 Cusp 中心相对普通区域的倍数。
  • cusp_zone_length 决定权重渐变覆盖的总路径长度。
  • cost_check_points 用机器人坐标系三元组近似车体多个部位。

检查点权重会被归一化，所以共同缩放所有检查点权重通常不会改变相对占比。应保证非空权重总和为正数，并在启用多个检查点后提高迭代预算。

12.3 路径采样 ​

  • path_downsampling_factor 越大，Ceres 参数块越少，速度通常更快，但细节约束更稀。
  • path_upsampling_factor=0 保留稀疏结果。
  • path_upsampling_factor=1 按原索引密度恢复。
  • 更大的上采样因子会生成更密路径，但不会增加 Ceres 真正优化过的节点数量。

12.4 端点与倒车 ​

  • reversing_enabled 依赖输入 Path 的有效朝向；没有可靠朝向的路径应关闭。
  • keep_start_orientation 控制是否保留起点方向。
  • keep_goal_orientation 控制是否保留目标方向。

12.5 Ceres 求解器 ​

  • linear_solver_type 当前只接受 DENSE_QR 与 SPARSE_NORMAL_CHOLESKY。
  • max_iterations 是迭代上限。
  • gradient_tol、fn_tol、param_tol 分别影响梯度、目标函数变化和参数变化停止条件。
  • debug_optimizer 会输出逐迭代日志与完整求解报告。

十三、源码边界与风险 ​

13.1 重复坐标点不是合法输入形态 ​

连续重复点会产生零长度段。源码用 EPSILON 保护部分长度比，但圆弧、切向、归一化和贝塞尔方向仍可能遇到退化几何。包 README 已明确不支持以重复坐标表达原地旋转的路径。

13.2 插件失败分支抛出的是异常指针 ​

外层 ConstrainedSmoother::smooth() 在内部求解返回 false 时执行 throw new nav2_core::PlannerException(...)。按 C++ 类型系统，这会抛出 PlannerException *，不是 PlannerException 对象。

包外 Smoother Server 捕获的是 nav2_core::PlannerException & 和 std::exception &，两者都不能匹配这个指针类型。因此，这条失败路径存在异常传播缺口。本文只记录当前事实，不把它误写成“服务器会正常捕获并终止 Goal”。

13.3 时间上限不等同于 was_completed=false ​

内部函数没有检查 Ceres termination_type。求解因时间上限停止后，如果 Summary 仍判定解可用且代价没有变差，插件就返回 true。所以当前实现中的 was_completed 更接近“是否接受求解结果”，不严格等于“是否在限制内完整收敛”。

13.4 Costmap 残差不能代替最终碰撞检查 ​

插件采样连续 Costmap 代价并做软惩罚，不把 Footprint 碰撞设成不可行约束。尤其在权重较小、迭代不足、检查点稀疏或插值曲线穿过高代价区时，仍应让 Smoother Server 执行 check_for_collisions。

13.5 参数校验并不完整 ​

源码校验了检查点数组长度和线性求解器名称，但没有系统校验半径、Cusp 区域、采样因子、迭代数、容差和检查点权重总和。配置必须遵守算法隐含的有限值与正值前提。

13.6 TF 与 Footprint 不属于当前优化核心 ​

插件保存 TF 却没有使用，配置函数也忽略 Footprint Subscriber。不要从函数签名误判它会在包内变换 Path 或按完整 Footprint 建模；输入 Path 与 Costmap 必须已经处于可直接比较的坐标语义，完整 Footprint 检查发生在包外。

十四、总结 ​

14.1 用一条主线记住 29 个函数 ​

ConstrainedSmoother 接住 Nav2 插件接口并完成消息转换，参数结构把 ROS 配置变成平滑权重与 Ceres Options，Smoother 把路径下采样成优化问题，SmootherCostFunction 用四维残差推动每个中间点，几何工具处理圆弧、切向和 Cusp，最后再用三次贝塞尔恢复路径密度与朝向。

它真正有价值的地方，不是“让折线看起来圆润”，而是把车辆最小转弯半径、障碍代价、前进／倒退切换和原路径保持放进同一套可微优化框架。它真正需要警惕的地方也同样明确：这是软约束、参数影响高度耦合、当前项目尚未启用，而且异常传播、时间完成语义和部分参数校验仍有源码边界。

理解这些边界后，调参不再是盲目放大某个权重，而是围绕输入路径质量、Costmap 梯度、Cusp 密度、采样规模、求解预算和包外碰撞验收共同设计整条平滑链。

以底层原理、源码与验证证据为基础的工程文章。
